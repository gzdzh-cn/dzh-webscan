# Agent pull RPC v1

应用 v3 使用此独立版本的 RPC 合约。生成的 Go SDK 位于 `sdk/agent/v1`，常量约束在 `limits.go`；运行根目录 `scripts/generate-agent-protocol.sh` 可重新生成。

`Capabilities` 在读取前核对节点 ID、合约版本及批次限制。每节点复用一条 mTLS HTTP/2 连接，同时进行最长 25 秒事件长轮询和默认 30 秒指标读取。连接及采集失败独立退避，不等待整轮节点完成。

服务器端验证 CA 证书链，还必须明确匹配采集器 CN 或 `spiffe://webscan/collector/...` URI。信任 CA 不等于允许任意该 CA 签发的身份读取数据。采集器按节点配置的 SAN 名称验证服务端证书。离线签发／吊销工具、已有连接的逐 RPC 校验及可选的跨重启持久版本下限见 `docs/V3-PKI.md`；签名 CRL 的下发已接入，节点叶证书自动更新、换根和完整安装验收仍需继续，验证证书不用于生产。

事件流程：

1. Agent SQLite 事件先持久化，未确认的记录不会按已完成事件清理。
2. `FetchEvents` 最多返回 100 条、消息不超过 2 MiB，并产生 10 分钟有效的 receipt。采集代次写入 Agent；更旧代次不能确认。
3. 主控在 PostgreSQL 同一事务提交事件、去重键及双通道通知出箱。
4. 提交成功后 `AckEvents` 只能确认本 receipt 提供过的 ID；未知 ID、重复 ID 或失效代次拒绝。
5. 未收到确认可重读；同节点事件 ID 和规范化摘要相同则幂等。永久拒绝分开记录，不清除原事件、不阻塞后续正常事件。

每节点同一时刻只允许一个事件读取。receipt 不是客户端认证凭据，不进入浏览器或用户 API。网络和数据库错误不视为事件永久拒绝。事件投递为至少一次，中心去重；外部通知提交成功但结果持久化失败时，重试可能再次发送。

指标按 Agent 原采样时间保留最近一小时，最多 120 个样本一页、整页不超过 2 MiB。主控成功写入 VictoriaMetrics 后才推进 PostgreSQL 游标；失败重读相同时间戳，依赖时序库的相同节点／标签／时间戳去重。首个样本、重启及计数重置时，派生速率保持缺失。

Linux Agent 共用 19100 的 HTTP/2 gRPC 与旧 `/metrics`。验证模式需运行配置 `transport_mode: pull`、`metrics.tls_enabled: true` 及非空的 `pull.collector_identities`。现有 v2 部署器不会自动生成或切换这些字段；不能据此直接在生产节点手工迁移。

`Capabilities` 兼容增加 `configuration_version` 和 `configuration_sha256`，报告当前实例启动时加载的源配置版本及摘要。旧验证配置返回 0／空字符串，表示没有该回执，不能填成期望版本。此回执不代替文件覆盖、扫描、队列及资源限制验收；完整服务切换仍未开放。私有配置包和任务绑定见 `docs/V3-NODE-CONFIGURATION.md`。

`UpdateTrust` 是合约 v1 的可选增量方法，不改变原事件或指标消息。主控在身份协商前及指标周期同步最新完整签名 CRL；已确认相同摘要时不重复发送。子控按已配置的采集器允许名单、原 CA、当前完整列表及持久下限验证，原子提交后返回节点、列表 SHA256、编号和到期时间；不接收路径、命令、CA 或私钥。消息仍不超过 2 MiB，CRL 正文上限为 `MaxBytes - 4096`。

新生成的私有运行配置启用 `pull.revocation_updates`，且要求 TLS、种子 `revocation_file` 及独立 `revocation_state_directory`。仅第一次从种子初始化，此后使用持久目录的 CRL；过期历史可启动受限更新入口，但普通 RPC 保持拒绝，直到一个当前有效、未吊销的允许身份提交原 CA 签名的新列表。普通 RPC 返回前再次检查，吊销后的长轮询不再返回事件。

旧节点未启用或没有此方法时返回 `Unimplemented`，主控继续使用原采集协议；不能将其记作 CRL 更新成功。其他错误不降级为旧能力。升级仍需明确执行，不自动改写旧节点配置。此入口不更新叶证书，节点叶证书已过期时也不能代替 SSH 恢复。

`PrepareIdentityRenewal` 和 `ActivateIdentityRenewal` 是合约 v1 的可选增量方法，复用原 mTLS 端口与逐 RPC 吊销鉴权。启用 `pull.identity_renewal` 的受管理节点在 `Capabilities` 中报告真实活动叶证书摘要与到期时间；旧节点返回禁用、空摘要及 0，不伪造证据。新生成 format 2 配置启用此能力，format 1 保持原样。

续期准备只接收本节点 ID 与原证书摘要，返回不超过 64 KiB 的规范公开请求；新 Ed25519 私钥持久化在子控，永不通过 RPC 传输。请求包含原私钥对完整 CSR 的持有证明。激活只接收本节点、原证书／请求摘要和不超过 16 KiB 的公开证书，核对本地待签私钥、固定 CA、相同身份与 SAN，以及当前持久吊销规则后原子替换。丢失响应可重试，同一监听器无需重启，原身份历史和未确认事件保留。

两个方法都要求受管理活动身份位于节点数据目录、TLS、非空的吊销种子和持久状态目录，并且普通鉴权配置了当前吊销策略。不能经 `UpdateTrust` 的过期列表恢复例外调用续期；已过期叶证书仍需独立 SSH 恢复。每次本机操作限时 5 秒，错误不包含路径或私钥。此阶段只接通节点 RPC，主控定时申请、独立宿主签发和自动交付仍需继续实现。
