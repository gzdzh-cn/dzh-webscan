## 第一阶段变更

### 独立证书维护升级资料

新增 `preview-single-pki-upgrade`、`prepare-single-pki-upgrade`、`check-single-pki-upgrade`、`maintain-single-pki-upgrade`。原 `maintain-single-pki` 兼容行为保留。

维护升级包验证独立信任公钥、发布签名和新工具摘要，绑定原安装摘要及当前程序数据库结构版本。旧安装中的程序、配置、CA、Vault 和不可变清单均不覆盖；不复制或重建密钥。新维护程序仍验证全部原安装资料、维护绑定及已完成的安装检查点。维护定时任务不得自动迁移数据库。

预览不写文件；准备资料不激活 systemd、不重启主控；已发布目录不允许覆盖。具体操作见 `V3-SINGLE-INSTALL.md`。

### 名称裁剪执行与重新授权

接通宿主 `prepare/run/cancel/node-name-pruning-status` 命令、固定 SSH 和受签名摘要保护的远端工具。运行器逐步续租并重新检查配置、账号、凭据和历史依赖；任务必须通过实际新连接的 mTLS 证书及新鲜健康指标验收，不能因 SSH 回执成功而完成。子控执行不修改配置、不重启服务，保留活动身份历史、基线与待确认事件。

到期或取消后的新管理员授权复用原本机 CSR／密钥及唯一签发记录，支持尚未激活与已经激活两种状态；后者用当前有效后继密钥证明持有权。请求使用独立签名域，保持原发行摘要及证书不变，不允许重新签发、更换 SAN、配置摘要、快照、代次或有效期。当前 CRL 仍检查父／后继吊销。数据库灾备恢复保留发行 ancestry、取消未完成授权；新管理员必须重新准备并取得新租约。

新增本地管理员历史快照退役预览与确认，数据库结构升级至 37。退役记录不可修改，保留原快照及任务、证书审计；活动或仍有未完成操作的节点不能退役。恢复、部署和配置应用在远端操作前检查退役，数据库运行登记另有最终约束。只有精确退役的历史快照不再保护旧名称，实际证书裁剪仍走独立签名及 mTLS 验收；不会自动吊销当前证书。隔离数据库、迁移及恢复竞争回归已通过，真实 SSH／服务联合验收尚未完成。

### 总览证书证据

宿主维护程序在核验实际 CA、采集器身份及 CRL 后，发布白名单公共期限与维护心跳。总览显示 CA／采集器期限、维护状态及脱敏失败原因；缺失或过期心跳显示未知，不用采集器健康推断所有节点证书健康。数据库结构不符时不自动迁移、不发布健康心跳；备份恢复后删除归档维护心跳，等待新宿主观察。

### 时序备份与离线恢复组件

新增宿主 `backup-metrics`、`verify-metrics-backup`、`restore-metrics-offline`。备份来源绑定已完成的单中心不可变安装、实际私有配置、实例、数据库凭据路径及回环时序地址；没有新增网页路径或命令探测接口。备份和恢复写操作仅允许 Linux amd64 root。

创建本次独立 VictoriaMetrics 快照后，限定复制其三个已知相对链接指向的同名快照目录，不跟随任意链接或活动数据；生成目录、字节数和逐文件 SHA256 清单。输出为独立普通文件，经校验后原子发布，不覆盖已有目录。校验及恢复要求可信外部摘要，拒绝多余、缺失、损坏、权限不符及链接替换。取消仍限时清理本次已知快照；回执不明不猜测名称、不清理历史快照。清理失败返回非零，并区分有效独立备份和未完成拷贝。

真实 v1.128.0 进程已经在工作区专用 bind 存储完成独立实例恢复：原指标可查询，备份后新写入的指标不混入；两个实际同时开始的备份竞争同一输出目录，只有一个发布成功，历史快照保留。没有启动生产服务或通知。

随后新增宿主 `backup-single`、`verify-single-backup`、`restore-single-offline` 编排：覆盖 PG 业务归档、VM 快照、原安装、实际 API／执行器配置、当前及旧 Vault、PKI、CRL 下限、签名物料、配置包及显式历史恢复目录。复用签发／身份更新锁，随后固定数据库写入；校验原绑定及宿主前后两次摘要。源目录不跟随链接，不直接拷贝活动 PG／VM，归档不可覆盖。

实际签名 Linux 程序、PG17 和 VM 已完成捕获、校验、全新目录展开、空库导入、凭据解密、CA／采集器身份保留及真实指标查询联合测试。进一步接通持久化每日备份策略、独立任务记录、并发互斥、失败和中断状态、按实际校验归档保留最近七份；原策略不因升级覆盖，未知目录及未提交归档不参与清理。新安装请求默认生成独立 timer，旧不可变安装资料不增加文件；此新安装激活路径仍需联合验收。

实际签名程序已验证定时任务命令、重复调用不重复备份、恢复库中的策略禁用，以及恢复后的真实主控 API 启动、登录和第二次进程启动后会话保留。恢复测试明确禁用执行器及业务通知，并采用隔离路径与数据库覆盖资料，不代表全部任务和通知恢复完成。报告仍只标记捕获／暂存，不把某份未验收备份标为可恢复，也不授权生产服务切换。总览分别显示归档与恢复证据，不用清理心跳推断备份成功。当前数据库写入在复制期间等待，整个命令有五分钟预算，尚未验证大数据量下的影响。命令和限制见 [完整备份实施状态](V3-FULL-BACKUP.md)。

### CA 换根组件与管理员持久任务（联合验收中）

新增显式双根／新根独占授权，绑定原 CA 的 DER 摘要、新 CA、固定成员摘要和最终确认摘要，同时要求旧、新 CA 的独立签名。新根必须使用不同公钥。初次应用授权限十分钟；已持久化的同一授权支持响应丢失后的精确重放。最终授权必须引用原双根授权，不能跳过双根、替换成员或回到旧根。

每个签发者使用独立 CRL 和持久下限，防止跨 CA 序列号碰撞或吊销历史丢失；本机信任状态原子发布并保留历史，已初始化目录损坏后失败关闭。普通 TLS、实际 Agent gRPC、受限 CRL 刷新、本机叶证书切换及后续续期已接通；schema 38 管理员持久任务及固定 SSH 编排已实现，真实联合门禁仍未通过，不能从本机原语结果推断完整交付。

2026-10-31 继续补齐：节点和采集器本机生成新私钥，用当前叶证书签名证明 CSR 持有权，主控签发只返回公开证书；节点／采集器均支持精确激活回放。原 CA 保留为历史签名锚，最终阶段不再作为 TLS 信任根。普通续期不能跨 CA，已有后继身份的签发使用被明确授权的后继目录；旧根退出后不能选择旧签发者。

宿主维护程序已按原／后继两个独立签发者刷新 CRL，续期当前采集器并发布其实际 CA 期限。最终阶段后维护不再依赖旧 CA 私钥。完整备份按原签发者、已存在的固定后继签发者、信任下限、身份的顺序锁定，后继私钥和历史仍在原受控 authority 目录内。旧不可变配置可以按认证历史核验，但运行身份必须再次通过当前信任；不会让过期种子重新参与登录或服务启动。

新增 root-only 固定子控工具 `node-v3 --identity-root-rotation`，仅接受目标节点、已安装配置摘要、当前证书摘要、共同签名信任快照及公开 CSR／证书，不接受命令或路径。它与部署共用 journal／服务锁，支持双根发布、准备、激活和只读资源核验；独立的主控真实 mTLS 观察仍必须由后续管理员任务完成。新增限十分钟、双 CA 签名的目标绑定分发授权，以安全续作原已批准但超过十分钟的不可变任务；不能更换成员、节点、配置、证书、CRL 或倒退最终信任。

schema 38 已接通主控持久管理员任务、固定 SSH、全部成员新鲜 mTLS 观察和独立最终确认；后继 CA 下的新节点及名称维护已有兼容实现。任务绑定账号版本、完整成员、配置、指纹、运行快照和签名发布，支持限时授权、检查点、租约及灾备后重新授权。现有协议仅覆盖一次原根到后继根；尚未签发且冻结的原叶证书已经到期时不能用过期证明新签发。这些边界及真实 native／Docker 29 联合门禁仍须核对，不得视为完整交付。命令见 V3-PKI.md。

### 归档后新增历史退役的独立对账

新增宿主 `export-node-retirements` 和 `reconcile-node-retirements`。检查点包含不可变退役记录，使用原 Vault 独立域的回执密钥认证，并绑定中心实例和原 CA。恢复旧归档后，需要可信外部 SHA256、当前管理员和新幂等键才能补齐；只增加缺失限制，不覆盖现有历史或运行状态。缺失／变化历史、仍活动的已退役快照、错误 Vault／CA／中心均停止整笔事务。

检查点必须独立保留最新副本；旧归档或旧检查点不能自行证明自己是最新。对账回执始终为 `cutover_authorized:false`，不启动采集、部署或通知，也不完成节点代次协调。操作说明见 `V3-PKI.md`。
