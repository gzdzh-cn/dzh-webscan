# v3 设置保存与运行策略分离

本模块已接入本地 v3 网页的“系统设置 → 运行设置”和账号绑定 API，支持白名单编辑、预览、保存及独立应用。配置恢复已接公开保存态流程；完整运行应用仍需完成；中心启动交接已增加内部适配器，尚未接入公开应用及安装器。完整 v3 仍未发布，不能用于升级生产。

## 保存和应用

schema 20 保留 `v3_settings` 作为各工作器读取的运行设置，新增 `v3_settings_drafts` 保存待应用设置。旧库没有草稿时，运行设置同时作为已保存基准，升级不补造待应用修改。

内部保存操作只改变草稿，不启动通知、不改变告警、网站检测或历史清理策略，也不部署节点。内部显式应用重新校验完整正文、账号、草稿代次及运行基准后，在同一事务更新运行设置和应用标记。启动参数、中心重启和远端节点下发仍需专用流程，不能凭这一步认为已应用。

- 草稿代次独立递增，JSON 使用字符串传递；运行设置版本独立推进。确认后配置变化时必须重新读取确认。
- 分域 HMAC 绑定草稿正文、代次、运行版本和运行正文摘要；保留旧密钥时可继续读取旧证明，新写入改用当前密钥。缺失密钥、正文损坏或运行基准变化时停止。
- 保存前及应用前，已有设置和全部节点会生成加密 `before_edit` 存档。备份、变更、幂等回执和审计同事务提交，任何一步失败全部回滚。
- 同账号同幂等键重试不重复执行，降权后不能借旧回执绕过权限。事务关系锁与节点／部署／恢复流程共用，避免混合配置快照。
- 响应与审计仅含版本、代次、状态和时间；正文不能作为公开 JSON 或诊断字符串输出。内部数据库载荷仍按含通知凭据资料保护，不能代替 SSH 独立加密仓库。

## 网页与公开接口

- `GET /api/v3/settings`：管理员读取字段定义、已保存值、运行值和两份凭据配置标记。缺失字段保持缺失，不补造已保存默认值；未知字段不返回，保存时保持原样及大数精度。
- `POST /api/v3/settings/preview`：`action: save|apply`，提交字符串 `expected_generation`、`expected_runtime_version` 和 `edit`。预览只记录安全审计，不改变草稿、运行状态、备份或远端服务。
- `POST /api/v3/settings/confirm`：原样提交编辑内容及 `preview`，同时提供 `Idempotency-Key`。关系锁内重新核对、备份及提交；同键重试返回原安全回执。

写入要求登录管理员、CSRF 和可信 HTTPS；显式配置可信反代后，可接受该直连反代的唯一 `X-Forwarded-Proto: https`，不能仅凭公网地址或伪造转发头信任连接。请求最多 2 MiB，严格拒绝未知字段、重复 JSON 键、null 容器、嵌套过深及非规范代次。

白名单涵盖已有工作器消费的网站检测参数、服务器告警阈值、飞书及 SMTP 通知参数和通知类别。主控采集器调度、启动监听、文件路径、旧模式选择、备份计划及原始指标保留不在此编辑范围。`monitoring.interval_seconds` 是告警判定参考间隔，不修改主控采集周期。未实现的随机退避开关不作为可编辑字段。

凭据通过 `edit.secrets` 的 `keep`／`replace`／`clear` 操作，SMTP 密码、Webhook 和签名密钥不回显。替换要求有效文本，遮罩不能当成凭据；保留与清除禁止附带值。启用的通道必须有完整有效参数；清除必需凭据前先停用通道。停用只影响后续投递选择，不删除队列。预览列出变更项目，提示新启用通知通道和缩短期限风险，不显示值；没有自动测试通知操作。

十分钟签名预览使用独立 HMAC 域，绑定随机票据、账号版本、完整已保存配置、运行版本、节点、启动草稿和最新部署证据。任何相关变化、未完成部署、失效票据或缺失证明密钥均阻止新提交。应用只接受已保存设置，不保存网页草稿；包含尚无运行协调器的变化时明确拒绝，不能把未知策略标为已生效。

网页在预览后确认，仅保存成功显示“尚未应用”。应用入口只处理已保存版本；有未保存输入时不可应用。服务错误保留草稿、网络结果不明时保留同一确认键，明确冲突需重新预览。重新读取先确认放弃草稿；重读失败仍保留输入。关闭预览、切换设置页或离开页面清除临时凭据并忽略迟到响应。系统设置没有新增删除按钮。

## 保留期限的兼容行为

已有历史设置接口仍将五项保留天数单独保存并生效。存在其他待应用修改时，只把相同的五项期限同步合并进草稿，不顺带应用 SMTP、飞书或告警修改；合并使旧应用确认失效。

更新保留期限保留未知字段和 JSON 数字精度，不将超过 JavaScript 安全整数范围的参数舍入。低层无密钥写入遇到现有草稿时停止，不能破坏证明；旧 YAML 初始化也不能覆盖待应用设置的基准。

## 配置备份及灾备

配置备份捕获已保存设置：有草稿时记录草稿正文和可选 `settings_generation`，同时保留 `settings_version` 运行版本。无草稿的旧文档不需要新增字段。捕获前验证草稿证明及运行基准；损坏草稿不能被包装成有效存档。

schema 19 升级前要求核验一致性备份，失败不迁移。PostgreSQL 灾备恢复保存草稿、运行设置、独立代次和证明，不自动应用；继续写入需原独立密钥。与已有恢复意图／破坏性任务的灾备取消规则并行，不复活这些操作。

## 配置恢复应用中的运行设置（schema 23）

内部设置适配器已能将已保存恢复中的设置应用到工作器实际读取的 `v3_settings`。它不是公开应用入口，也未安装到 `Serve`；节点、启动参数及完整验收适配器未完成前，统一运行器仍禁止只应用部分配置。

- 执行必须持有原任务的有效租约、成员和配置计划，重新认证当前控制账号、原候选与提交证明、两份存档及其回退引用。前向仍需原账号有效；当前另一管理员可明确接管回退，历史签名只作证据，不恢复旧账号权限。
- 核对完整草稿证明、保存代次、原运行版本及目标正文。在同一短事务提交实际设置、应用标记、加密前后回执及安全审计；任一步失败全部撤销。无设置变化也生成回执，但不增加运行版本。
- 回执使用独立 Vault 密钥进行 AES-GCM 加密，绑定任务、计划、保存代次、成员和阶段。接管可验证较早执行代次的回执，但必须持有新的当前租约，并确认实际运行状态完全匹配。回执缺失、损坏、错位或运行漂移不能解释为成功。
- 回退恢复回执冻结的原运行设置，运行版本继续递增。目标保存草稿保留供复核，重新显示待应用；不回退数据库快照，不修改事件、通知和其他节点。尚未应用设置的失败只记录无副作用回退，不提前应用目标设置。
- 单次事务上限十秒；开始和提交前均检查租约，等待取消、迁移冻结或执行中租约到期会撤销整个事务。并发重试在配置关系门禁下串行复核，不能重复应用。
- schema 22→23 迁移前必须完成一致性备份。PostgreSQL 灾备包含加密回执及运行／保存差异，未完成任务仍冻结；显式继续后可核实已经提交的效果，不因进程或恢复后的租约变化重复写入。

这些回执证明运行设置已在数据库事务中提交，不能证明节点已安装、中心已重启或外部通知已送达。真实节点协调、中心启动参数交接、完整运行验收和保护引用释放仍需完成。


## 中心启动交接（schema 24）

内部 `configurationBootstrapRuntime` 支持 `bootstrap` 与 `restore-bootstrap`，与运行设置适配器分开。它尚未组成完整应用运行器，没有公开排队入口或生产安装能力。配置保存本身不会重启或激活中心。

1. 在现有配置关系门禁与有效任务租约内，认证保存来源、账号、保护存档、成员及启动草稿代次，捕获实际运行角色。
2. 事务外核对目标 DSN 确实连接当前可写业务数据库，检查本机凭据、证书、工具及目录；后台监听地址变化时试绑定目标地址，失败不批准重启，也不终止占用者。
3. 再次加锁、复核上述计划和 DSN 字节后，原子写入加密交接与安全审计；回执为 `pending`，不推进应用检查点或已生效标记。
4. 原进程发现新交接后取消并等待全部角色退出，再签署结束记录；由外部服务管理器启动下一进程。实际安装器的自动重启与完整服务交接仍待接通。
5. 新进程从原启动信任锚解密目标配置，按已经验证的目标 DSN 打开实际连接。API 先绑定监听器并加载 TLS，再启动工作器；各角色完成首轮真实初始化后才生成签名运行记录。HTTPS 保留 HTTP/2。
6. 应用任务检查冻结角色集合、激活代次、启动及运行摘要、启动时间和新鲜签名。只有证据完整才在同一事务确认交接、更新启动草稿标记及审计；十分钟内角色仍不完整不视为成功。

进程记录表示启动与角色初始化，不代表业务全面健康。采集成功、扫描、节点版本、队列及最终配置联合验收仍由后续完整验证阶段负责。单独适配器不能绕过“全部前向及回退阶段均支持”的运行器门禁。无启动变更时完成该阶段，不创建交接、不停止服务。

`v3_bootstrap_handoffs` 的 AES-GCM 载荷绑定成员、任务、阶段、代次、批准时间及密钥；确认与进程记录使用不同域的 HMAC，拒绝正文、时间、身份、角色或状态篡改。公开序列化及诊断字符串不输出私有载荷。有效进程记录每三秒更新，十二秒内视为新鲜；超过一天的旧记录由有界维护任务清理。结束记录在全部工作器排空后写入，不能把观察协程退出当作中心已停止。

原始启动文件及原 Vault 密钥是独立信任锚，轮换后仍须保留；启动仍需通过原 DSN 文件访问业务数据库，凭据轮换不能使这个引导入口失效。目标密钥集合只有通过原锚认证后才能加入。缺失密钥、启动配置漂移、损坏交接或丢失已确认交接不能静默退回旧启动配置。监听、拓扑和分片变化不能通过普通节点操作夹带；拓扑及分片变更仍需专用迁移流程。

回退使用已认证前向交接保存的原运行配置。即使目标从未启动，也会创建新的回退代次以撤销前向批准；确认后恢复原运行配置，并保留目标草稿待复核。更换管理员不继承旧账号权限，当前恢复管理员须显式控制任务，且仍需原存档和密钥。旧租约不能确认新代次；重启或响应丢失后，新持有者先核实效果，不重复批准。

schema 23→24 升级必须先做并校验一致性备份，失败不迁移。灾备保留加密交接与确认，但删除归档中的进程心跳并冻结未结束应用；未确认交接必须由当前管理员显式恢复任务后才可启动，不能依据归档心跳确认生效。已确认运行配置可恢复解析，后续应用工作仍受灾备冻结约束。迁移与恢复不触发业务通知。

本地测试覆盖真实 HTTPS/API 重启、全部非执行器角色初始化、HTTP/2、会话与 CSRF 保留、新连接实际使用目标数据库账号、前向／回退、损坏证明及批准时间、失效账号／租约／存档、事务故障及灾备冻结。前序环境／节点检查点在这些适配器测试中明确为合成数据，不能作为真实节点安装或完整配置应用验收。

## 配置应用与子部署绑定（schema 25）

父配置应用现在具有受签名保护的节点任务绑定、统一目标发布清单及持久操作门禁。子部署成功后保留父任务需要的原回退资料；父任务接管会同时隔离旧子执行器，节点阶段和最终完成各自重新核对结果。普通独立部署不能抢走绑定任务。详见 [父子任务协调](V3-DEPLOYMENT-STATE.md#配置应用与节点任务协调schema-25)。

这仍是内部部分实现：启用节点的阶段适配器已能调用绑定子任务，schema 26 已补齐停用节点的中心登记及回退；内部组合验证器已经实现，自动准备提供器和完整公开应用运行器仍未装配。现有环境、设置及启动适配器的部分测试证明不能拼接为完整安装已经通过。保持正式版本 v2.0.46，继续本地实现与隔离验证。

停用节点只更新中心登记，不伪报远端下发或生效版本；回退保留保存草稿与新增历史，使用新代次重新采集，详见 [停用节点登记](V3-DEPLOYMENT-STATE.md#停用节点登记及回退schema-26)。


内部组合运行器已串联环境、节点、启动和设置适配器，最终联合验收将实际运行设置、确认的启动交接、有效进程及节点采集证据与检查点放入同一事务复核。空节点实际应用／中心重启及回退已做本地联调，详见 [内部组合与验收](V3-DEPLOYMENT-STATE.md#内部组合运行器与联合验收)。自动准备、公开提交、正式安装和规模验收仍未完成，当前没有对生产启用。

## 恢复记录与应用状态的区别

提交到保存配置的原始回执始终为 `saved_pending_application`，表示当时只保存了配置。它不会因后续部署完成而改写，重试也不会把旧保存请求变成新的应用请求。

恢复列表与详情的 GET 接口现会附加可选的 `stage.application`：在同一个数据库快照中批量读取关联任务并校验计划与状态签名。页面据此显示等待应用、应用中、未完成、冻结、完成或回退，详情显示任务阶段及更新时间。原 `stage.status` 仍为保存流程的状态，保持兼容。尚无关联任务时仍显示“已保存，待应用”。

完成表示**这一次历史任务**通过验收，不保证之后保存的配置或其他任务已生效。回退及取消也不删除保存草稿。读取失败保留页面上次结果并明确提示；任务证明或密钥不可用返回服务错误，不能退化成没有任务或应用成功。列表没有应用任务时无需访问 Vault 文件。

这些只读字段不授予执行权限，不接受浏览器提供的任务证明或配置正文，也未开放应用提交、继续或回退按钮。内部应用尚未装配到自动生产调度，完整公开工作流仍待后续实现。


## 内部节点准备与环境门禁（schema 27）

配置应用的内部组合现在使用加密的持久节点资料自动准备配置包。绑定从已保存的 SSH 凭据与已登记节点证书选择，规则正文在绑定时加密保存；浏览器不能提交准备回调或本机路径。环境阶段会先检查需要部署的节点资料，缺失或损坏在进入服务切换前失败；节点阶段在私有文件 I/O 前后复核父租约、来源、配置、绑定、凭据语义及证书吊销状态。

已有子任务的继续和回退复用原冻结计划，不从最新绑定重建任务。停用或已生效且登记不变的节点不会因缺少重新安装资料而误判必须安装；最终健康门禁仍执行。详见 [可信节点部署资料](V3-DEPLOYMENT-STATE.md#可信节点部署资料与自动准备schema-27)。此前章节“自动准备未完成”记录对应早期阶段，当前公开应用及自动调度仍未开放。正式安装／证书运维、迁移回退及容量验收仍需继续。


## 显式本地工作器与应用日志

schema 27 的组合现在可由 `executor.applications_enabled: true` 显式装配到 `Serve(all|executor)`，默认关闭。只处理已经保存且经认证的恢复计划，本地管理员命令可以排队或控制任务。启动后自动执行阶段；中心实际重启后等待旧租约到期，按新代次接续，不把重启请求当成功回执。说明和私有输入格式见 [本地工作器](V3-DEPLOYMENT-STATE.md#本地配置应用工作器与只读进度schema-27)。

网页新增管理员只读任务列表和应用日志，恢复记录可进入对应进度。日志游标保持字符串，网络失败保留已读内容，隐藏标签暂停。这一阶段最初只开放只读进度；当前受控 HTTPS 操作见下节，默认仍关闭。上述章节未装配到 `Serve` 的说明为早期阶段记录；正式安装、公开执行和规模验收仍需继续。


## 明确应用已保存配置

恢复详情新增独立的 `can_apply` 提示和“应用已保存配置”确认，不复用“仅写保存配置”的确认语义。只有工作器启用、原账号及版本仍有效、恢复已保存、候选已提交且尚无关联应用任务时才提示。执行时继续核实真实保存态与保护引用；不能用提示绕过并发控制。仅保存和实际应用仍是两次明确操作。

提交后立即进入持久任务日志页。继续、回退或取消固定管理员看到的任务游标；状态变化要求重新读取。HTTPS、CSRF、管理员权限和幂等要求见 [管理员应用工作流](V3-DEPLOYMENT-STATE.md#管理员-https-配置应用工作流schema-27)。开关默认关闭；此前章节中“公开提交未开放”的描述记录较早阶段，不代表完整 v3 已满足发布条件。独立节点管理、正式安装和 PKI、迁移无损回退、HA 与容量稳定性仍需完成。
