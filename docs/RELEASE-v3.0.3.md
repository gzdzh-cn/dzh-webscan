# v3.0.3 证书维护与完整备份

本说明描述 v3.0.3 的功能与限制。发布状态、构建摘要和实际验收结果以对应 GitHub Release、`acceptance.json` 及最终发布回执为准。

本版补齐受签名保护的独立宿主维护升级资料、证书续期与过期身份恢复、名称变更和旧名称裁剪、管理员显式 CA 换根任务，以及 PostgreSQL、VictoriaMetrics、配置、Vault、PKI 和部署恢复物料的完整备份。总览显示真实证书期限、维护心跳和备份证据；没有证据时显示未知。

普通子控维护不应重启中心或使现有登录失效。针对隔离联合测试发现的短暂数据库超时和备份锁住心跳问题，观察器仅在原有证据有效窗口内重试，备份仅排除恢复时丢弃的进程心跳表，仍冻结业务和配置写入。安装复验失败保留原服务、数据和配置，并返回脱敏检查原因。

本版经管理员授权更换发布签名公钥，DER SHA256 为 `cdef2eb5557be9af4df627c66a0a2d2523bbcb952bbcc6808e29eed74e4fa478`。旧签名私钥已不可用，本版不能提供旧密钥交叉签名；管理员须通过独立渠道确认新指纹，并保留旧公钥用于旧安装及恢复资料核验。密钥仅在本机受限的非缓存目录保管，不下发签名私钥；CA、Vault、SSH 信任保持各自独立。

数据库从 v3.0.2 的结构 36 增量升级至 38。升级前必须制作一致性备份；维护定时任务不会自动迁移数据库。原安装记录、CA 和 Vault 保留，不通过重新生成密钥处理兼容问题。独立维护资料使用新程序和验签资料，不能用旧工具直接管理新结构。

全新安装默认每日完整备份并保留最近七份，已有策略不覆盖。恢复先在全新独立目录校验和展开，显式导入隔离数据库；不会依据归档中的旧地址启动业务工作器、SSH 部署或通知。备份恢复门禁包括真实指标查询、原凭据解密、恢复 API 登录／重启、部署检查点保留及模拟通知出箱重放，不等同完整生产灾备切换。

CA 换根必须显式发起，先分发双根、轮换所有固定成员，再根据实际 mTLS 观察独立确认退出旧根。本版协议目前只覆盖一次原根到后继根的转换；尚未签发时原叶证书过期不能通过延长任务授权绕过身份验证。native／Docker 29 的真实 SSH、服务管理、主控任务和 mTLS 联合门禁结果随 `acceptance.json` 提供；单独原语测试不能替代这些验收。

保留原版 UI、Docker 默认方式、native 可选、文件事件首次手动查询和现有删除保护。公共规则批量下发、网页本人改密、远程卸载、v2 迁移、高可用及容量认证继续按后续版本推进。本次发布不自动升级线上中心或任何子控，也不导入旧主控数据。
