Compose 实机测试在 macOS Docker Desktop 的 Linux VM 中运行，测试覆盖挂载取消了 macOS 不支持的根目录 rslave 传播选项，生产配置保持该选项。观察到中心约 69 MiB／384 MiB、exporter 约 27 MiB／32 MiB；这是少量测试目标下的观测，不作为 50 台服务器、1000 网站长期运行的容量结论。

所有测试使用隔离目录、示例 IP 和测试账号，飞书发送关闭，未向业务群投递消息；未修改生产服务器、业务网站、Nginx 或防火墙。

systemd 测试使用本版 Go 管理库编译的独立测试启动器，不是正式 amd64 发布镜像。配置、Socket、管理数据库权限为 root 所有的 0600，Socket 目录为 0700。测试容器缺少时区包，使用 UTC 测试配置。Docker Desktop 的 amd64 仿真 systemd 单元曾以 255 退出；原生 ARM64 测试通过，正式 amd64 服务仍需在原生 Linux 环境核验。

1. 在原生 amd64 Linux 隔离主服务器验证正式程序与 systemd 单元、真实 SSH 新增节点、配置应用及中断恢复。上述 ARM64 管理库测试不能替代正式目标平台的部署验收。
2. 在旧四组件完整隔离部署上执行历史迁移、切换、故障注入与回退，核对已知事件、全部节点、账号及未发送消息。当前完成的是模块测试，尚未完成整个流程的端到端验收。
3. 核对长时间运行的数据库大小、采集延迟与内存，再发布版本及远端 latest 标签、核对摘要并同步部署包。

发布前无需在生产环境执行迁移。新版发布并完成上述验收后，用户再手动升级主服务器，从后台执行迁移；不要直接删除旧四组件或旧数据。
