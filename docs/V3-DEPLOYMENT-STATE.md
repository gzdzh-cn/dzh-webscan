## 任务记录

PostgreSQL schema 3 增加凭据、任务及日志三张表。已有 schema 1／2 必须经 `migrate-db --output <私有目录>` 完成一致性备份和校验，再以事务升级；备份失败不迁移。备份恢复按外键依赖写入，保留任务 ID、检查点及日志游标。

任务固定记录节点版本、运行方式、目标版本、SHA256、凭据引用及计划摘要，不存 SSH 密码或私钥。实际 SSH 适配还要求任务绑定签名发布清单的 SHA256；旧测试任务可缺省该字段，但不能交给真实 SSH 运行器执行。配置采用创建任务时的快照；每阶段核对节点版本及配置摘要。节点存在运行中或需要恢复的任务时，后台配置保存被阻止。只读环境检查或准备阶段失败会结束任务并解除节点保护，允许修正配置后新建任务；进入备份前先持久化恢复保护，之后失败／中断必须继续或回退。

状态为：

```text
排队 → 运行 → 成功
          ↘ 失败／中断 → 明确继续 → 运行
                      → 明确回退 → 回退运行 → 已回退
```

同节点只允许一个运行中或需要恢复的任务；失败任务不会自动重跑。继续或回退绑定任务摘要和当前日志游标，过期操作会冲突。同一账号、幂等键及请求重放原结果，不能创建重复任务。已经进入回退的任务不能改回正向部署。

正向阶段依次为环境检查、准备程序、备份、切换、验收、完成登记。前两个阶段不得停止旧服务或更改有效配置；进入备份阶段前持久化恢复保护，即使此时进程崩溃也保留保护；回退依次为恢复服务、回退验收。`applied_version` 仅在正向全部阶段完成后推进。协调器不恢复旧业务数据库快照，不删除切换后新增事件。

## 接管与远端证据

任务领取使用 PostgreSQL `FOR UPDATE SKIP LOCKED`。租约 30 秒，每 10 秒续租；每次领取递增代次。旧执行器不能续活过期租约，也不能提交结果或失败状态。

执行每个阶段前调用 `DeploymentRuntime.Inspect`，要求远端证据绑定任务、计划摘要、阶段和当前代次。远端已完成则只补交本地检查点，避免 SSH 响应丢失后重复切换；没有记录才调用该阶段，状态未知或代次不匹配时停止。

子控新增内部 `node-v3` 工具，固定使用 `/var/lib/webscan-deploy/v3/node/`。每次请求读取受限 JSON，绑定节点、任务、计划、参数摘要及代次；SQLite WAL／FULL 记录意图及完成凭据，`flock` 覆盖整个操作。更高代次先持久化；未知操作必须核实后才允许继续，旧代次及已退役任务不能重新操作。目录为 0700，数据库及锁为 0600，拒绝符号链接、硬链接及不安全权限。

工具读完请求后忽略 SSH 挂断信号；当前只读检查有独立超时。进程硬退出后，下次读取未完成意图，要求处理器证明已经完成或没有效果，不能直接重做。默认命令只支持环境检查和程序包／镜像准备；显式 `node-v3 --lifecycle` 则选择 native／Docker 完整阶段处理器，并强制要求配置包、源配置和目标版本绑定。 模拟处理器的崩溃恢复测试不能替代 native／Docker 实际安装验收。未来涉及外部子进程的处理器，还必须证明旧进程已停止，不能仅凭父进程锁已释放判断可重试。

应用退出时取消远端请求，并尽力保存中断状态；数据库暂不可用时保留租约，后续接管仍需核实远端阶段。数据库灾备恢复不代表可以直接接管 Agent，仍需完成节点代次协调。

## 安装完成的可信恢复证据（schema 28）

显式 native／Docker 子控在正常 `finalize` 完成回执中附带两份摘要：原始 `capture/intent.json` 和不可变目标活动指针的 SHA256。读取时核对原捕获、快照和激活资料，并保持 Journal 操作锁；回执重读只校验，不重新启停。证据读取失败时返回验证失败，即使本地阶段已写完成，也不能返回无绑定的安装成功。

SSH 适配仅接收绑定当前任务、节点、计划、阶段和代次的完成证据；其他阶段、恢复请求、无效摘要或缺失证据不能认证安装完成。实际 Spec 来自主控发出的请求，不从远端另收一份可替换的配置。

主控将证据、原请求 Spec 和独立密钥派生的 HMAC 存入 `v3_deployment_installations`，与任务成功、已应用版本及审计处于同一受租约保护的事务。数据库异常、验收缺失、租约过期或任一步写入失败时全部回滚。相同证据重放不覆盖原行、不重复审计；变化的证据拒绝。

证据核对使用任务绑定的不可变配置快照及其摘要，不能使用已省略配置正文的任务对象或较新的保存草稿。新草稿不影响历史证据；原快照被修改则拒绝。密钥不入数据库或备份；轮换时需保留旧验证密钥，灾备恢复也需配套密钥资料。

schema 27→28 必须先完成一致性备份，备份失败不迁移。不为旧完成任务补造远端证明。该表可随 PostgreSQL 备份恢复，但不能据此跳过远端 Journal、当前运行登记或恢复权限核对。

当前只完成证据保存链路。主控生成独立恢复任务、绑定已结束后继及新运行代次，并使用可信当前工具下发恢复引用仍未接通；公开部署写接口继续关闭。真实内核的既有恢复验收针对前一源码版本，不覆盖本次新增完成回执。

## 发布清单与工具准备

新增 Ed25519 分离签名清单校验，包含版本、Linux amd64 平台、内部工具协议、工具和 native 包的大小／SHA256，以及固定摘要的 Agent 镜像。清单上限 64 KiB，采用 Go JSON 规范序列化格式；未知字段、重复键、错误签名、浮动镜像标签及不支持的协议均拒绝。验签公钥须来自管理员独立信任配置，不能信任清单或节点随附的公钥。本轮没有生成生产签名密钥，也未发布 v3 清单。

SSH 适配要求清单摘要与任务快照一致：native 核对包摘要，Docker 核对镜像摘要。继续任务时替换工具或清单会被拒绝。新增字段保存在已有任务 JSON 中，不增加 PostgreSQL schema 版本。

`ProvisionHelper` 先验证本地私有程序文件及当前任务租约，再通过固定指纹 SSH 传输至 `/var/lib/webscan-deploy/v3/tools/<SHA256>/webscan`。只使用固定路径及十六进制摘要，远端重复核对大小、SHA256、root 所有权、0700 权限和目录安全性；使用同文件系统临时目录及原子文件替换，成功后同步磁盘。已有相同文件可重用，错误文件和符号链接不会被覆盖。此方法只准备部署工具，不安装 Agent、不更改运行配置，也不推进任务阶段。

每次调用工具仍核对目录、权限、大小及摘要；SSH 响应受 64 KiB 限制，原始 stderr 不进入日志。响应必须绑定当前任务、阶段、计划和代次。SSH 回包丢失后的再次检查会读取远端 SQLite 完成凭据，再补交 PostgreSQL 检查点。

已提供离线 `release-v3` 生成／签名／验证工具、`vault-v3` 独立密钥初始化，以及 `deployment_trust` 配置检查，见 [发布签名与独立凭据密钥](V3-RELEASE-TRUST.md)。签名私钥不下发中心或节点，验签公钥须独立预置；工具不会生成生产信任资料、上传或安装发布。正式流水线、安装菜单及业务提交流程尚未完成；执行器角色可显式启用，公开部署接口继续关闭。

## 程序包和镜像准备

`ProvisionBundle` 把同一签名清单绑定的 native 工具包传至 `packages/<SHA256>/agent-native.tar.gz`；`stage` 验证压缩包大小和 SHA256，再解包到私有临时目录。限制条目数、单文件及总展开大小，拒绝重复条目、越界路径、链接、特殊文件和异常尾部；核对完整 SHA256SUMS、版本、Linux amd64 ELF，以及随包 YARA／可选 ClamAV 客户端。现有规则不能读取或编译失败时停止。通过后原子发布到 `releases/<SHA256>/`，重放已有完成凭据时再次验证文件和工具。

Docker 使用固定本机 socket、临时匿名仓库配置和不可变 `repo@sha256:...` 引用。只有匹配镜像摘要及 Linux amd64 身份才通过。下载失败可使用签名清单额外绑定的 `image_archive` 与 `image_config_sha256`，经 SSH 发送至 `images/<SHA256>/docker-image.tar`。先核对完整归档大小及 SHA256、Docker-save／OCI 元数据和配置摘要，再从同一已验证文件描述符导入；导入后检查精确配置 ID、系统和架构。

`docker load` 可能没有 `RepoDigests`，此时通过已验签的归档及配置摘要证明身份；标签、导入输出和未经签名绑定的 config ID 都不能单独证明目标版本。归档和配置摘要也参与任务绑定，继续任务不能替换。程序不会执行 `docker run/stop/rm`、更改运行配置或删除原服务。

准备能力不等于安装完成。默认准备运行器在进入 `backup` 前明确停止，不建立尚无恢复实现的切换责任，不推进 `applied_version`；公开部署写接口继续关闭。离线证书工具与在线吊销校验见 [v3 证书工具](V3-PKI.md)。

## 停写、快照、native 切换及回退基础方法

新增内部安装归属检查、固定服务停写控制、私有恢复意图及 SQLite 一致性快照。回退导出从当前数据库按原 ID 重新输出待确认事件，先落盘再事务登记；保留备份后新增事件和已确认状态。重试复用原服务启动状态及已发布快照，异常清单、文件、归属、锁或空间均停止操作。停服后、快照发布前的中断可依据持久配置及数据库存在性恢复原服务；激活后快照缺失不能走此分支。原服务启动前重验补发文件，已有回执不能掩盖文件缺失或损坏。

内部 native 激活／恢复已增加持久意图、原子替换、精确进程参数核对、响应丢失续作及保留当前数据库的恢复；只读验收另核对 systemd 属性、进程句柄及内核 cgroup。变更客户端继承共用操作锁，父进程退出或超时不能放行重叠操作。新增独立内部 native 阶段处理器已连接子控 SQLite Journal，覆盖正向阶段、完成回执、恢复及回退验收；默认 `LocalRuntime` 仍只有预检查和准备；显式配置的执行器通过 SSH 选择完整处理器，公开部署提交仍关闭。本机完成回执不代表中心已验收或推进配置生效版本。内部 Docker 处理器也已连接阶段 Journal；独立嵌套引擎实际验证保留旧对象、同配置不同任务切换、响应丢失续作、mTLS 配置回执及当前数据补发回退。预检查替身、原生 amd64 完整内核成功验收、完整安装验收和旧服务兼容仍是未完成边界。服务控制替身、Rosetta 子进程和内核读取验证不能代替完整服务验收。详见 [子控切换数据保护及兼容缺口](V3-NODE-TRANSITION.md)。

## 实际采集网络的部署验收

PostgreSQL schema 4 增加内部 `v3_node_readiness`。它由实际采集器写入，不能由 SSH 返回的本机启动状态、API 服务或部署执行器的网络自检代替。

- 指标侧要求受每次 RPC 证书／吊销校验保护的采集连接、节点身份和协议匹配、指标持久化游标，以及进程报告的发布版本、配置版本和源摘要。
- 同一指标样本还须证明采集就绪、目录覆盖正常、根目录数量完整、规则仍属于启动配置、Agent 心跳新鲜。期望启用的 YARA／ClamAV 必须启用并通过近期自检；停用的引擎不能冒充已启用，也不要求其成功心跳。缺失、带标签、重复或非有限的关键标量不能用于验收。
- v3 Agent 在启动初始化时立即自检扫描引擎，以后每轮完成后等待 30 秒；每引擎最多 10 秒。只扫描私有数据目录 `.scanner-readiness/` 中的临时小文件，沿用实际规则、客户端和 clamd 配置，快照和规则临时文件也在此目录；结束后删除临时文件。该目录要求本运行账号所有、0700、没有符号链接，v3 实时监听、补扫和规则重载均排除它。不能将其子路径配置为监控根、关键文件或探针目录。自检不创建业务事件或通知；证据仅存于内存并绑定有效规则，重启或规则变化不能复用旧成功。
- 事件侧在正常读取并完成必要的入库／确认后记录；空队列的成功读取同样有效，不制造测试业务事件。
- 两类证据绑定节点期望版本、配置摘要、地址、TLS 名称和实际分片租约。旧代次或停用节点不能写入；链路失败删除对应证据，身份失败同时失效两类。
- `verify` 和 `finalize` 在推进检查点的同一事务中，锁定当前节点、证据及有效采集租约；要求目标版本／摘要一致，两类观测晚于本任务激活检查点且最近 60 秒有效，指标时间也有范围检查。缺少证据不能完成配置生效。
- 执行器最多等待 90 秒，等待期间续租；超时记验收失败并保留恢复资料，取消则记中断。继续任务重新获取有效证据；本机已完成阶段无需重复启动。
- 证据随数据库备份校验，但恢复时清空，必须重新采集。schema 1／2／3 升至 4 仍先一致性备份，失败不变更。

真实本地 HTTP/2 双向 TLS、Agent SQLite、事件确认及 PostgreSQL 已做联调；吊销节点证书后，原连接不能刷新验收证据。实际采集调度每次协调时批量查找正在验收且租约有效的任务，只唤醒本采集器持有分片中的对应配置版本；唤醒绕过初始抖动和普通采集间隔，合并重复请求，并沿用采集并发上限。同节点不重叠采集，慢请求结束后重新等待完整间隔；即时任务查询失败不取消已成功续租的正常采集。正常间隔设为一小时的真实 mTLS 联调已通过。另用真实 Agent、YARA、inotify 和临时 PG 验证目录丢失会阻止已经通过 verify 的任务完成 finalize，生效版本不推进。部分协调器／SSH 测试使用明确标注的证据替身，不等同于真实服务安装。生产执行器和完整探针验收仍需完成，公开部署写接口继续返回 503。另有隔离实际 clamd 自检：只加载无害测试签名、使用私有 Unix socket，客户端确实命中后验证扫描就绪；停止该测试服务后就绪失效且不影响 YARA，不生成业务事件。它不代替生产扫描库或跨部署方式安装验收。上述健康门禁复用 schema 4，不修改 RPC 合约。

## 当前环境检查边界

工具可检查 Linux amd64／root、监控目录可访问性、可用空间及 inode、native 的 systemd ≥231／管理器／CPU 与内存控制器，或已有 Docker／Compose；启用 ClamAV 时检查客户端及固定 clamd socket。空间估算包含程序及可选镜像归档的准备空间、现有数据库两份空间及 512 MiB 预留。缺失证据显示未知或失败，不伪报通过。

指标端口只读取本机 TCP 监听表，无法证明云安全组、来源限制或链路可达。占用端口显示待核实；无法读取必要监听表显示未知，不认为端口空闲。此阶段不会监听端口、安装 Docker、改变防火墙、停止服务或连接业务通知渠道。跨主机网络及 mTLS／授权的部署验收仍需接入后续流程；程序包准备已验证实际 YARA 工具及规则。

## SSH 凭据

- 使用 AES-256-GCM，随机 nonce；认证数据绑定凭据 ID、节点、密钥 ID 和凭据修订号，防止调换或篡改。
- 主密钥为独立的 32 字节随机值文件，十六进制保存；要求属于服务运行账号、权限 0600／0400，拒绝符号链接。主密钥不进入 PostgreSQL、配置导出或任务备份。
- 密码或未加密 OpenSSH／PEM 私钥二选一；加密私钥、公钥及损坏内容明确拒绝。必须先核实主机 SHA256 指纹。
- 替换产生新凭据 ID；任务和回退引用的旧凭据继续保留。密钥轮换可带旧密钥读取，再逐条重新加密；旧备份恢复仍需要对应的旧密钥资料。
- 幂等请求仅保存独立派生 HMAC 的摘要，避免密码出现在请求回执或形成未加密密码摘要。跨主密钥切换的旧凭据写入重试可能返回幂等冲突，应先查询原操作结果，不能自动重复创建。
- SSH 连接限定为有效任务指定的加密凭据，复用现有 Go SSH 实现，以 root 认证并核对固定指纹；不修改 v2 known-host 文件。连接成功不等于安装或验收成功。

当前凭据接口仅供内部模块调用；已提供离线密钥初始化／检查命令，尚未开放网页凭据管理及生产初始化向导。后续接入必须同时完成权限、TLS、审计及密钥灾备流程。密钥文件读取拒绝任一层符号链接、不安全父目录和额外硬链接；旧密钥最多 8 个，重复密钥明确拒绝。

## 配置应用与节点任务协调（schema 25）

新增内部父子任务绑定与目标清单记录。配置应用中的节点任务继续使用原部署表、不可变计划、阶段日志、配置备份及远端代次，不复制另一套部署流程。每个绑定的 HMAC 覆盖父计划、节点、子任务、执行顺序、父代次和子计划摘要；目标清单使用独立 HMAC，固定全部子任务的版本与发布清单，防止程序重启后混入另一版本。

父应用排队、运行或仍承担恢复职责时，普通节点创建任务、领取、续租、阶段提交、恢复、登记和普通编辑入口均受持久互斥门禁约束。不同节点的普通部署仍可并发。门禁先取得共享／独占行锁，再取得关系及记录锁；父应用状态变化推进门禁代次，等待后的旧重复读事务会发生可重试的序列化冲突，重新检查实际状态。

仅内部精确绑定的节点执行上下文可执行子任务。每次 SQL 提交重新认证父账号、来源存档、有效租约、阶段、方向及绑定，不能仅凭旧子任务租约继续操作。父任务接管会推进子执行代次，即使旧子租约未到期，旧执行器也不能续租或提交。远端仍必须取得主机操作锁并核实持久检查点；数据库接管不等于远端操作已经停止。

已启用节点按 ID 顺序逐台执行，后续节点不能越过前序未完成节点；回退按绑定顺序逆序执行。成功子任务清除自身“需要恢复”状态，但保留原回退备份引用，供父应用后续阶段失败时使用。私有回退可重新打开成功子任务的原计划，不以新备份替换旧基准。回退完成恢复原已生效版本，同时保留较新的保存配置待应用；中心新增事件不被旧快照覆盖。

未进入服务变更且尚未武装恢复的任务，只有核对原运行登记未变后才能结束，并明确审计“服务未变更”；不伪造远端恢复回执。子任务未结束、采集证据不新鲜或登记不匹配时，父节点阶段不能推进。父应用最终成功／回退事务再次认证全部子任务，只有所有子任务结果符合方向且备份可用，才解除本任务的回退备份引用；任一失败不部分释放。备份本体与业务事件继续保留。

独立部署成功和回退时会清除持久恢复标记；历史终态行残留的旧标记在读取时归一化，恢复预览不再把这些终态任务误判为未完成。失败／中断且已武装恢复的任务继续阻止新的配置恢复。

schema 24→25 必须先完成可校验的一致性备份。灾备恢复保留签名绑定和目标清单，但冻结未完成父应用；旧子租约不可自行执行，必须由当前管理员明确恢复父任务并以新代次接管。取消中的子执行器保留精确上下文写入中断记录，不能通过一个无绑定的后台上下文绕过门禁。

内部 `nodes`／`restore-nodes` 阶段适配器现已调用绑定子任务执行器：按顺序准备缺失任务、重用已有任务、失败后停止后续节点、回退按逆序执行，结束后重新核对实际 SQL 登记及新鲜采集证明。检查入口不准备配置包或触发远端动作。准备来源由可信本地配置／证书提供器注入，目前未装配公开全自动提供器。schema 26 已补入禁用节点的独立前后回执，见下节。

本节仍是内部部分实现，尚无公开父应用提交入口，也未在 `Serve` 中装配组合应用运行器。测试使用真实 PostgreSQL、发布清单验签、加密凭据和 SQL 验收条件；远端安装动作、采集观察及部分父阶段检查点仍为合成夹具。它不代表 native／Docker 实机安装、完整公开恢复应用、HA 或万台容量验收已经完成。


## 停用节点登记及回退（schema 26）

内部节点阶段现在支持停用节点。只改变中心采集登记，不操作远端服务，不推进 Agent 的下发或生效版本。登记快照、采集代次、状态缓存失效、待发送健康告警取消、加密前后回执和审计在同一事务中提交。未安装节点也可保存停用登记。只读检查不改变登记。

回执使用 Vault 的 AES-GCM 密钥，绑定父任务、不可变计划、中心成员、节点和方向。继续／接管时同时核对回执与实际登记、快照摘要和生效版本；旧账号、旧租约、来源损坏、迁移冻结或登记漂移均拒绝。最后一条审计写入后再次核对租约，过期则回滚整个事务。并发重试只产生一次效果。

回退恢复原登记或撤销首次登记，并使用新的运行代次隔离旧采集请求。保存的目标草稿继续待应用，不覆盖数据库、不删除新增事件，也不复活取消的告警、通知租约或过期观测。父节点检查点与终态检查都要求对应回执及实际效果匹配。已经完成前向节点阶段却丢失回执时不能跳过回退。

schema 25→26 仍要求先完成可校验的一致性备份；灾备保留回执但冻结未完成任务，必须由当前管理员明确继续。此实现仍是内部节点适配器的一部分；下节已补入内部组合验收，自动准备提供器、公开应用入口、完整安装与迁移及容量门禁尚未完成，不构成正式 v3 可发布条件。


## 内部组合运行器与联合验收

环境、节点、启动交接和运行设置阶段现已通过内部 `configurationCompositeRuntime` 组合。节点准备、验签目标、运行配置或恢复阶段不完整时，不声明具备完整执行能力；公开提交和 `Serve` 的自动父应用调度仍未开放。普通部署仍使用现有执行器。

`verify`、`finalize` 和 `verify-rollback` 不修复遗漏阶段：它们要求真实设置回执与当前草稿／运行策略一致，启动交接已确认且所需角色有新鲜签名进程记录。启用节点、未变化节点以及回退后重新启用的节点均需真实登记与新鲜采集证据，覆盖指标、事件链路、目录、规则和已启用扫描引擎。缺失、错误、过期、旧租约或错误配置版本不能解释为成功。

实际数据库身份及 VictoriaMetrics 查询／空导入检查在事务外执行；不写入测试指标，不连接飞书、SMTP 或业务网站。随后在持久操作门禁内重新认证父任务、账号、来源、运行状态及租约。最终复核与检查点共享一个 SQL 事务，不直接采信先前检查返回的“完成”。终态同时解除子部署和父恢复的精确回退引用；审计、日志、引用或最后的租约核对失败均回滚，不留下半完成状态。存档本体、历史和新增事件保留。

本轮实际运行过空节点的完整内部应用链、真实中心进程重启及逆向回退、实际 PG／VictoriaMetrics 连接。节点健康及部分远端测试仍用明确的合成观察；这不是正式安装器、完整公开工作流或万台验收。联合验收的批量查询与规模预算、自动准备提供器、公开流程及完整安装／迁移仍待继续，正式版本不变。

恢复记录列表和详情现可读取经过签名认证的关联应用任务，以区分保存、应用和回退。按页一次批量查询，不为每条记录独立查任务；阶段和状态与恢复记录共享 MVCC 快照。只有历史查询展示，不启动工作器、不解除备份引用，也不改变原始保存回执。详见 [恢复与应用状态](V3-SETTINGS-LIFECYCLE.md#恢复记录与应用状态的区别)。


## 可信节点部署资料与自动准备（schema 27）

新增本地 `control-v3 --action bind-node-provisioning`。输入只通过属于运行账号的 `0600` JSON 文件读取，不接受浏览器路径、上传文件名或任意远端命令：

```json
{
  "node": "node-example",
  "expected_version": 1,
  "expected_generation": 0,
  "credential": "已入库的凭据ID",
  "identity_id": "已签发登记的节点证书ID",
  "collectors": ["collector-local"],
  "rules_file": "/绝对路径/私有规则.yar"
}
```

```bash
.cache/webscan-v3 control-v3 --action bind-node-provisioning \
  --config /绝对路径/隔离配置.yaml --username admin \
  --request-key binding-example --source /绝对路径/binding.json
```

`expected_generation: 0` 只允许首次创建；替换需提交当前代次。绑定需要当前管理员、准确节点版本和有效已登记身份，拒绝未完成部署／配置应用期间修改。规则最多 512 KiB，重复键、未知字段、不安全文件、错误节点凭据和无效采集身份均拒绝。绑定、幂等回执及审计原子提交。输出只有绑定 ID、节点、代次与配置状态，不回显凭据 ID、私钥、规则、来源路径或明文配置。

`v3_node_provisioning` 的私有引用、语义摘要、采集身份和规则正文使用 Vault AES-GCM 加密，AAD 绑定记录、节点、密钥及代次。SSH 凭据和节点叶私钥继续保留在各自加密登记表。规则在绑定时读取一次，运行时不依赖原本机路径。凭据只重新加密但语义不变时可以继续使用；替换实际 SSH 凭据、证书变化或吊销后需重新核实。旧 Vault 密钥仍须保留，特别是旧数据库备份；本次没有增加全量密钥轮换／清除工具。

内部组合运行器的环境阶段先检查需要部署的节点资料，再检查真实 PG／VM 依赖，最后复核资料；缺失／损坏在进入服务切换前失败，不产生配置包或子任务。节点清单一次认证、两批读取；逐节点资料及密码学校验仍有开销，单次十秒预算，不构成容量验收。停用节点以及已生效且登记完全一致的节点不要求重新准备资料，但最终健康验收继续检查适用节点。

节点阶段读取实际父应用的有效租约、来源和当前配置，解密凭据绑定并验证已登记证书、主机名、采集身份与吊销下限，生成内容寻址的 `0600` 私有配置包。文件 I/O 在 SQL 锁外进行；写入后重新认证实际租约、账号、配置、绑定和资料摘要。过期、接管、篡改或来源变化不能授权创建子任务。失败可能保留无引用的不可变包，不能直接删除可能被其他任务引用的同摘要文件。

安装／升级判断使用现有已生效版本和运行表的 `delivered_version`。native／Docker 的目标来自验签发布清单，不使用浏览器传来的镜像或版本。已关联子任务只能继续原不可变计划，禁止重新准备替换；回退通过原子任务和配置包进行，即使绑定后来不可用也不重新选取材料。

schema 26→27 仍要求先完成可校验一致性备份；灾备恢复保留加密绑定及审计，未完成应用继续冻结。内部工厂已自动装配此提供器，公开应用提交、`Serve` 自动调度及完整安装器仍未开放。测试中的远端服务／采集观察有明确的合成夹具，不算实际 SSH 安装、完整 PKI 生命周期或万台规模已通过。


## 本地配置应用工作器与只读进度（schema 27）

`executor.applications_enabled` 为实验性本地开关，默认 `false`，并要求 `executor.enabled: true`。显式开启后，`all` 或 `executor` 角色装配真实节点准备、阶段运行器及联合验收；同一进程一次处理一个阶段。启动就绪包含 `configuration-applications` 的首次授权查询与心跳，不能只因启动了协程就报告就绪。缺失信任资料时启动失败。

工作器按原稳定中心成员领取任务，每进程使用独立所有者。持久门禁、签名任务及 45 秒租约隔离其他工作器；阶段执行期间续租，过期后重新核实实际效果才接管。失败任务等待管理员明确处理，不无限自动重试。退出时取消并等待当前阶段排空，保留尚未完成的检查点；启动交接请求不等于重启完成。目标配置不能在本任务结束前关闭自身执行器／应用工作器。

以下本地命令只读取管理员提供的私有 JSON 文件，不接受路径、检查点或远端输出作为执行成功证明：

```bash
webscan control-v3 --config /etc/webscan-v3/control.yaml \
  --action queue-configuration-application --username admin \
  --request-key apply-one-saved-restore --source /root/apply.json
```

`apply.json`：`{"stage":"<64 位恢复编号>","generation":"<候选代次>","confirm":true}`。必须是已经真实提交到保存配置的恢复，候选代次使用十进制字符串；排队本身不表示生效。

```bash
webscan control-v3 --config /etc/webscan-v3/control.yaml \
  --action control-configuration-application --username admin \
  --request-key control-one-application --source /root/control.json
```

`control.json`：`{"id":"<64 位应用任务编号>","action":"resume","confirm":true}`，`action` 为 `resume`、`rollback` 或 `cancel`。文件权限 `0600`，拒绝符号链接、重复键、额外字段和多个 JSON 对象。重试保持相同请求键。只有原账号版本仍有效时可继续正向应用；当前管理员可以接管回退。有恢复责任时不能取消，工作器关闭时仍可取消尚未切换的任务。该阶段最初仅开放本地操作；当前网页提交与控制见下节，默认仍关闭。

管理员可在“部署任务 → 配置应用任务与日志”查看进度；恢复记录也提供对应日志链接。公开只读接口：

- `GET /api/v3/configuration-applications`：分页，可按 `stage` 筛选。
- `GET /api/v3/configuration-applications/:id`：签名认证的历史状态及同快照操作提示；实际控制须重新授权。
- `GET /api/v3/configuration-applications/:id/logs?after=0&limit=100`：相同数据库快照内的任务与连续日志，默认 100、最多 200 条。

日志只含固定阶段／安全代码、时间及十进制字符串游标；不能将游标转为 JavaScript 浮点数。缺失日志、非法代码、任务签名或密钥损坏返回服务错误，不能显示假成功。网页运行中每三秒读取，后台标签暂停；失败保留结果和游标，切换任务取消旧请求，终态及日志补读结束后停止轮询，页面最多保留最近 1000 行。历史成功不代表当前配置版本仍生效。

已验证的真实 `Serve` 流程使用空节点、隔离 PostgreSQL 和模拟指标 HTTP；实际重启接管等待原 45 秒租约自然到期，另覆盖双工作器竞争及活动阶段退出。该证据不替代真实 native／Docker 节点安装、完整公开工作流、高可用故障转移或容量验收。本地开关仍保持默认关闭，不更改生产及正式版本。


## 管理员 HTTPS 配置应用工作流（schema 27）

`executor.enabled` 和 `executor.applications_enabled` 同时启用后，管理员可在恢复详情中单独确认“应用已保存配置”。默认关闭；不开放任意配置正文、文件路径、远端命令或运行检查点上传。创建任务后立即进入 `/configuration-applications/:id`，任务排队不显示部署成功。普通独立节点安装／升级的公开提交仍未开放，不受本入口替代。

- `POST /api/v3/configuration-applications` 只接受 `stage`、正规范十进制字符串 `generation` 和 `confirm: true`。重新核实原账号、保存态、候选证明、备份引用及配置关系门禁；幂等重试返回原排队回执。
- `POST /api/v3/configuration-applications/:id/resume|rollback|cancel` 只接受 `expected_log_cursor` 字符串和明确确认。固定当前成员及签名任务上界；任务推进、成员不匹配、活动租约或恢复保护冲突返回 409。普通排队任务无需“继续”。原账号及版本有效才可继续前向；其他当前管理员可明确回退。有恢复责任不能取消。
- 全部写入要求登录管理员、CSRF、幂等键和可信 HTTPS。仅显式列入可信代理的来源可以声明 HTTPS；请求头不能自行授信。开关关闭返回 503，不创建或控制任务。本地旧命令保留原请求摘要，不影响已有防重回执。
- 详情和日志响应的 `can_resume`、`can_rollback`、`can_cancel` 与任务处于同一快照。它们仅为提示，执行时重新核实。界面确认期间固定操作、任务 ID、游标和请求键，暂停进度轮询；不自动提交写请求。响应丢失时手动重试沿用同一请求键，明确冲突后要求重新确认。
- 读取失败保留原数据并禁止依据过期状态新建控制确认。切换路由、退出或权限变化撤销本页请求，迟到响应不能覆盖新页面。所有游标保持字符串，超过 JavaScript 安全整数仍精确。

实际 API→`Serve` 验证使用隔离 PostgreSQL、空节点及本地指标服务，覆盖完成、依赖失败后明确继续与幂等重试；恢复授权测试中的节点前序检查点明确为合成。此闭环不证明真实 native／Docker 节点安装、独立部署管理、完整迁移、HA 或容量稳定性通过。

## 历史安装的独立恢复任务（schema 29）

连续安装后，原成功任务不能重新打开来回退。主控新增本地管理员命令，创建新的 `recover` 任务；该类型不被公开部署请求接受。必须显式启用执行器，源任务须正常完成并保存 schema 28 的可信安装证据，当前后继须已完成回退，运行登记必须与源安装一致。无证据的旧任务不补造授权。

```bash
webscan control-v3 --config /etc/webscan-v3/control.yaml \
  --action queue-deployment-recovery --username admin \
  --request-key restore-one-historical-installation --source /root/recovery.json
```

私有 JSON 输入只包含 `node`、`expected_version`、`credential`、`source_job`、`source_plan_digest`、`head_job`、`head_plan_digest`。文件遵循既有账号所有者、0600、拒绝符号链接、大小及重复键限制，不接受路径或命令字段。源码／计划摘要应取自核对过的本地任务记录；此命令仅用于隔离验证，不代表正式安装入口。

- 同一事务保存当前配置的加密存档、新任务、分域 HMAC 来源绑定、回退引用、日志、防重回执和审计。备份或任何写入失败均不产生部分任务。重复请求键只返回原任务；并发不同请求只有一个可取得节点。
- 固定来源、后继及其计划摘要；来源不能已被另一恢复任务使用。后继必须是创建前最新节点任务；普通后继还须已有激活完成检查点，不能用未切换服务的本地结算冒充远端激活证据。恢复链最多 128 层，逐级核对独立密钥证明、原安装摘要及终态；历史链校验不要求祖先仍处于当时运行代次。
- 新任务保存当前 `from_runtime` 和来源最初的 `restore_runtime`。每阶段检查完整不可变快照摘要与当前代次；发布旧快照时从当前代次加一，不重用历史 epoch。原普通部署的代次条件保持不变。执行阶段与完成事务均重新认证授权，缺失远端完成回执不能推进。
- SSH 使用新任务身份、来源安装 Spec、capture／指针摘要及已结束后继的引用；原任务保持原终态。下发当前签名清单所绑定的辅助程序，不依赖来源的旧配置包或已过期证书文件，不上传前向部署程序包、镜像或配置。实际旧安装资料仍须由子控在本机锁内验证。
- 响应丢失和接管沿用新任务继续，重新探测远端阶段；恢复失败继续保护备份。终态恢复已应用版本并释放本任务引用，保留较新的已保存草稿、历史事件和当前子控数据库。恢复前原本未登记时移除运行登记及其当前采集／健康状态。
- schema 28→29 需要一致性数据库备份，失败停止；数据库备份包含新任务与来源绑定，恢复后仍需原独立密钥。本改动未开放公网恢复写接口，未接入配置应用父任务的历史恢复协调，未替代完整中心／子控联合验收。
