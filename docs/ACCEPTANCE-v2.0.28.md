# v2.0.28 公开 Docker Hub 项目镜像加速修复

## 原因与修复

首次安装已通过物理内存检查，失败发生在准备 agent 镜像。配置中的 `registry.prefix: docker.io/gzdzh` 被当作私有项目入口，因此公开项目镜像跳过了 `registry.mirrors`，实际由 Docker 的全局加速器处理；全局加速器的认证请求超时。

项目入口只有在 `auth_required: true` 时直接拉取。公开 Docker Hub 项目镜像与第三方组件按 YAML 的加速源顺序下载，失败后尝试官方引用。非 Docker Hub 仓库保持直接下载；需要认证的项目不向匿名加速源发送凭据。固定摘要在来源切换时保留。

SH 引导提取工具仍直接下载 central。此修复不修改 Docker daemon 的全局加速器；`registry.mirrors: []` 仅关闭脚本配置的加速。README 和仓库配置说明已同步澄清两者区别。

## 验证

- 回归测试覆盖公开 central/agent 的 latest、版本标签及摘要引用、多个加速源顺序和官方回退，以及需要认证的项目和其他公开仓库保持直拉。
- 前端类型检查、6 项测试、Vite 构建及 Go 全量测试通过；镜像候选和凭据隔离的竞态检查、部署包静态检查及差异空白检查通过。
- 实际主服务器通过其配置的加速源拉取 v2.0.27 agent 固定摘要成功，证明该源可用。本次测试只下载镜像，没有创建监控容器。
- 修复后的 Linux amd64 下载程序在实际主服务器加载原 YAML，通过配置的加速源成功拉取 v2.0.28 central、agent 的 latest；两份实际下载摘要均与 Docker Hub 发布记录一致。

## 发布

两个公开 Docker Hub 仓库均发布 v2.0.28 和 latest。分别匿名下载所有镜像层，验证压缩和解压摘要，加载后的镜像身份与本地构建一致；版本标签、latest 和发布记录的摘要一致。摘要记录保存在 `dist/v2.0.28/release.json`。

本地 SH 及主服务器三文件部署包已更新。同步保存权限受保护的旧包备份，YAML 字节保持不变；离线主服务器预览通过，部署状态及运行容器 ID 与同步前一致。真实前端产物保存在 `dist/v2.0.28/frontend`，源码恢复纯 Go 开发占位页面。

## 原失败任务的处理

旧任务锁定 v2.0.27。`--resume` 必须使用原工具与原配置，不能借此切换到新部署程序。原任务停在 `preparing`，中央配置回退记录为空，没有本次启动的节点记录，也没有主服务器 Compose 配置；尚未切换监控服务。

更新部署包后由管理员执行：

```bash
cd /root/webscan-deploy
bash deploy-webscan.sh --rollback
bash deploy-webscan.sh
```

第一条部署命令结束原失败任务，第二条进入新版菜单，选择安装。YAML、HTTP/HTTPS 选择、账号、数据及原日志保留；不手动删除或伪造状态文件。发布和部署包同步阶段不安装生产监控服务。

私有配置、快照与验证日志存放于 `.cache/transport-v2.0.28/`，不可公开上传。
