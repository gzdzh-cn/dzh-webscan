# v2.0.27 隐藏目录规则与部署验收修复

## 原因

节点的 `monitor.exclude_paths` 包含 `/www/wwwroot/**/.*` 时，监控程序按规则忽略隐藏目录。部署工具此前固定创建 `.webscan-deploy-test-编号/fixture.php`，导致测试文件被正常忽略，中央服务收不到测试事件，最终报 `acceptance_event_timeout_create`。本次线上日志中的内存、主服务器就绪和后台账号验收已经通过；节点数据库中没有对应测试文件事件，HTTP 事件端口也可连通。

## 修复

- 验收和部署后的 PHP 修改测试共用目录选择逻辑。优先保留兼容的隐藏目录；被规则排除时，使用普通 `webscan-deploy-test-编号` 目录。检查当前节点的完整合并规则，允许从多个监控根目录中选择可监控路径，不修改用户的忽略规则。
- 部署环境检查提前校验测试路径。没有可监控的 PHP 测试路径时，立即提示 `monitor.roots`、`extensions`、`exclude_paths`，不等待文件事件超时。
- 主服务器识别新旧两种受保留的测试目录；静默验收仍要求管理身份登记确切路径、内容摘要、动作和扫描结果。业务文件、未登记内容、扫描失败及过期登记保持正常告警。
- 旧主服务器通过能力标识校验。单节点安装遇到普通测试目录需求，而现有接收服务不支持时，提示先升级主服务器，不绕过注册校验。
- 全量任务只有在自动回退已确认、全部节点已回退、没有验收通过节点、主服务器登记已撤销、配置和操作范围一致时，菜单 1 或完整 `--upgrade` 才能使用新目标版本重试。创建新任务并保留原日志、备份、数据库及队列。明确执行 `--resume`/`--rollback` 继续锁定原任务版本；部分节点已验收、回退未确认或 YAML 已改变时不允许此重试。

## 验证

- 前端类型检查、6 项测试、Vite 构建和 Go 全量测试通过。bootstrap、部署、中央服务及 common 包竞态检查、`go vet ./...` 和差异空白检查通过。
- 回归测试覆盖隐藏目录被排除、普通目录可监控、多根目录选择、无 PHP 覆盖立即失败、新旧测试目录识别、未登记/不同内容/扫描失败正常通知，以及旧接收服务能力判断。
- 重试测试覆盖新任务和旧备份分离、节点先准备再更新主服务器、原协议保持不变，以及未确认回退、部分验收、未回退节点、配置改变、范围改变、卸载任务及显式恢复的阻止条件。
- 实际 Linux amd64 SH 包在隔离环境证明已确认回退任务选择 `latest`，临时容器删除，引导锁保持、部署锁释放，所选 YAML 不被改写。
- 实际 central、agent 和固定版本 Vector 镜像分别通过 HTTP/HTTPS 隔离联调，开启忽略隐藏文件规则；文件新增、修改、移动、删除、YARA、消息登记、飞书业务响应重试、Loki 投递、接收服务重启、真实 PHP 修改测试、队列排空及不重启容器的规则更新均通过。飞书和 Loki 使用隔离模拟服务，没有向业务群发送测试消息。

## 发布与交付

central、agent 的 v2.0.27 与 latest 发布到公开 Docker Hub。版本标签与 latest 对应摘要一致；匿名下载全部镜像层，核对压缩与解压摘要并重新加载，镜像身份与本地构建一致。摘要保存在 `dist/v2.0.27/release.json`。

发布同步前复核发现主服务器监控容器和部署记录已被移除，因此按当前状态更新三文件部署包，不恢复旧记录。同步保留完整 YAML、HTTP 设置及 64 MiB 安装预留，文件备份受权限保护；离线预览通过，部署状态及业务容器 ID 保持不变。生产安装由管理员手动执行，安装时仍按 960 MiB 门槛检查可用物理内存。

私有配置、快照与日志位于 `.cache/transport-v2.0.27/`，不可公开上传。本次没有安装或切换生产容器，没有修改业务站点、Nginx 或防火墙。
