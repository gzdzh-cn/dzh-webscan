# v3 内部部署执行器

当前公开网页流程、外部执行器、凭据及恢复接口见 [网页部署说明](V3-WEB-DEPLOYMENT.md)。新接口已接入，能力由真实信任资料和工作器心跳决定；正式验收仍以发布记录为准。

以下为此前分阶段实现记录，涉及“公开写入未开放”的表述仅描述当时边界。

最新进展：显式生命周期已接入[固定模板包装组件的整组目标切换与恢复](V3-NODE-TRANSITION.md#整组目标切换与恢复边界)。预检查只读，备份保留全组证据，native／Docker 启动前复查停写；恢复导出当前未确认事件后才恢复旧成员，响应丢失按持久化边界续作。真实 systemd、活动三容器、完整中心验收和公开写入仍未完成。

本地开发入口已将 PostgreSQL 部署协调器、验签 SSH 适配和子控 native／Docker 阶段处理器连接起来。默认关闭，不改变 v2 部署流程。实际 systemd 安装、Docker 完整原生内核成功验收、旧三容器接管、证书分发与轮换、公开预览／提交流程及 Vue 接入仍未完成，不能用于生产升级或据此发布完整 v3。

## 显式配置

先准备独立密钥、受信任公钥及已签名的程序包，见 [发布信任工具](V3-RELEASE-TRUST.md)。再在隔离配置中添加：

```yaml
executor:
  enabled: true
  concurrency: 4
  configuration_directory: /var/lib/webscan-v3/node-configurations
```

`concurrency` 省略为 4，允许 1～32。关闭 `enabled` 可以保留目录和并发偏好，不启动执行器。配置包目录必须已存在、属于服务账号、权限 `0700`，逐层拒绝符号链接及不安全父目录。`deployment_trust` 必须完整配置；初始化不会自动相信下载文件中的公钥。

```bash
webscan control-v3 --config /绝对路径/隔离配置.yaml --action run --role executor
```

`all` 角色仅在 `executor.enabled: true` 时包含执行器；`api`、`collector`、`notifier`、`websites` 不会因此额外启动执行器。执行器在领取任务前验证密钥、发布签名、工具／native 包、可选镜像归档和目录；错误即启动失败。角色心跳记录实际活动数和并发，不记录 SSH 或配置内容。

## 每个任务独立的配置包

配置包由现有内部 `PrepareNodeConfiguration` 创建，固定存为：

```text
<configuration_directory>/<任务绑定的 SHA256>/node.json
```

任务必须同时绑定发布清单、目标程序、配置包大小及 SHA256、节点配置版本和源摘要。执行器不使用一个会被其他部署覆盖的公共配置文件。每阶段校验任务绑定的文件和当前配置，准备阶段通过固定指纹 SSH 发送对应包；浏览器不能指定服务器路径。

同一个执行器可以并发处理不同节点。配置包缺失、变动、权限不安全或任务没有绑定包时停止，不能猜用其他文件。HA 接管实例必须能够读取同一批不可变发布资料和配置包；自动共享／分发存储及安装向导尚需完成。

## 子控阶段入口

默认 `node-v3` 仍只提供预检查和程序包准备。受校验的 SSH 命令显式增加 `--lifecycle` 后，才按请求的部署方式选择真实 native／Docker 阶段处理器：

```text
预检查 → 准备 → 备份与停写 → 激活 → 本机验收 → 本机完成
                                    ↘ 恢复 → 回退验收
```

未绑定完整配置的生命周期请求会在创建操作记录前拒绝。请求不接受命令或任意路径。工具参数是服务端生成的固定开关，仍须先验签并核对工具文件；不会回退调用旧安装脚本。

子控操作锁、持久化意图、递增代次和完成凭据沿用 [切换数据保护](V3-NODE-TRANSITION.md)。SSH 中断后不能仅凭本地日志重做；接管先读远端凭据。备份后失败保留继续／回退责任，原服务或新事件数据库不会被旧快照覆盖。旧三容器和不支持的包装服务继续明确拒绝。

v2 目标激活前现已增加 [旧 JSONL 对账](V3-NODE-TRANSITION.md#v2-jsonl-启动前对账)：只从已校验快照补入当前 SQLite 缺失的事件，保留已有确认和扫描状态；事务游标支持中断续作，损坏或冲突阻止目标启动。该前置能力不解除旧 sidecar／包装服务的接管限制，默认开关与公开部署接口均未改变。

旧 Vector／exporter 的 [systemd 包装模板](V3-NODE-TRANSITION.md#旧-systemd-包装单元的只读识别) 现已接入归属检查，兼容其实际 `0644` unit。它只允许已经停止且禁用的已知残留通过；活动包装服务仍拒绝。原模板启动前会删除并重建容器，尚不能用它直接恢复原容器 ID，因此没有开放旧三容器自动接管。

已增加 [包装服务的停写与恢复步骤](V3-NODE-TRANSITION.md#包装服务的内部停写与原对象恢复步骤)：持久化原状态后改用不可变 ID 单元，支持响应丢失续作和只读核对；完整原模板保留在私有资料。显式 SSH 生命周期已将该步骤接入整组备份、native／Docker 目标激活及恢复。主 capture 始终绑定 Agent 与各包装成员，只有同任务协调器核对通过才使用 Agent 视图，普通启停方法仍拒绝忽略包装成员。

保留 ID unit 已增加[跨任务来源识别](V3-NODE-TRANSITION.md#保留-id-unit-的跨任务来源识别)：首次来源在替换前持久化，后续任务核对原意图、当前对象、配置及实际状态，不创建引用链。普通只读清单只接受已停止、禁用的保留组件，活动组件必须走显式整组迁移。公开部署写入及真实安装验收仍未完成。

中心 `verify`／`finalize` 仍须由实际采集器的 mTLS 身份、指标落库、配置回执、目录／扫描健康与事件读取证据共同确认，不能由本机完成凭据代替，详见 [部署门禁](V3-DEPLOYMENT-STATE.md)。执行器角色不会重启主控。

迁移冻结期间不领取新任务，不发起下一阶段远端调用，也不提交阶段完成。冻结本身不把任务标为失败；解除冻结、原租约到期后可接管原任务，先核对远端检查点再继续。冻结不能撤销已经发出的远端操作；正式迁移切换仍须等待执行器与远端阶段稳定，不能把数据库冻结记录当成所有节点已经停写的证明。

## 当前接口与验证边界

公开部署写接口继续返回 503，详情中的继续／回退能力仍为 false。本地管理员可通过 `store-ssh-credential`、`prepare-deployment`、`queue-deployment` 读取私有输入、验证当前采集信任、准备节点包并排队；详见 [配置包的本地准备与提交](V3-NODE-CONFIGURATION.md#本地管理员准备与提交)。本地账号绑定十分钟预览和事务确认见[部署预览](V3-DEPLOYMENT-PREVIEWS.md)。完整的自动 PKI 分发、公开凭据管理和网页预览／提交尚未开放；本入口不替代最终单中心安装交付。

本轮真实 SSH、PostgreSQL 和远端 SQLite 联调覆盖配置包分离、固定命令、备份响应丢失、继续及回退；其中服务操作与采集门禁使用明确标注的测试证据，不能冒充实际 systemd 安装。Linux CLI 实际启动并终止 executor 角色，角色心跳正确；容器缺少 systemd 时 `node-v3 --lifecycle` 预检查失败，不启动服务。更早的独立嵌套 Docker 引擎证据仍按原范围使用，本轮没有将它计为完整执行器端到端验收。

## 部署前存档认证

执行器与 SSH 运行器共享经过校验的独立 Vault。绑定 `before_deploy` 的任务在首次远端调用前认证存档，在备份／恢复服务前再查一次；目标节点版本、元数据及完整配置摘要须与计划一致。只存在密文或引用不代表资料可恢复。失败使用固定的 `backup-failed`，不输出正文、路径或底层错误。准备期失败释放本任务引用，已经进入恢复保护则继续保留回退引用。旧无绑定任务不伪造存档，公开部署仍关闭。详见 [任务引用与恢复保护](V3-CONFIGURATION-BACKUPS.md#部署前自动备份与任务引用)。
