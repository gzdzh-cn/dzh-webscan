# v3 服务器告警接入状态

本模块已接通本地 v3 主动采集和 PostgreSQL 通知出箱，仍属于开发验证代码。完整 v3 未完成，不能据此切换生产。已发布的 v2 后台及其 SQLite 告警继续沿用原流程。

## 当前流程

```text
采集租约及节点版本校验
→ 保存指标游标、节点状态
→ 串行判断本节点告警
→ 同一事务保存规则状态、历史、待通知记录
→ notifier 持久租约分组
→ 同一事务写入飞书／邮箱独立队列
→ 各通道按既有重试、限流与顺序规则投递
```

- 与 v2 共用持续时间、恢复迟滞、提醒及磁盘／inode 严重级别抑制规则。CPU／内存阈值告警默认关闭。
- 使用 PostgreSQL 时钟记录观察时间和分组等待，计算告警持续时间；旧指标补采仅保存历史。最新样本超过 `max(60, 3 × interval_seconds)` 秒时不参加实时告警。连续空响应且指标过期会记录采集失败。
- 首样本、重启、计数重置和缺失数据保持未知。CPU 五分钟平均值至少需要 240 秒连续有效数据；间隔超过两倍采样周期或存在缺失样本时，平均值未知。PostgreSQL 仅缓存该计算所需的最近五分钟 CPU 样本，不复制完整指标历史。
- 重复、较旧观察不会多算恢复次数；过期采集租约及旧节点配置不能写入。
- 维护时清除待触发累计和恢复样本数，保留触发中的异常与历史。维护来源包括显式节点名单，以及持有效租约、已进入需恢复阶段的部署任务；任务失败或结束后恢复判断。
- 停用节点不发送虚假恢复。尚未转入通道队列的通知取消，已入队通知及原历史保留。
- 分组等待默认 30 秒（至少 15 秒），同节点及阶段的分组间隔默认 300 秒。按 15 秒时间桶分组：最多五项分别通知，更多项目汇总前五项及总数。
- 不可达告警抑制该节点其他告警的入队，恢复后继续处理。抑制条件在批次限制前过滤，避免积压堵住其他节点。
- 每轮最多处理 500 条，事务中不访问业务通知网络。稳定批次 ID、出箱完成状态和两通道入队原子提交。

## 设置与接口

策略目前由 PostgreSQL `v3_settings.payload.monitoring` 读取，使用既有健康规则字段：`alerts`、`interval_seconds`、`repeat_hours`、`group_wait_seconds`、`group_interval_seconds`、`maintenance_nodes`、`notifications_paused`、溢出及丢弃告警开关。飞书与邮箱仍使用顶层通道设置。实时判断自动使用采集器实际周期，避免长周期采集反复重置持续时间；兼容策略中保留 `interval_seconds` 字段。

当前尚未提供网页策略编辑或旧 YAML 自动导入，不能把这些开发配置当作正式部署步骤。

| 接口 | 用途 |
|---|---|
| `GET /api/v3/alerts/current` | 只列出启用节点的触发中异常，按规则标识分页 |
| `GET /api/v3/alerts/history` | 时间、节点、告警阶段筛选，按时间及 ID 倒序分页 |
| `GET /api/v3/dashboard` | 已有缓存总览增加 `current_alerts` 与 `pending_alerts` |

两类告警接口要求登录，每页 1～200 条；历史默认最近 24 小时、最多 31 天，时间参数为 RFC3339，记录时间为 Unix 秒。接口及 TypeScript 数据模型见 `api/control/v3/openapi.yaml` 和 `web/src/controlV3.ts`。

历史返回稳定 `record_key` 和保护原因。自动期限清理已接入，见 [历史保留](V3-RETENTION.md)；手动清理仍未接通，`can_delete` 始终为 false，不提供绕过保护的删除入口。当前异常不能直接删除。

## 数据与迁移边界

告警模块在 schema 5 引入观察游标、短期 CPU 样本、规则、历史、批次和出箱；schema **6** 增加历史身份和迁移保护，schema **7** 补齐文件事件迁移，schema **8** 补齐网站通知出箱，schema **9** 增加自动历史清理，当前 schema **10** 增加网站配置备份。已有 schema 1～9 必须先完成受校验的一致性备份再升级；备份失败则事务不修改表和版本。备份／空库恢复包含上述表及其依赖。

旧 SQLite 健康状态、告警历史、已有批次和通知依赖已补齐冻结映射，保留原 ID、重试和入队进度，见 [历史迁移](V3-HISTORY-MIGRATION.md)。网页告警页面切换、策略编辑、历史清理、最终增量切换与回退仍未完成。迁移准备状态仍不可用于生产切换。不可简单重建旧告警通知，否则可能重复投递。

## 本地验证

隔离 PostgreSQL 验证持续时间、恢复、未知、维护、停用、并发去重、CPU 窗口、旧指标回放、事务中断、分组、抑制队列、租约、双通道失败隔离、登录、分页、保护原因，以及 schema 4→5 与备份恢复。发送器使用替身，未连接业务飞书或真实邮箱。完整验证记录见 [V3-VALIDATION.md](V3-VALIDATION.md)。
