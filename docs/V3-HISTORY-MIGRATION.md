# v3 告警和通知队列迁移

当前仅用于本地隔离验证，完整 v3 尚未交付，不能据此切换生产。已发布版本仍为 v2.0.46。本页不提供释放迁移保护或启用业务通知的命令。

## 已完成的映射

| 旧数据 | PostgreSQL 中保留的内容 |
|---|---|
| 服务器健康规则 | 规则键、节点、阶段、持续及恢复计数、提醒时间 |
| 服务器告警历史 | 原事件 ID、节点、类型、阶段、时间、消息及状态 |
| 告警出箱和批次 | 原批次 ID、原成员集合、入队完成状态 |
| 飞书任务 | 原节点和事件身份、创建时间、重试次数、下一次尝试及完成状态 |
| 邮件任务 | 原收件人逐个保留尝试次数、等待时间和完成状态 |
| 投递尝试及限流窗口 | 关联尝试、成功状态、通道限流时间；原始响应保存在受控归档 |

迁移邮件保留旧 `任务编号:收件人` 对应的 Message-ID 种子，避免仅因 PostgreSQL 自增 ID 改变就更换邮件身份。旧租约不转移所有者，下一次尝试时间不得早于旧租约到期时间。邮件和飞书继续独立投递。

已移除节点只建立历史身份，不伪造启用配置或采集地址。其尚未确认入队的历史保留待核对，不自动通知。原规则列为“已停用”、旧载荷仍为“触发中”时，以列中的阶段为准。

## 隔离环境使用

先分别对同次冻结的两个旧 SQLite 文件执行 `archive-v2`，完成一致性快照和无损暂存。只对独立测试库操作，记录两份报告中的 `source` SHA256：

```bash
# 旧中心 events-v1.sqlite3 快照：通知、邮件收件人和投递历史。
.cache/webscan-v3 control-v3 --config /绝对路径/隔离配置.yaml \
  --action map-notifications-v2 --source <通知快照SHA256>

# 旧 metrics-v1.sqlite3 快照：规则、告警历史、批次及成员。
.cache/webscan-v3 control-v3 --config /绝对路径/隔离配置.yaml \
  --action map-health-v2 --source <指标快照SHA256> \
  --notifications-source <通知快照SHA256>
```

两个映射可按任意顺序执行；服务器告警映射要求配套通知快照已经完整归档。首次绑定要求对应目标领域为空，拒绝覆盖运行中的告警或通知。绑定后只能使用原 SHA256 续作，不混合其他来源。

每批最多处理 500 条源记录且归档载荷不超过 8 MiB，摘要校验、业务写入和检查点在同一事务提交。失败报告保留已提交进度，同一命令重试不会重复写入。`processed` 和 `imported` 统计源记录，不等于目标行数：一个旧邮件任务可能生成多个收件人队列行。

以下情况停止映射并保留原始归档：待发送邮件缺少原收件人、批次成员缺少关联、阶段或节点不一致、损坏载荷、摘要变化、未完成归档，以及尚未支持的待发送目标。已完成的旧 Loki 任务、已无父任务的投递尝试继续保存在无损归档中，不伪造待发送业务行。

## 避免重复发送

旧告警和通知位于两个 SQLite 文件。通知可能已经入队，但告警库因响应丢失仍显示“未入队”。两份映射完成后按原 `native:<批次ID>` 核对原任务：

- 已存在原通知任务时，确认该批次已经入队，保留原通道、收件人和完成进度，不按当前设置扩展。
- 已完成批次不重新通知，即使旧通知历史已按期限清理。
- 原批次尚未入队且没有原任务时，保留原批次和成员，供后续正式切换后按同一身份入队。

关联核对以最多 500 个成员的短事务推进，批次与其全部成员原子更新。中断后继续核对，已完成部分不重复处理。尚未入队的原批次不会与新事件重新分组；停用、维护和不可达抑制继续生效。

## 迁移保护与备份

映射完成只表示当前领域已映射，报告的 `ready_for_cutover` 始终为 `false`。持久迁移保护阻止实时告警变更、通知领取、业务入队、新事件确认和节点配置写入。新事件仍由子控缓存。重启或数据库备份恢复不会解除这些保护。

当前业务 schema 为 **10**；schema 6 新增历史节点身份、迁移绑定及通知来源字段，schema 7 补齐文件事件摘要和迁移展示，schema 8 补齐网站通知出箱，schema 9 增加受保护的自动历史清理，schema 10 增加网站配置备份。已有 schema 1～9 必须通过 `migrate-db --output <私有目录>` 先完成校验过的一致性备份；失败停止，不执行在线 VACUUM。恢复只允许空应用库，并保留节点身份、批次、原任务及待切换状态。

数据库及原始归档包含私密信息，沿用私有目录和文件权限。迁移错误不返回 PostgreSQL 可能含原载荷的 DETAIL；公开记录不展示旧通知的原始错误响应。

完整配置和任务迁移、最终增量、旧写入冻结、凭据交接及保留新增数据的回退尚未完成，因此没有正式激活命令。网站的待发送出箱及合并策略现已接入，见 [网站迁移](V3-WEBSITE-MIGRATION.md)；看门狗调度交接仍需补齐。
