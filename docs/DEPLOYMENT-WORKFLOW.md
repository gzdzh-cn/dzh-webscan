# 配置与部署流程（v2.0.44）

[返回 README](../README.md) · [后台指南](CONSOLE.md) · [日常维护](OPERATIONS.md)

## 服务器状态

采集状态表示最近指标是否正常；部署状态表示安装、验收或回退进度；配置状态比较已保存配置与实际应用基准。三者独立：已保存不等于已部署，采集正常也不代表所有新配置已生效。

尚未部署或回退后的 YAML 节点继续显示，不需要重新添加。服务器管理、节点编辑和系统设置显示未完成任务入口。命令行中断任务提供当前任务恢复入口；操作前读取实际状态，不以最新历史记录推测。

## 添加、检查与保存

表单分为基本信息、连接认证、部署方式和文件监控。默认“使用公共配置”，只读展示目录、后缀和忽略规则；首次切换独立配置复制公共值。同一次编辑切回公共再切回独立保留草稿。列表整体替换，高级规则保留原有继承方式。

“连接与环境检查”通过主服务器使用当前表单连接目标，检查 root SSH、Linux amd64、磁盘、监控目录及 systemd / Docker 环境。最多 60 秒，不修改 YAML、不持久化上传私钥、不安装软件、不启动服务。首次连接展示主机指纹，正式部署才记录；已有指纹不符拒绝连接。没有安装 Agent 时，指标端口显示待部署验收。

“校验并预览”仅检查格式和影响范围，不连接目标。“仅保存”写入 YAML，“保存并部署”启动持久化任务。已有凭据留空保留。修改表单使预览和检查结果失效。

## 独立升级子服务器

已安装、启用的子服务器在编辑弹窗中提供“升级子服务器”。点击后核对当前版本、部署方式、目标版本及镜像摘要，再点击“确认升级（不保存草稿）”。此操作读取磁盘已保存配置，弹窗中的私钥、目录、模式等草稿都不会保存。预览列出此节点已保存的待应用差异；旧记录缺少可信基线时明确显示无法确认。

目标 Agent 默认使用宿主管理程序对应的明确版本并锁定摘要。显式镜像仍需与管理程序版本兼容。已确认降级被拒绝；同版本、同摘要且配置已应用时提示无需升级。Docker 和 native 均支持；若已保存部署方式与实际方式不同，应改用“保存并部署”。预览 10 分钟后、配置或部署记录变化后需重新生成。未完成任务通过原任务入口继续或回退。

命令行 `webscan --upgrade --node 节点ID` 同样使用指定子服务器范围；继续／回退保留原范围及已锁定摘要。

## 中心免重建范围

首次安装本版本需要升级中心。之后普通子服务器添加、更新仅热加载目标节点登记、来源限制、采集目标和维护状态，保留中心容器、进程、启动时间及登录。只有中心版本、监听、协议或挂载等变化才按需重建中心。

内部接口使用现有管理令牌，公网事件入口及子服务器令牌不可调用。加载前比较运行配置版本，拒绝夹带其他节点或中心变更；磁盘写入不等于登记成功，必须取得中心版本确认。中心暂不可用限时重试；不支持此能力时在切换节点服务前要求先升级中心，不暗中重建。失败恢复同样使用受限热加载，保留已有事件和数据库。

## 登录与网络中断

登录绝对有效期仍为 12 小时，重启不续期；最多保留 100 个有效会话。会话只持久化令牌摘要，不保存原令牌或密码。主动退出撤销当前会话，改密或管理员终端重置撤销全部会话。v2.0.43 的内存会话无法迁移，第一次升级可能需要重新登录一次。

短暂断网、502／503／504 时保留页面和已显示结果，前台每 3 秒重连；后台暂停，返回后继续。部署日志沿游标读取，不重复提交写请求。只有明确的登录鉴权失败才跳登录；数据库错误显示服务异常。

添加／编辑弹窗的正文可滚动，标题及底部操作始终可见；手机窄屏表单单列、按钮自动换行。

## 部署与恢复

任务详情先展示范围、结果和失败阶段，再展示实际阶段与日志。关闭页面不停止任务。旧任务没有结构化阶段时只展示原始日志，不推测进度。

继续与回退只允许当前未完成任务，恢复预览绑定账号、配置及部署状态，有效 10 分钟。执行前重新验证，保留原节点、仅中心或全量范围。后续任务接管后旧任务不再提供恢复按钮。卸载移除、架构迁移继续沿用专用恢复流程。

节点已通过检测、扫描、投递和健康验收后，维护状态收尾若暂时失败，将保留当前服务及检查点，按原范围继续任务。中心繁忙或短暂不可用自动限时重试；认证和配置拒绝直接提示。

日志可搜索、仅看错误、关闭自动滚动，并下载完整脱敏日志。页面保留最近 1000 条，完整记录以下载为准。删除保护不变。

## 配置生效与构建版本

系统设置显示磁盘配置相对应用基准的差异、影响节点和重建要求。注释及节点排序不构成应用差异；私密字段只比较内部 HMAC 摘要，绝不返回摘要或明文。

旧版本没有凭据摘要时显示“待核对”；成功应用后按实际范围建立基准。只升级中心不将其他节点标成已应用。调试和生产检查中看到未知状态时，不代表采集故障。

运行版本区显示中心和宿主管理程序的版本、源码提交、构建时间及源码快照摘要。`-dirty` 表示构建包含未提交源码；本轮 Git 由维护者手动提交。程序文件被单独挂载时标明临时替换，正式升级后使用镜像内程序。

## 发布和升级

本轮升级命令为 `webscan --upgrade --central-only`。升级前备份配置、部署状态和一致性数据库，保留回退资料。已有子服务器无需升级，公共规则若有独立待应用修改需另行预览应用。

镜像构建清单位于版本产物的 `build-info.json`，记录精确源码快照摘要。只有源码提交确定后才能生成对应 GitHub Release 标签和源码安装清单，不将旧提交伪装为新版本源码。

默认 Agent 镜像填写 `latest` 时，部署会使用与当前部署工具相同的明确版本标签下载，随后锁定摘要，避免镜像加速站的旧缓存造成工具包版本不一致。显式版本和摘要保留原设置。
