# v3 子控与采集器证书工具

v3.0.3 已正式发布，独立维护升级、续期、过期身份固定 SSH 恢复、名称维护／裁剪及一次管理员换根已通过真实 native／Docker 29 联合验收，结果与限制见 [发布回执](RELEASE-v3.0.3-RECEIPT.md)。本文按实现顺序保留过程说明；早期“未完成”“待验收”“尚未发布”等状态以最终回执为准，不代表当前阶段仍未完成。现有 v2 节点不会自动更换证书；本次没有升级生产或修改其信任。

## 身份和信任

- 一个私有 Ed25519 CA；子控使用 `spiffe://webscan/node/<节点ID>`，采集器使用 `spiffe://webscan/collector/<实例ID>`。
- 子控证书仅具有 ServerAuth 用途，采集器证书仅具有 ClientAuth 用途；不能互换。子控证书具有明确的 DNS／IP SAN，保留正常主机名验证。
- 证书序列号随机生成；叶证书默认 30 天，可配置 1～2160 小时。CA 默认 5 年；叶证书不能超过 CA 有效期。
- 私钥不进入 JSON 输出。CA 私钥不会附在节点／采集器证书包中，在线校验不读取 CA 私钥。

## 离线命令

以下是低层离线操作，正常受管理安装应使用宿主维护任务。父目录要求 0700，属于运行账号，使用绝对规范路径；拒绝符号链接、组／其他用户可写路径和已有输出目录。

```bash
# 本地开发工具；不代替正式签名产物。
go build -o .cache/webscan-v3 ./cmd/webscan

# 管理员先准备一个私有父目录，再显式创建新 CA。
mkdir -m 700 /绝对路径/隔离证书目录
.cache/webscan-v3 pki-v3 --action init \
  --authority /绝对路径/隔离证书目录/authority

# 子控证书：ID 必须与登记 ID 相同，names 为实际地址或 DNS 名称。
.cache/webscan-v3 pki-v3 --action issue \
  --authority /绝对路径/隔离证书目录/authority \
  --role node --id node-a --names node-a.example.test,192.0.2.10 \
  --output /绝对路径/隔离证书目录/node-a

# 每个采集实例使用自己的身份。
.cache/webscan-v3 pki-v3 --action issue \
  --authority /绝对路径/隔离证书目录/authority \
  --role collector --id collector-a \
  --output /绝对路径/隔离证书目录/collector-a

# 吊销明确的叶证书；保留以前的全部吊销记录。
.cache/webscan-v3 pki-v3 --action revoke \
  --authority /绝对路径/隔离证书目录/authority \
  --certificate /绝对路径/隔离证书目录/node-a/identity.crt

# 吊销列表默认有效 24 小时；离线工具续发，不自动连接任何节点。
.cache/webscan-v3 pki-v3 --action renew-crl \
  --authority /绝对路径/隔离证书目录/authority
```

CA 目录包含 `ca.crt`、`ca.key`、`ca.crl`、`crls/<递增版本>.pem`。证书包仅包含 `ca.crt`、`ca.crl`、`identity.crt`、`identity.key`。目录 0700、文件 0600，写入后同步磁盘。证书包不覆盖已有目录；重新签发产生新序列号，旧证书须单独吊销。

CA 操作使用文件锁串行执行。更新吊销列表先持久化不可变历史，再原子替换 `ca.crl`；中断后下一次操作选取已保存的最高版本并修复活动副本。并发吊销不会互相覆盖；损坏或不明的较新版本停止处理，不跳过它继续签发。错误不包含私钥内容。

## 受管理节点签发与共享登记

本地签发默认关闭。管理员预先创建 CA、配置匹配的采集器证书及当前签名吊销列表后，才能显式开启：

```yaml
node_pki:
  enabled: true
  authority_directory: /etc/webscan-v3/authority
```

不会生成或替换现有 CA。仅受控签发进程需要访问 `ca.key`；API、在线采集器和子控执行证书校验不需要此私钥。CA 目录采用与离线工具相同的路径、所有权、权限和文件锁检查。受管理 CA 必须与 `collector.ca_file` 一致，发行时使用的当前吊销列表必须与采集器配置一致。

新增本地 `control-v3 --action issue-node-certificate`，要求已存在的管理员账号、有效的 `--request-key`、完整 `deployment_trust` 和私有 `--source` JSON：

```json
{"node":"node-a","expected_version":1,"lifetime_hours":720}
```

只为 PostgreSQL 中已保存且启用的节点签发其 ID 和 TLS 名称，不接受外部指定角色、SAN 或签名路径。默认 720 小时，允许 1～2160 小时；证书不超过 CA 有效期。重复请求复用相同记录；同一幂等键更换请求会拒绝。只返回记录 ID、节点、创建时配置版本、CA／证书摘要、序列号及到期时间，不返回证书私钥。

数据库 schema 12 增加 `v3_pki_authorities` 和 `v3_node_certificates`。签名叶证书的私钥使用独立 Vault 的 AES-GCM 加密，认证数据绑定记录 ID、节点、CA 和证书摘要，不能把密文移到其他身份复用。证书登记、请求回执和审计同事务提交；写入失败全部回滚，不创建部署任务或推进生效版本。CA 私钥不进入数据库、配置包或节点。

首次登记固定集群 CA；不同签发实例使用相同数据库下限核对当前签名吊销列表。独立机器上的文件锁不能相互协调，数据库行锁和唯一约束负责防止重复提交和另一实例降低版本。即使各自本地文件自洽，也拒绝回退编号、同编号不同内容、删除既有吊销及隐式更换 CA。根证书轮换需要后续专门迁移，不通过修改路径或重新启动自动接管。

准备部署可使用 `identity_id` 从加密登记读取叶证书，也保留原 `identity_directory` 离线方式，两者互斥。两者均不提供时，启用签发后可带稳定 `--request-key` 自动签发并准备配置包，重试复用同一证书及包。若签发已提交而后续规则／配置包准备失败，保留加密登记，修复后用相同键重试；准备成功也不会自动开始远程安装。详见 [节点配置包](V3-NODE-CONFIGURATION.md)。

已经排队的任务在每个远程阶段前重新核对当前采集器信任和共享下限；不能仅因旧包 SHA256 正确便继续使用过时吊销资料。更新吊销列表后，旧准备包需要重新准备。签发／准备仍不替代实际服务安装和采集验收。

PostgreSQL 一致性备份包含加密叶密钥和共享下限，恢复仍要求外部独立 Vault 密钥、受管理 CA 和配套公开信任文件。`RewrapNodeCertificate` 仅重包加密，不改变证书身份；处理现存记录后仍须保留能够解密旧备份的旧密钥。该方法不是证书续期或吊销。schema 11 及更早版本必须先完成一致性备份再迁移，备份失败不改 schema。

## 在线校验接入

主控验证入口增加可选配置：

```yaml
collector:
  ca_file: /绝对路径/已安装证书/ca.crt
  cert_file: /绝对路径/已安装证书/identity.crt
  key_file: /绝对路径/已安装证书/identity.key
  revocation_file: /绝对路径/已安装证书/ca.crl
  revocation_state_directory: /绝对路径/服务数据/collector-trust
```

子控 pull 验证配置：

```yaml
pull:
  enabled: true
  collector_identities:
    - spiffe://webscan/collector/collector-a
  revocation_file: /绝对路径/已安装证书/ca.crl
  revocation_state_directory: /绝对路径/服务数据/pki-trust
```

子控继续使用 `metrics.ca_file`、`metrics.cert_file`、`metrics.key_file` 与 `metrics.tls_enabled: true`。文件须由服务运行账号持有，禁止符号链接、硬链接及组／其他用户可写权限。这里只展示新增字段，不能当作完整 Agent 配置。

启用后，每次 RPC 都校验证书有效期、用途、精确身份和吊销状态。子控拒绝被吊销采集器的现有 HTTP/2 连接；主控发送后续确认前及长轮询返回后再次校验，避免在证书失效后保存返回数据。子控旧 `/metrics` 路由也服从配置的证书策略。

签名吊销列表最多每秒重新读取一次，必须通过同目录临时文件和原子替换更新。文件丢失、损坏、过期、错误签名、版本倒退或删除已有吊销记录时拒绝请求。修复后按同样机制恢复；不能把失败当作未启用。

未填写 `revocation_file` 的原有验证配置保持原行为；正式 v3 安装器必须设置并分发该字段后，才能宣称已具备吊销管理。

## 跨重启的吊销版本保护

设置 `revocation_state_directory` 后，在线进程先持久化已接受的完整签名吊销列表，再允许连接继续。目录与文件为 0700／0600，固定 CA，文件锁串行更新，临时写入、fsync 后原子发布。服务数据父目录必须已存在、属于服务账号且为 0700。新生成的节点配置固定使用 `/var/lib/webscan-v1/pki-trust`，不跟随发布目录替换；主控采集器也可设置独立持久目录。

重新启动会比较已保存版本，拒绝旧版本、同版本不同内容、删除已有吊销记录或无明确迁移的 CA 替换。已保存列表过期后仍作为历史下限，允许合法续发，但当前用于连接的列表必须有效。多个本机进程共享目录时也不能互相降低版本。状态文件缺失、损坏、链接或权限不正确会停止校验，不能静默重建已有空目录。

该目录须跟随服务数据备份并在配置回退时保留；仅回放旧证书／配置不会重置它。删除整个服务数据目录或整盘回放不在本地文件下限的证明范围内，仍需主控发行记录与恢复检查。没有设置此字段的旧验证配置仅有进程内下限，不宣称已完成持久保护。

## 原子叶证书替换与运行中加载

可选的受管理身份文件将一张叶证书和对应 PKCS8 私钥保存于同一 PEM 文件，最多 128 KiB。`collector.identity_file` 用于主控；`metrics.identity_file` 用于启用 pull 和 TLS 的子控。设置后不能同时配置该组件的 `cert_file`、`key_file`；未设置时原分文件配置保持不变。既有 `format: 1` 节点包保持分文件配置，不会自动转换；新准备的 `format: 2` 节点包使用下述种子及活动身份目录。全新单中心安装的 `format: 2` 已使用受管理身份文件；旧 `format: 1` 安装保持原样。

```yaml
collector:
  ca_file: /受控私有目录/trust/ca.crt
  identity_file: /受控私有目录/collector/active.pem
  # 同时保留原有 revocation_file、revocation_state_directory、调度配置。
```

```yaml
metrics:
  tls_enabled: true
  ca_file: /受控私有目录/trust/ca.crt
  identity_file: /受控私有目录/node/active.pem
  # 这里仅展示新增字段，仍需端口及其余完整 Agent 配置。
```

这些目录必须已存在、属于运行账号且为 0700。文件为 0600，禁止符号链接和硬链接。Docker 使用只读**目录挂载**，在宿主机发布新文件；单文件 bind mount 会固定旧 inode，不能用于原子替换。挂载目录不得包含 CA 私钥，也不能因此扩大中心／子控容器的凭据访问范围。

显式激活已签名资料，不安装服务、不连接节点：

```bash
.cache/webscan-v3 pki-v3 --action publish-identity \
  --source /受控私有目录/已签发节点包 \
  --ca-file /受控私有目录/trust/ca.crt \
  --identity-file /受控私有目录/node/active.pem \
  --role node --id node-a
```

源目录包含 `ca.crt`、`identity.crt` 和 `identity.key`。CA 必须与明确指定的已安装根完全一致，角色、身份、用途、有效期和密钥必须匹配。首次发布不覆盖现有文件；后续发布须带 `--expected-certificate-sha256`，值为先前返回的公开证书摘要，并要求新到期时间更晚。相同候选文件的重试返回当前公开回执，不重复替换。

显式离线续期保存原身份及全部 DNS／IP SAN，生成新密钥：

```bash
.cache/webscan-v3 pki-v3 --action renew-identity \
  --authority /受控私有目录/authority \
  --ca-file /受控私有目录/trust/ca.crt \
  --identity-file /受控私有目录/node/active.pem \
  --role node --id node-a \
  --expected-certificate-sha256 上次返回的64位证书摘要 \
  --lifetime-hours 720
```

身份文件的父目录与 authority 目录必须分开。默认 720 小时，范围 1～2160 小时，不能超过 CA 到期时间。必须具有有效签名吊销列表；已吊销身份不能通过续期复活。过期叶证书仅允许该显式离线流程核对历史身份，在线加载仍拒绝。续期回执丢失后须先核对当前文件，不使用旧摘要强制重试或降级。

每次替换先将旧私钥和证书原子保存到 `active.pem.history/<旧证书摘要>.pem`，持久化成功后才原子替换活动文件；备份或校验失败不替换活动身份。这些私有历史需随配套资料备份，不能放入网页普通导出。成功响应仅含公开摘要、身份、序列号、到期时间及是否变化，不含私钥。

主控和子控在新握手时最多每秒重读一次受管理文件，固定启动时的 CA 和身份；损坏、丢失、过期及同进程内到期时间倒退会拒绝新握手，不静默回退旧密钥。该到期时间保护**不跨进程重启持久化**，不能代替签发记录与吊销版本下限。

已建立连接在未吊销且未过期期间继续工作。主控发现本机身份变化后，在下一轮 10 秒协调中取消并重建节点连接；远端旧叶证书吊销／过期后，取消该节点工作器，再由协调器重新连接。监听器及主控进程不重启。每次 RPC 在实际选中的连接上发送前校验身份，返回后再次校验实际 peer，防止新握手记录误授权旧连接的长轮询结果或确认。

## 子控活动身份与安装种子

新准备的节点私有配置包使用 `format: 2`；`format: 1` 仍可读取和按原字节生成运行配置。安装目录继续只读保存 `identity.crt`、`identity.key`，新运行配置设置 `metrics.identity_seed_directory` 指向该目录，`metrics.identity_file` 固定为 `/var/lib/webscan-v1/pki-identity/active.pem`。native 和 Docker 共用已有数据目录及权限，不新增可写挂载。

首次启动核对固定 CA、节点角色及 ID、密钥匹配与叶证书有效期，在私有临时目录写入公开根和单文件身份，fsync 后一次发布完整目录。目录 0700、文件 0600，不接受符号链接、硬链接或其他账号资料。该目录已存在时只检查 CA 固定值和活动身份，绝不重读旧种子私钥；种子过期或删除不影响已经续签的活动身份重启。活动文件或根固定值丢失、损坏、权限不符或换根均停止，不能拿种子自动修补。活动叶证书过期仍需专用 SSH 恢复，不能通过 CRL 更新绕过。

目标配置和程序更换时保留该目录及 `active.pem.history/`；一致性切换备份持有与原子激活相同的证书锁，再复制活动身份、固定根和私有历史并校验摘要，防止管理员手动换证穿插备份。新增快照字段 `identity_state` 可缺省以读取旧快照，单次上限 32 MiB／4096 个文件，超过时失败，不截断；空间检查将证书资料计入预算。恢复服务及配置时不拿旧快照覆盖当前证书状态，切换后续签的叶证书继续保留。完整目录丢失或整盘回放仍需外部发行记录和灾备资料核对。

活动身份承载、远端叶证书续期签发及交付已接通，公开队列与签发角色见后文；CA 换根仍未完成。改变节点 TLS 名称必须配套签发／激活覆盖新名称的受管理身份；仅更换安装种子不能替换已初始化的叶证书，该专用流程仍需与完整配置下发集成。回退到旧 `format: 1` 程序或配置不会自动改写为新身份路径，其旧叶证书若已失效，仍需专用恢复，不能把数据目录保留等同于完整跨架构证书回退验收。

## 主控主动下发完整吊销列表

新生成的节点运行配置启用 `pull.revocation_updates: true`，复用 19100 上的 mTLS／HTTP2 连接及原允许身份名单，不增加端口。主控在协商节点能力前尝试发送当前 CRL，此后随指标采集周期检查变化；每个主控共享一秒缓存，不为每台节点重复读取和验签源文件。按节点记住已确认摘要，不反复上传相同正文。回执严格匹配节点、原始签名列表摘要、编号及到期时间；响应丢失重试不会降低状态。

子控只接受原固定 CA 签名的完整列表，既有吊销不能消失，编号和时间不能倒退。更新者仍须为允许名单内、当前有效的 Collector 身份，并在拟提交的新列表下未被吊销；不能通过重放旧列表绕过持久下限。更新串行执行，最多等待五秒，不接收文件路径、命令、CA 或私钥。正文限制为现有 2 MiB RPC 包络减 4096 字节；超限明确失败，不截断列表。

种子 `pull.revocation_file` 保持安装时的不可变资料；活动列表和持久下限统一使用 `pull.revocation_state_directory/ca.crl`。首次初始化必须有有效种子，之后重启读取已接收的列表，不使用旧种子覆盖。已初始化目录内的资料丢失、损坏、权限异常或链接均拒绝；删除或整盘回放全部本地信任资料仍不在此证明范围内，须保留一致性备份和主控发行记录。

持久列表过期时可以启动监听器，但普通采集、确认与旧 `/metrics` 仍关闭。只允许受限更新方法使用新签名列表与旧持久下限验证调用者，提交成功后恢复正常策略；叶证书本身过期或 CA 改变时不能借此恢复，仍需专用 SSH 流程。普通 RPC 返回前重新校验，避免已进入长轮询的旧身份在吊销后收到事件。

只有明确返回 `Unimplemented` 才作为旧能力兼容，主控不会把失败记成已确认分发。旧节点仍需升级配置和程序；已有配置不被自动改写。此能力仅分发公开 CRL，不分发节点私钥或续签叶证书。

## 子控本机生成续期请求

续期内核由 `PrepareNodeRenewal`、`SignNodeRenewalRegistered` 和 `ActivateNodeRenewal` 组成。可选 RPC、PostgreSQL 公共任务、独立宿主签发与采集器交付已经接通；安装方式及验证边界见本页后续说明，仍不是完整 v3 正式交付。

子控为当前活动证书生成新的 Ed25519 私钥和标准 PKCS#10 请求，私钥只写入 `/var/lib/webscan-v1/pki-identity/renewals/<原叶证书摘要>/key.pem`；公开 `request.json` 包含原叶证书、新 CSR、固定 CA 与原证书摘要，并由原活动私钥对带专用域标识的完整请求再次签名。因此仅知道其他节点的公开证书不能伪造换证请求。相同原证书的并发、断线或重启重试均复用同一已持久化请求和私钥，不覆盖损坏或缺失的待签资料。目录 0700、文件 0600，临时目录完整落盘后才发布。

签发器要求原身份仍有效且未吊销，校验新旧密钥各自的持有证明，固定节点角色、ID、CA、所有 DNS／IP SAN；拒绝复用原公钥、申请额外名称／权限或扩展、错误签名及回退有效期。请求上限 64 KiB，CSR 和单张证书各 16 KiB。返回材料只有根与公开新证书，绝不返回节点私钥；调用方必须在受控登记事务里保存相同请求的发行回执后再投递，签发函数本身不代替该持久幂等登记。

激活核对请求摘要、受控目录中已保存的本机私钥、新公钥和原节点名称，并要求调用方使用当前持久 CRL 下限验证新证书。成功后复用原子身份发布和私有历史，响应丢失重试返回相同公开结果，不重启监听器。待签私钥保留在私有目录以便核对和一致性备份，不能导入普通网页导出；后续清理须另行受保护处理。任务租约、公共签发登记与自动分发已连接；过期节点 SSH 恢复、名称变化下的新证书转换及完整安装仍待完成。

离线叶证书续期、原子激活、运行中加载、CRL 主动分发、逐节点公开续期队列和单中心宿主定时签发已接通，详见 [单中心证书维护](V3-SINGLE-INSTALL.md#本机证书维护)。SSH 过期恢复、名称变更／裁剪和 CA 管理员持久任务分别见后文；公开网页不提供换根入口。v3.0.3 的完整安装、真实宿主与 Docker 29 联合验收仍须独立通过，不能以原语测试替代。真实三机高可用及完整灾备切换属于后续阶段。

完整部署验收仍需验证新旧证书交叠分发、失败恢复、节点离线和时钟异常；当前真实连接测试使用隔离证书和本地 HTTP/2 服务，未接触生产节点。
## 子控续期的 PostgreSQL 签发回执（schema 30）

内部宿主签发操作将公开 CSR 绑定当前运行快照、递增代次和节点专用持久租约。来源证书必须来自本节点已登记的初始证书，或已提交的本机私钥续期链；不会用保存但尚未应用的节点名称、地址或启用状态替换运行依据。未完成部署、运行代次不一致、缺少身份登记、已吊销或过期原证书均停止。

`v3_node_certificate_renewals` 只保存公开签发证书、摘要、运行快照和时间，不包含子控新私钥，也不伪造中心可解密的私钥记录。每个原证书仅允许一个后继；相同 CSR、快照、代次与有效期的重试读取原回执，不重复签名。不同 CSR 或参数冲突必须重新核对，不能覆盖。重新读取回执也校验当前完整签名 CRL 及 PostgreSQL 共享版本下限，不能用旧主控磁盘状态绕过其他实例已经观察到的吊销。

签发、共享吊销下限和审计在同一事务提交；租约在结束时再次检查，提交失败不返回证书。数据库回执时间统一 UTC。初次签发和续期保持相同文件锁／数据库锁顺序。迁移要求一致性备份，备份／恢复包含新账本及依赖快照。

这是宿主签发器内部接口，不开放 CA 签名的 HTTP／gRPC API。单中心维护命令已调用队列签发，采集器负责公开请求与叶证书交付；普通交付仍要求原证书有效，长期离线后的 SSH 恢复另行完成。主控采集进程不因此得到 CA 私钥或 Vault 密钥。


## 子控续期 RPC

可选 `PrepareIdentityRenewal`／`ActivateIdentityRenewal` 复用现有 mTLS／HTTP2 连接，不新增端口。新 format 2 配置默认启用，要求节点数据目录的活动身份和持久吊销状态；旧 split-key 配置保持不启用。`Capabilities` 返回当前磁盘身份的摘要和真实到期时间，状态不可读或被吊销时返回失败。

准备请求绑定原证书，子控原子保留新私钥及 CSR，网络只返回规范的公开 JSON。规范解码拒绝重复／未知字段、超限和非规范文本。激活绑定节点、原叶证书及请求摘要，只接受匹配本地私钥且通过当前 CRL 的 CA 签名叶证书。两方法限制 5 秒；无允许身份、缺少普通吊销策略、已吊销现有连接、错误节点、摘要或证书均拒绝。不接受角色、SAN、路径、配置和命令。

真实 Agent 可在原监听器应用新叶证书，重启后保持新身份，未确认事件可继续读取与确认。主控自动队列、单中心宿主签发调度与公开证书交付已接通，下面说明其事务边界；长期离线的过期恢复、换根及完整宿主安装仍待完成。


## 公共续期队列与自动交付（schema 31）

新格式节点在证书剩余不超过七天时，由正常采集周期准备本机 CSR。采集器校验原私钥持有证明、公开信任、登记来源和当前运行快照，将规范公开请求写入 `v3_node_renewal_jobs`；不需要 CA 私钥或 Vault。维护中的节点暂停续期，不把预期暂停写成协议故障，也不阻断部署验收；丢失分片租约的采集器不能准备新请求或提交队列。

全新 format 2 单中心的宿主 PKI 定时命令，在数据库初始化检查点之后读取任务，每次最多 500 条、预算 45 秒，按节点专用持久租约签发 30 天叶证书。数据库 schema 必须已正确迁移，定时器不执行自动迁移。本机信任维护与依赖数据库的节点签发分别报告状态；数据库暂不可用或节点签发失败保留队列，不形成中心开机对数据库的循环依赖。单条失败持久化脱敏原因及 60 秒至一小时退避，不阻塞同批其他节点；相同节点的并发和接管仍由唯一签发账本去重。预算和批量是实现上限，不代表已通过万台容量测试。

后续采集周期只交付已提交的公开证书，并再次核对当前节点、运行快照、请求和共享 CRL。配置更新后可以在新运行代次下重新绑定同一待签请求，读取原签发回执；原发行记录的快照与代次不被改写，不重复签名。主机名不再被原证书覆盖时拒绝复用，要求专用身份转换。

激活后以数据库事务记下确认和一次审计。响应丢失时，下次经过认证的能力读取按实际活动证书补记确认。采集器结束旧连接，新握手确认新叶证书；原监听器和中心进程不因该流程重启。旧叶证书仍遵守原到期及显式吊销策略，不通过自动续期复活已吊销身份。

任务和回执都只含公开材料，备份与恢复包含队列、快照和签发依赖；子控私钥仍需要单独的一致性私有数据备份。尚未完成过期 SSH 恢复、CA 换根、真实 systemd 定时重启演练、全套联合安装及 HA 维护角色安装，不能据此发布完整 v3。


## 初始种子过期后的升级

已存在公开续期签发回执的子控使用不含叶私钥的 format 3 升级包。初次 format 2 安装与未启用本地续期的旧 format 1 保持兼容。主控只校验当前有效的公开继任回执和历史部署绑定；旧种子私钥不参与升级，不因其过期或吊销另发一套私钥覆盖活动身份。

节点对当前磁盘身份执行完整校验，并在停止旧服务前再次检查。若原 format 2 任务中的种子及静态 CRL 已过期，可在已有有效活动身份和最新持久 CRL 的前提下继续同一不可变任务；不改写原任务摘要、原配置文件或本地吊销下限。历史读取仅用于既有任务及节点本机恢复，不用于在线 TLS 或新装授权。活动身份本身已过期、吊销、损坏或被删除时仍拒绝，需要尚待集成的专用 SSH 恢复。

详细格式和校验边界见 [节点运行配置](V3-NODE-CONFIGURATION.md#已续期子控的升级与旧任务继续)。本轮不增加数据库 schema，不改变旧事件／指标消息或端口。

## 既有部署任务的主控侧继续校验

主控执行器已对接任务上下文校验。既有任务的不可变 format 2／3 资料过期时，先检查租约、节点版本、原文件字节及摘要，再核对当前公开继任证书、Collector 身份和 SQL 吊销下限；全部通过才连接已固定指纹的 SSH。新安装和新预览仍使用严格校验，不能用历史资料申请新授权。远端还需独立验证实际私钥与持久 CRL，公开签发回执不能替代节点就绪证明。

## 过期活动身份的 SSH 恢复内核

`nodepki` 新增独立的限时恢复凭据与请求。凭据绑定节点、原证书摘要、CA 摘要、随机挑战及十分钟期限；过期私钥对完整恢复请求作独立域签名，CSR 的新私钥只保存在子控私有目录。已有待续期 CSR 可以复用，重试不重新生成密钥。

恢复签发只允许已过期、历史证书链及持有证明有效、最新 CRL 未吊销的原身份。签发器在自己的锁内重查最新 CRL，回调持久化失败不返回可交付的签发结果。普通在线续期、TLS 和 RPC 没有接受过期身份的选项。恢复原语也不允许改变 SAN、用途、节点或 CA。

私有信任目录必须已存在且保持原 CA 固定值。SSH 恢复仅能提交完整有效、单调递增且保留所有历史吊销项的 CRL；缺失、损坏、链接、不安全权限及低版本均拒绝，不以重新初始化掩盖状态丢失。激活前再次核对限时凭据及最新 CRL 中原证书和新证书的吊销状态，持有信任目录锁直到本机 CSR 原子激活完成。旧私有身份保留，丢失响应可重试；恢复后再次走普通续期。

恢复只提供主控宿主机 root CLI，不开放浏览器恢复 API。下节接通主控持久任务、固定指纹 SSH、固定路径工具、签发去重及受控启动；执行器与本机资源／mTLS 健康确认现已连接，完整主子控联合验收仍需完成。普通网络续期不能调用这一离线恢复能力。


## 过期身份的主控恢复任务与 SSH 工具（schema 32）

管理员的显式恢复意图先持久化，再允许连接节点；绑定账号及权限版本、节点版本／配置摘要、实际运行快照及代次、原 CA／证书、有效十分钟的挑战，以及已验证指纹的加密 SSH 凭据引用。每步复核，凭据密文重包不影响语义绑定，凭据实际改变、账号失权、节点变化、迁移冻结、租约丢失或任务到期均拒绝。同节点的编辑、部署、配置恢复和普通续期不能与活跃恢复交错；其他节点可继续管理。

恢复与普通续期共用节点签发租约和 `v3_node_certificate_renewals` 账本，每个原证书只产生一个后继。公开请求、签发、吊销下限和审计通过事务提交；提交失败不交付证书。新的独立授权恢复任务可在当前运行绑定下核对并取回同一本机 CSR 的原签发证书，保留原发行快照与审计；不能更换 CSR、有效期、节点、CA 或 SAN。取消只停止后续步骤，保留已签证书和节点数据。schema 31→32 及恢复均要求已有一致性备份。

宿主内部 SSH 适配器校验可信发布清单指定的工具摘要和字节数，经固定 root 主机指纹连接，将工具存入内容寻址私有目录；执行前再次验证远端文件。固定 `node-v3 --identity-recovery` 只接受限长 JSON，没有路径、服务名、可执行文件或任意命令字段。普通 `--lifecycle` 与身份恢复不能同时指定。工具复用节点部署／服务互斥锁；缺少已结束安装记录、有未完成部署或回退、活动指针与生成配置不一致时停止。

`prepare` 仅从固定私有身份目录产生公开 CSR 和原密钥证明；`activate` 只启用匹配本机待用私钥的公开证书。两步都拒绝缺失目录、错误权限、链接、过期授权、CRL 回退或吊销，不使用旧配置包里的种子私钥恢复。原身份历史保留，丢失响应可重试。`start` 要求签发证书已经是本机活动身份，不能借启动步骤激活候选或使用旧种子；再次校验原挑战、CSR、私钥、CA 和当前吊销状态。保持信任和身份锁直到本机服务操作结束。

启动前核对已完成安装、不可变程序／工具清单、实际 unit／容器、生成配置及保留旧组件。native 只启动原 `webscan-agent-native.service`；Docker 只启动已核实的不可变容器 ID，不运行 Compose 重建。已运行的服务不重复启动，已禁用服务或关闭重启策略的容器拒绝自动开启。启动后重查归属、配置和运行状态；失败或 SSH 响应丢失可重新检查同一对象，不停止／重启其他服务，不修改 YAML、监听端口或业务目录。

宿主完成确认须重新连接已保存的实际采集地址，通过正常证书与主机名验证、当前 CRL 和精确签发摘要检查，并以真实 gRPC mTLS 对端确认配置版本及活动证书。节点返回的激活 JSON 本身不能把任务标为完成。SSH 适配器和宿主执行器已连接固定启动及资源核验步骤；不能将分层测试当作完整 SSH／systemd／Docker 恢复验收。


可复跑的分层验证入口：`bash scripts/verify-v3-identity-recovery.sh`。需先准备 `scripts/Dockerfile.v3-scanner-validator` 对应的本地 Linux 扫描测试镜像；脚本固定使用已解析的镜像 ID，自动建立独立内部网络、内存 PostgreSQL 和禁网 Agent／PKI 测试容器，并按归属清理。结果写入 `.cache/verification/v3/identity-recovery.*`；不会读取实际 YAML、连接生产 SSH 或业务通知。此脚本不替代真实宿主服务恢复、容量与 HA 验收。

受控启动的真实内核验收入口：`bash scripts/verify-v3-kernel-lifecycle.sh recovery`（native）及 `bash scripts/verify-v3-kernel-lifecycle.sh docker-recovery`（Docker）。两者使用无外部网络的独立 x86_64 内核及真实 systemd，Docker 使用虚拟机内专用引擎。恢复签发由隔离夹具调用，尚不等同于公开恢复工作器与 SSH 的完整联合验收；本轮结果见 [验证记录](V3-VALIDATION.md)。

## 换证后中断的新授权续作

原十分钟授权到期后不再允许启动或确认，`prepare` 也继续要求活动原证书，不能把新证书当作过期原身份。管理员重新授权后，主控 SSH 适配器发现已有原签发回执时，交付固定 `reconcile` 操作和公开证书；没有回执仍走原 `prepare`。新任务继续绑定账号权限、节点版本、运行快照、SSH 凭据及节点签发租约。

原身份尚未激活时，复用原本机 CSR 及过期原密钥证明。已经激活时，子控在信任及身份锁内核对当前有效私钥、已签发证书和原待用 CSR，以**当前活动新私钥**在独立签名域签署新挑战。请求保留原 `renewal` 字节与摘要，增加可选公开 `continuation_certificate`；没有该字段的旧规范 JSON 及摘要不变。不读取历史原私钥或安装种子，不创建新密钥、不改写活动身份，也不借此改变 CA、SAN 或配置。

主控接纳续作前必须核对原公开发行账本的完整证书、原 CSR 摘要、节点、CA 和有效期设置。签发回放再次核对原回执并保留原快照／代次和审计；续作请求不能调用离线签发原语，账本缺失时明确失败，不能重新签发补齐。激活回放和受控启动均绑定同一公开证书，仍须当前 CRL、原身份未吊销及新身份正常有效。旧授权、错误挑战、已吊销身份、丢失的本机待用资料或不同活动证书均不能续作。

该内核已通过本机竞态、隔离 Linux／PG／SSH 分层验证；本轮真实内核测试在磁盘准备阶段失败，未启动 guest，不能计为 systemd／Docker 验收。宿主执行器／CLI、实际资源核验和采集／扫描／覆盖检查已连接，下面说明操作边界；实际 SSH 与服务管理的联合验收仍待完成，启动回执只证明服务归属和运行状态。详见 [验证记录](V3-VALIDATION.md)。


## 宿主恢复执行器与限时授权 CLI

以下命令仅用于隔离 v3 环境，尚不是正式发布的生产操作。四种操作只允许 Linux amd64 主控宿主机上的 root 执行；输入来自所属账号的私有文件，禁止链接、重复／未知字段和超限 JSON。后台账号仍必须具有管理员权限，任务只能由其原授权账号执行或取消。

先将原过期**公开证书**（不是私钥）和已登记的 SSH 凭据引用放入 `0600` 输入文件，文件父目录应为 `0700`。准备输入示意：

```json
{
  "node": "node-example",
  "expected_version": 1,
  "credential": "已登记的凭据引用",
  "certificate_pem": "-----BEGIN CERTIFICATE-----\n原过期公开证书\n-----END CERTIFICATE-----\n",
  "lifetime_hours": 720,
  "confirm": true
}
```

```bash
webscan control-v3 --config /etc/webscan-v3/control.yaml \
  --action prepare-node-identity-recovery --username admin \
  --request-key recovery-intent-001 --source /root/recovery-prepare.json
```

准备仅保存十分钟授权，不连接 SSH、不签发证书、不改变节点。CA 摘要取自受信启动配置，未提供有效期时默认 720 小时；新授权复用已有发行时必须保留原有效期。响应只包含任务 ID、节点、状态、版本和期限。以返回 ID 创建另一个私有文件：

```json
{"id":"返回的任务ID","confirm":true}
```

```bash
webscan control-v3 --config /etc/webscan-v3/control.yaml \
  --action run-node-identity-recovery --username admin --source /root/recovery-target.json
```

执行依次进行准备、原子激活、原服务启动、实际资源核验、正常 mTLS 与采集健康确认。输出逐行 JSON 进度，包含阶段、运行／通过／中断状态和时间，不输出路径、凭据、CSR 或私钥。中断后可在授权仍有效时重复同一任务；超过期限须重新授权，不能延长旧授权或重新签发已有后继。执行器每十秒续租，续租只更新仍有效的同一 owner／epoch，不以重新抢租复活过期执行器；任一续租失败立即取消远端工作。租约与授权均为绝对时限。

本机 `verify` 在原部署、服务、信任及身份锁内核对已安装程序／工具、当前活动身份、生成配置与实际进程。native 读取 systemd 和内核 CPU／内存／文件句柄限制；Docker 核对不可变 ID、管理配置、真实 PID、cgroup 和进程归属。该步骤不启动、停止、重启或调整资源。

主控另外建立全新且正常验证名称的 gRPC mTLS 连接，核对精确签发证书、当前 CRL、配置版本及摘要，再在同一认证连接读取指标。仅最新有效样本用于验收：采集就绪、目录覆盖、规则、心跳，以及已启用 YARA／ClamAV 的健康信息必须满足当前配置；缺失、过期、重复标量或异常均不能完成任务。暂未就绪最多等待 90 秒并受原授权期限限制，只有最终数据库事务复核权限、配置和租约后才标记完成。

只读查询使用 `node-identity-recovery-status`，相同目标文件即可，不要求 `confirm`。取消使用 `cancel-node-identity-recovery`，目标文件必须 `confirm: true`，并提供新的 `--request-key`；取消保留已签证书及节点数据。历史状态可在到期／取消后读取，不代表授权恢复；已完成历史重放不执行 SSH。

尚待实际 Linux 宿主的 SSH＋systemd／Docker＋主控完整联验。本机替身资源文件、隔离 PostgreSQL、真实 SSH 传输和测试 gRPC 服务的分层通过不能替代该门禁；CA／SAN 迁移与完整 v3 发布条件继续保留。


## 节点 TLS 名称变更核心（尚未接入管理应用）

新增独立 `NodeNameChangeIntent`／`NodeNameChangeRequest`，以及准备、签发和激活原语。它们不用于普通续期，不接受换根、角色或节点 ID 变化。授权包含原节点／CA／证书摘要、唯一目标名称、随机挑战和最多十分钟期限；调用方必须先以受保护持久任务绑定账号、已保存目标配置、原运行快照、SSH 指纹及节点租约。请求回显自身 intent 不能代替授权。**主控持久授权与共享签发账本已在 schema 33 接入；现已增加宿主 root CLI 和固定 SSH 交付，见下节及“名称变更的宿主操作”。网页入口、完整配置应用及实际验收仍未完成；重新授权续作已补入“名称变更到期后的独立授权”，不能用于生产名称迁移。**

目标名称要求规范的小写 DNS 或 IPv4／IPv6 文本，不接受通配符、URL、端口、IPv6 区域标识或 IPv4 映射别名。已有证书已覆盖目标时不签发多余迁移证书。迁移证书保留全部原 DNS／IP SAN，再加入唯一目标，总数仍最多 16；这样原配置、新配置和配置回退期间都能进行正常名称验证。后续裁剪旧名称需独立受控收尾，不能通过普通续期偷偷改变 SAN。

子控要求现有活动身份和既有持久 CRL 目录。准备在信任→身份锁内产生新的本机 Ed25519 私钥及 CSR，以原活动私钥对包含完整授权和 CSR 的独立签名域作持有证明。目录为 `name-changes/<授权摘要>/`，文件 0600、目录 0700，完整落盘后原子发布；同一授权重试只读取原 CSR／密钥。丢失、损坏、链接或不安全权限均停止，不修补活动身份、信任目录或待用密钥。没有私钥进入公开请求或签发返回值。

签发器持有 CA 锁并读取当前完整 CRL，检查原身份仍有效且未吊销、精确新增名称、CSR 新私钥证明，以及原密钥授权证明；拒绝额外 SAN、URI、扩展、角色及原密钥重用。签发期限必须增加活动叶证书的到期时间并受 CA 和 90 天上限约束。结果只在调用方持久提交回调接受后返回；回调失败或上下文失效不返回成功，不修改节点。该原语自身不是共享去重账本，接入前必须复用同一节点的后继唯一性约束。

激活持有当前信任锁，重新核对授权、原身份与候选吊销、原本机请求及 CSR 私钥、精确 DNS／IP／URI 范围和用途；额外邮件 SAN、额外用途／KeyUsage、错误主体、不同私钥及过期证书均拒绝。复用身份 compare-and-swap 原子发布并保留旧私有身份，丢失响应重试返回同一结果。所有操作保留原 CA、CRL 下限、数据、监听器和运行配置；不能用新种子替换已初始化身份。普通续期的原协议与校验保持不变；迁移后正常续期继续保留批准的重叠名称。

本机已验证实际双向 TLS 在同一监听器上切换：激活前新名称失败，激活后新旧名称和原 IP 都通过正常 CA、身份和名称验证。该证明不等于实际 Agent、固定 SSH、主控任务及 systemd／Docker 联合变更。授权到期后拒绝继续使用旧凭据；已激活但未完成应用时的独立重新授权核对和固定 SSH 已接入后文；配置应用／回退的完整验收与旧 SAN 裁剪仍须完成，完整 v3 发布门禁继续保留。具体结果见 [验证记录](V3-VALIDATION.md)。


## 名称变更的主控持久授权与签发去重

schema 33 增加 `v3_node_name_changes`。名称变更由独立管理员任务授权，分别绑定已保存目标快照和原活动快照／代次，以及账号修订、节点版本、目标名称、CA／原证书、有效期和已加密保存的 SSH 凭据引用／内容证明。目标名称只能来自已保存配置；不能从节点回传的请求自行取得授权，也不放宽普通续期或过期身份恢复对当前名称的要求。该持久层自身不提供后台或 RPC 操作；宿主 root CLI 与固定 SSH 交付见下节。

准备仅持久化十分钟挑战。接纳公开 CSR、签发以及重复查询均重新校验原管理员权限、两个配置快照、凭据和迁移／部署互斥。凭据封装换密不使相同凭据内容失效，实际内容变化则必须重新授权；没有原始 SSH 凭据、私钥或节点本机路径进入任务、回执与审计。

名称变更和普通续期共用 `node-renewal:<节点>` 租约、节点行锁及 `(node,parent_sha256)` 后继唯一约束。公开签发记录新增 `request_kind`：旧记录迁移为 `renewal`，名称变更为 `name-change`。两类请求不能互换或覆盖已有发行；签发与审计、共享 CRL 下限、任务状态在同一事务提交，失败、租约或授权到期不交付证书。响应丢失时返回同一公开证书，回放不需要重新读取 CA 私钥，但仍需当前授权、CRL 和精确 CSR／名称范围。

任务准备至确认期间，目标节点的编辑、部署／预览、配置绑定及普通续期暂停；其他节点可继续编辑。全局配置恢复也等待活动任务结束。到期任务保留证据，下次准备时取消其活动占位；取消保留已签证书和节点数据。确认事务核对观察到的精确证书、原／新名称、当前 CRL、账号、配置与租约后才记为完成；调用方必须通过全新且正常验证的 mTLS 连接取得真实对端。存储层测试注入的证书对象不等于实际连接验收。

此任务完成只表示重叠身份已确认，不会发布目标运行配置、启动／重启服务或切换端口。固定 SSH 工具已接入下节的宿主操作；配置应用、回退的完整验收仍待完成；激活后授权到期的重新授权续作已接入后文；旧名称裁剪和 CA 换根也尚未完成。数据库增量升级仍要求先一致性备份，失败停止；公开签发和任务纳入数据库备份／恢复。完整 v3 的功能、容量与故障门禁继续保留。

## 名称变更的宿主操作

新增 Linux amd64 主控宿主 root 专用命令：`prepare-node-name-change`、`run-node-name-change`、`cancel-node-name-change` 和 `node-name-change-status`。这些为隔离验证入口，尚未构成可发布的生产名称迁移；网页和公网 RPC 不接受该操作。

先保存目标节点配置中的新 TLS 名称，保持原活动配置不变。准备文件必须为受保护的本地 JSON（目录 0700、文件 0600），包含 `node`、`expected_version`、`credential`、`certificate_pem`、可选 `lifetime_hours` 和 `confirm: true`。证书为原公开叶证书；凭据为已经核实 SSH 指纹并加密保存的引用，不提供私钥或密码。目标名称只从已保存节点取得，文件不能指定任意目标名称、路径或命令。默认签发 720 小时，必须延长原叶证书期限且不超过 CA／90 天限制。

```bash
webscan control-v3 --config /etc/webscan-v3/control.yaml \
  --action prepare-node-name-change --username admin \
  --request-key name-change-intent-001 --source /root/name-change-prepare.json
```

准备只保存十分钟授权，不连接子控、不签发、不修改运行配置。取得任务 ID 后，另建私有目标文件 `{"id":"返回的任务ID","confirm":true}`：

```bash
webscan control-v3 --config /etc/webscan-v3/control.yaml \
  --action run-node-name-change --username admin --source /root/name-change-target.json
```

执行依次输出准备、激活、资源核验和真实连接核验进度。固定 SSH 工具使用可信发布清单中的 SHA256／长度，校验本地文件并在远端核验；只允许 `--identity-name-change` 的 `prepare`、`reconcile`、`activate`、`verify`，没有启动、停止、重启或配置应用操作。私钥在子控本机生成、保留；回传内容仅限公开 CSR 和受限回执。丢失响应在原授权仍有效时复用同一任务、CSR 和发行记录，不重新签发后继。租约每十秒仅续租仍有效的同一 owner／epoch，失效立即取消。

子控持有部署 journal、服务操作、信任及身份锁，核对原安装程序、服务与配置，推进已有 CRL 下限后原子激活。资源核验检查当前进程、服务及保存的 CPU／内存／句柄限制；不会通过该命令重启服务。完整只读主机核验最多 90 秒，包含两次宿主清点、程序／工具摘要、扫描器自检及真实内核查询，各条主机只读命令仍限 10 秒。主控 SSH 调用另预留 15 秒传输余量；较早的调用超时、取消和十分钟授权到期始终优先，并传递至实际校验过程。证书发布仍保持原有短时限，信任和身份锁持续到主机核验结束。主控随后向**原活动端点**建立两条新 gRPC mTLS 连接，分别使用原 TLS 名称和目标 TLS 名称，要求正常 CA／名称／Collector／吊销验证、同一精确发行叶证书、原活动配置版本及摘要，并检查新鲜的采集、覆盖、规则和已启用扫描器证据。SSH JSON 回执不能完成任务。

`node-name-change-status` 使用相同目标文件，可省略 `confirm`；状态投影限定当前管理员本人，只返回任务、节点、状态、版本和期限。`cancel-node-name-change` 要求 `confirm: true` 和新的 `--request-key`，保留已签证书、节点私钥历史和数据。到期或取消的状态仍可查询，不能据此再次执行；完成任务的 CLI 重放不访问 SSH。

名称任务完成只证明新旧名称重叠身份已通过核验，**不代表已应用新端点、端口、监听器或目标配置**。激活后授权到期的独立重新授权已接通下节；配置应用／回退仍需完整执行及真实运行验收，旧名称裁剪尚未完成。真实 SSH＋Agent＋systemd／Docker 的联合验证和 CA 换根也未完成；分层测试不能替代完整 v3 发布门禁。

## 名称变更到期后的独立授权

原授权到期或主动取消后，不延长旧任务。管理员以新的 `--request-key` 再次执行 `prepare-node-name-change`，继续提交**原公开父证书**、当前节点版本及核实过的 SSH 凭据引用；目标名称仍只取当前已保存配置。`lifetime_hours` 必须与原发行一致，不能借新任务延长已签证书。新任务重新绑定当前账号修订、目标／原运行快照、代次和凭据，保存新的十分钟挑战。

存在原发行时，主控从共享账本和保留的原任务取出原公开请求及精确证书，通过固定 SSH `reconcile` 交付。子控检查现有部署、原本机 CSR／密钥、当前吊销下限及实际活动身份：

- 原证书仍活动且有效：用原私钥证明新挑战，只能继续激活原来已签的证书。
- 原后继证书已活动：用当前后继私钥证明新挑战；准备和激活重放均不重写身份，不读取原私钥历史或 CA 私钥。

两类证明使用独立签名域，保留原 CSR、原请求、精确已签证书和新的授权。新的任务请求摘要与**原发行摘要**分开保存；发行记录、有效期、序列号及原审计不改写。签发器拒绝这两类请求，只能在当前账号、配置、租约和 CRL 均通过时回放数据库原发行。即使当前运行代次已变化，原发行祖先仍保持不变，由新任务提供当前授权；不能以任意 CA 签发的同 CSR 证书替换原记录。

子控不为新授权生成私钥或 CSR 目录，已有文件缺失、损坏、链接或权限异常时停止。原任务和原公开请求是续作祖先，随现有一致性数据库备份／恢复保留。原任务仍不可执行；取消和到期不会删除已签证书及节点数据。原证书尚未激活且也已过期时，此续作不能绕过当前身份有效性检查；须先按独立身份恢复流程处理。

续作之后仍需资源验证及两条新且正常验证名称的 mTLS 连接，完成只确认新旧名称重叠身份。现有托管升级已验证可在完成后准备／预览／排队目标名称配置，无需私有种子，也不会提前发布活动配置；实际目标应用、回退及与 SSH／Agent／服务管理的完整联合验收仍未完成。

### 名称目标应用与回退的分层验证

重叠身份确认完成后，使用现有 `upgrade` 准备、预览和任务流程下发已保存目标。目标物料为不含私钥的托管配置；远端激活成功的检查点发布新运行名称和递增代次，只有新配置的采集、覆盖、扫描与事件链路证据通过，才标记已应用。旧名称的采集回执不能完成目标验收。

配置回退保留已保存目标，恢复原活动配置并再次递增代次；保留节点当前重叠证书和切换后事件，不恢复旧私钥或用旧快照覆盖数据库。本地原生／Docker 阶段用例已验证不可变配置、实际 SQLite 数据与日志导出、精确安装指针恢复及重放不重复启动；服务管理器和内核证据为明确夹具。主控 PG 用例覆盖真实事务、生产租约／信任校验和去重，远端阶段完成及采集证据仍由夹具提供。

真实 Linux 用例通过 `name-change`、`docker-name-change` 模式运行，要求实际 Agent、正常双名称 mTLS、原进程保持、目标版本／摘要及回退后的事件保留。2026-10-20 native 和 Docker 完整用例均已通过，Docker 子控使用 Docker 27.5.1；结果及范围见 [验证记录](V3-VALIDATION.md)。初次真实核验曾因错误复用五秒证书操作时限失败，修复后同一严格检查实际耗时约 5.5 秒并成功。用例使用本地签发夹具，不包含主控 PG／固定 SSH 的联合编排；不能据此认定完整安装器已验收。旧 SAN 裁剪的当前进度见下节，CA 换根仍待实现。

## 旧名称裁剪：本地原语与只读依赖检查

现已增加独立的 `NodeNamePruningIntent`／`NodeNamePruningRequest`，以及准备、签发回调、精确回执检查和本机原子激活原语。主控持久任务与共享签发账本已在 schema 34 接入，见下节；本轮已接通宿主 CLI、固定 SSH 和实际 mTLS 观察；网页执行入口未开放，真实 native／Docker 29 联合验收仍未完成。 普通续期和名称扩展流程均不接受裁剪请求，普通续期仍保留当前完整 SAN 集合。

裁剪授权最长十分钟，绑定节点、原 CA／叶证书摘要、已应用配置摘要、运行代次、当前名称和有序且不重复的必保名称。仅允许原证书名称集合的真子集，必须保留当前名称；不增加名称、不进行通配符扩展或 IP 别名替换，也不改变节点身份、CA 或角色。请求由活动父私钥签名，采用独立签名域；请求自带的配置摘要、代次和名称不构成主控授权。持久任务在每一步从受保护状态重新核对这些绑定。

子控原语为每个精确授权保存独立的本机密钥与 CSR，重试复用原文件。缺失、损坏、符号链接和不安全权限均停止，不重新生成材料掩盖异常。签发回调只收到公开证书和 CRL，调用方必须先提交唯一父证书后继的共享发行记录再交付。激活按信任→身份顺序持锁，检查现有 CRL、精确 CSR／回执和原活动身份，保留原私钥历史；不启动服务或修改配置。旧授权过期后不能直接继续；本轮补齐独立重新授权与原发行对账，见后文。

主控另有只读的 `planNodeNamePruning`，从真实 PG 的已生效配置、登记证书及当前吊销下限计算必保和可移除名称；保存、下发和应用版本必须一致，账号必须仍为管理员。未完成部署、身份操作、待激活续期、冲突后继、运行代次不一致或未知登记均停止。相同裁剪的原发行允许重新授权后精确对账，不允许第二次签发。它不读取 CA／子控私钥、不签名、不生成授权、不保存任务，也不证明远端已加载指定身份。

在显式历史退役协议完成前，**所有保留的配置快照均作为恢复依赖**，包括已停用和成功部署前的快照。检查按排序的完整快照流计算依赖摘要，不把完整历史装入内存，也不自动解除备份引用或删除旧快照以允许裁剪。名称目标部署成功后，只要旧快照仍保留，旧名称就继续受保护；全部名称受保护时返回无可移除项。后续持久授权与执行必须重新核对依赖摘要和实际活动身份。

本地回环 mTLS 已验证同一监听器加载裁剪身份后，新连接拒绝被移除的名称，保留的 DNS／IPv4 名称仍正常验证；IPv6 与纯 IP 子集也有原语测试。**裁剪不等于吊销原证书，也不等于既有连接已关闭**，保留的旧证书仍受正常有效期及吊销规则约束。这些结果不代表实际 Agent、SSH 或服务管理的完整裁剪验收；真实服务联合执行、历史退役、CA 换根及完整 v3 发布门禁继续保留。

## 名称裁剪的持久授权与唯一发行（schema 34）

`v3_node_name_prunings` 保存管理员授权、账号修订、节点版本、SSH 凭据引用及内容证明、原活动快照、公开父证书、完整历史依赖摘要和独立限时 intent。名称集合只从受保护数据库状态派生，提交不能指定要删的 SAN 或任意范围。准备、接纳、签发、确认和取消均为内部存储层方法，没有开放网络执行接口。

裁剪、名称扩展和普通续期共用每个父证书唯一的后继发行记录、分片租约及 CRL 下限。签发与任务状态、审计同事务提交；丢失响应后返回相同公开证书，不重复签发，已提交回放无需 CA 私钥。每步重查账号、当前配置、历史依赖、凭据证明和租约；SQL／文件等待后再次以当前时间校验证书及 CRL，过期不能返回有效回执。其他节点不被该节点的裁剪任务阻塞。

备份包含公开任务及不可变发行 ancestry。灾备恢复取消尚未完成的裁剪执行授权，保留已完成记录和唯一发行；恢复旧任务不能获得再次执行权限。schema 33 升级前仍要求一致性备份，失败停止。此处确认测试传入明确的证书观察夹具，尚不代表实际 Agent 已加载裁剪身份。

固定 SSH 交付、运行器续租、实际对端观察及独立重新授权与发行对账已接通。后续 schema 37 加入本地显式历史退役，见下节；只有精确退役且核验完整的快照才不再保护旧名称，不会自动删除恢复依赖。


## 名称裁剪的宿主执行与重新授权

仅在 Linux amd64 主控宿主机以 root 执行。准备请求为私有 0600 JSON 文件，字段如下（证书为当前登记父证书的 PEM 内容，不包含私钥）：

```json
{
  "node": "node-a",
  "expected_version": 3,
  "credential": "已保存且固定指纹的凭据 ID",
  "certificate_pem": "-----BEGIN CERTIFICATE-----\n...\n-----END CERTIFICATE-----\n",
  "lifetime_hours": 720,
  "confirm": true
}
```

```bash
webscan control-v3 --config /私有目录/host-config.yaml \
  --action prepare-node-name-pruning --username admin \
  --request-key pruning-001 --source /私有目录/pruning-prepare.json
```

准备只保存授权，不连接子控、不签发、不切换身份。将回执 `id` 写入另一个私有目标文件 `{"id":"回执中的 ID","confirm":true}`，再执行：

```bash
webscan control-v3 --config /私有目录/host-config.yaml \
  --action run-node-name-pruning --username admin \
  --source /私有目录/pruning-target.json
```

运行器按准备、激活、资源核验、实际 mTLS 与新鲜健康指标的顺序执行。使用发布清单固定摘要的工具及固定 root SSH 指纹，每步重查账号、配置、历史依赖、凭据与租约；SSH JSON 成功不能完成任务。进程中断后在授权有效期内使用同一任务继续，签发响应丢失仍返回原证书。只读查询为 `node-name-pruning-status`；取消为 `cancel-node-name-pruning`，要求目标文件确认并提供新的幂等键。状态回执不包含凭据、路径或私钥。

任务过期后重新使用准备入口和新的幂等键；旧任务保留证据且不恢复授权。若已有原发行，宿主向子控发送原公开请求及证书，子控以当前有效父私钥或精确活动后继私钥签署新挑战，复用原 CSR 和本地密钥。独立签名域绑定新授权及不可变原发行；当前 CRL 同时检查父证书和后继，不允许被吊销身份继续。已激活后继时不读取历史私钥，也不重新签证；原证书自然过期后仅有效活动后继可继续。配置摘要、运行快照、代次、名称范围及有效期须与原发行一致，变化时停止。

数据库灾备恢复仍取消未完成裁剪任务。原公开请求及唯一签发记录保留，恢复后的管理员必须重新准备、重新证明当前密钥并取得新租约；不能直接重放备份里的执行授权。总览的证书维护心跳也不从备份恢复为实时证据。

本轮测试覆盖真实 PG 事务、SSH 夹具、回环 mTLS 以及 native／Docker 安装状态夹具。它们不等同于真实 native 和 Docker 29 服务的主控／SSH／Agent 联合验收。显式历史退役已按下节加入；CA 双根的运行组件与本机子控工具已实现，但主控管理员持久任务和真实 SSH 编排仍未完成。


## 历史配置退役（本地开发，未发布）

`preview-node-history-retirement` 和 `retire-node-history` 仅允许 Linux amd64 宿主 root 执行，并要求当前数据库中的管理员账号。先使用私有 JSON 文件预览精确的历史快照 ID：

```json
{"node":"node-a","expected_version":3,"snapshots":["原任务记录中的历史快照ID"]}
```

```sh
webscan control-v3 --config /private/current.yaml --action preview-node-history-retirement \
  --username admin --source /private/retirement.json
```

核对返回的节点、历史名称及“禁用历史恢复”影响后，在同一文件加入 `"confirm": true` 和返回的 `"preview_sha256"`，再使用新的幂等键执行：

```sh
webscan control-v3 --config /private/current.yaml --action retire-node-history \
  --username admin --request-key explicit-history-retirement-1 --source /private/retirement.json
```

运行配置必须已保存、下发且生效。活动快照、当前保存配置，以及仍有部署、部署准备、续期、身份恢复、名称变更或裁剪待处理的节点会阻止退役；已过期的授权也需要先明确取消。每次最多 64 个精确 ID，不支持通配符。预览绑定账号版本、当前全部配置、运行代次及历史快照摘要，提交时再次核对。不会停止主控或子控，也不会自动裁剪或吊销证书。

退役是永久的恢复限制，不删除历史快照、旧任务、证书或事件。重试同一幂等键重放原回执；管理员降权后不能重放。配置重新生效、历史部署回退与配置应用均拒绝使用退役快照，数据库触发器另行阻止其成为活动登记。包含退役记录的 PG 备份及空库恢复保留这些限制。早于退役的旧归档不包含后续记录，不能据此证明最新退役状态；灾备切换前还需核对独立保留的最新退役资料，相关完整恢复流程仍在后续实施中，不会自动启动旧归档中的运行目标。

仅在所有保留的非退役快照不再引用旧名称后，旧名称才能通过名称裁剪流程移除。退役记录绑定的原快照损坏时裁剪仍停止，不能忽略损坏记录取得通过。原任务的历史凭据不因此重新获得权限；如需再次采用旧名称，应基于当前配置重新进行名称授权和新部署，不能复活已退役快照。

### 保留独立退役检查点及恢复对账

退役完成后，将最新认证检查点与其 SHA256 独立保留在业务归档之外。命令只在主控 Linux amd64 宿主 root 下运行，要求当前管理员和原 Vault：

```sh
webscan control-v3 --config /private/current.yaml --action export-node-retirements \
  --username admin --output /private/new-retirement-checkpoint
```

输出目录不能已存在。回执给出 `checkpoint_sha256`；目录中的 `retirements.json` 只包含原 CA、中心实例、不可变退役记录及认证信息，不含 Vault 密钥、SSH 凭据或私钥。没有自动证明“最新”的机制；必须在每次新增退役后独立更新副本。旧检查点不能解除更晚的限制。

恢复旧 PG 归档后，先核对来自独立受控来源的摘要，再准备私有请求文件：

```json
{"checkpoint_file":"/private/latest/retirements.json","checkpoint_sha256":"可信外部 SHA256","confirm":true}
```

```sh
webscan control-v3 --config /private/current.yaml --action reconcile-node-retirements \
  --username admin --request-key retirement-reconcile-001 --source /private/reconcile.json
```

对账只补入完全匹配原历史的缺失退役记录，原记录不覆盖，整笔事务可幂等回放。错误中心／原 CA／Vault／摘要、损坏历史、缺失快照或仍在活动的已退役快照均停止；不能通过强制改写运行状态处理。回执始终 `cutover_authorized:false`，不启动工作器、不解除迁移保护，也不完成节点代次、通知或部署任务的灾备协调。

## CA 换根管理员任务（schema 38，未发布）

已实现共同签名双根及最终授权、独立 CRL 下限和不可变历史、普通 mTLS／gRPC 的动态信任、限制为既有授权的 CRL 刷新、本机 CSR／私钥切换与后继普通续期。固定 root-only 子控工具为 `node-v3 --identity-root-rotation`；没有开放网页换根接口。该工具核对原安装、配置摘要、节点、当前证书及任务快照，不接受路径或命令，不能因 SSH JSON 回执就宣告完整换根。

分发续作使用两套 CA 私钥共同签署的十分钟目标授权，绑定原不可变任务、当前证书、节点、配置与完整信任快照；新鲜授权可以继续旧任务，不能更换成员或撤销最终旧根退出。API／采集器不持有这些私钥，普通在线 CRL 刷新不能使用该机制开始或结束换根。

单中心维护程序已能按实际叶证书签发者维护 CRL 和采集器，旧根退出后不再需要其签发私钥。后继签发者固定保存到原 authority 目录内的 `successor`，备份锁覆盖两套签发历史；原 CA 文件作为历史锚保留，不能用覆盖文件来换根。历史安装配置核验不会恢复过期种子身份。

主控持久管理员任务、固定 SSH 分发、全部成员真实 mTLS 观察和独立最终确认已实现。后继根可用于新节点、续期和名称维护；真实 native／Docker 29 联合验收仍在进行，不能因本机原语或 SSH 回执通过而标记门禁完成。

在 Linux amd64 主控宿主以 root 执行，使用当前管理员和已验证发布信任资料。准备文件为 0600 JSON：

```json
{"confirm":true,"members":[{"node":"node-a","credential":"已固定指纹的凭据ID","certificate":"当前节点公开PEM证书的Base64"}]}
```

必须精确列出全部运行登记中的节点，包括已禁用但仍有运行登记的节点。采集器身份由宿主读取，不由文件指定。准备只冻结当前账号、配置、运行快照、代次、凭据指纹和发布摘要，不签发根、连接节点或修改服务。

```sh
webscan control-v3 --config /private/executor.yaml --action prepare-root-rotation \
  --username admin --request-key explicit-root-001 --source /private/root-members.json
```

把返回的任务 ID 写入新的私有文件 `{"id":"任务ID","confirm":true}`，再运行：

```sh
webscan control-v3 --config /private/executor.yaml --action run-root-rotation \
  --username admin --source /private/root-task.json
```

程序先向全部成员发布双根，再切换节点与采集器身份；新私钥只在相应机器生成。主控必须从新连接观察到精确后继证书和新鲜指标，才进入 `ready`。此时仍保留旧根，管理员单独执行 `finalize-root-rotation` 才移除在线旧根信任。任一成员未确认不得跳过，也不能通过编辑成员或强制健康状态完成。

`root-rotation-status` 查询公开进度；授权有效 24 小时。中断后继续同一任务；到期或数据库恢复后使用 `reauthorize-root-rotation`、确认文件及新的 `--request-key` 重新授权，成员、配置、凭据和发布物料仍须完全相同。仅尚未签署双根授权的 `prepared` 任务可用 `cancel-root-rotation` 取消；已可能分发的任务保留续作路径，不放弃远端信任状态。普通维护定时器在任务未完成期间保留被冻结的采集器身份，仍刷新必要 CRL。

当前协议仅支持一次原根到后继根，不支持再次换根。已签发的精确后继回执可在原叶证书到期后继续交付；尚未签发且原叶证书已到期时不能凭旧证明签发新身份。不得删除状态目录、重建 CA 或跳过到期校验来处理。该边界及真实联合验收结果必须随发布记录明确保留，完整阶段是否可交付以 `V3-NEXT-IMPLEMENTATION.md` 为准。
