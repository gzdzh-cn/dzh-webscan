# v2.0.22 HTTPS 访问修复验收记录

## 问题与修复

浏览器拒绝部署 CA，或者客户端向 HTTPS 端口发送 HTTP 请求时，底层 HTTP 服务会记录握手错误。旧代码直接创建 GoFrame ServerConfig，未初始化 Logger，导致日志处理空指针，整个接收容器退出并重启。后台和节点事件接收会间歇中断。

本版本为接收服务和网站后台分别初始化 GoFrame 日志对象，保留原有请求日志关闭设置。握手失败仅结束该连接，不终止服务。不改变 CA、节点令牌、数据库结构、业务网站、Nginx 或防火墙。

## 验证

- 使用旧代码覆盖运行新增回归测试，复现 `ghttp.(*errorLogger).Write` 空指针和进程退出。
- 修复后，两套 HTTPS 接口均覆盖多次拒绝 CA 及错误使用 HTTP；后台会话接口、登录、文件事件接收、确认和模拟飞书/Loki 队列排空通过。
- 前端类型检查、6 项前端测试、真实 Vite 构建和 Go 全量测试通过；central、website、bootstrap 的竞态检测及 `go vet ./...` 通过。
- Linux amd64 central 镜像用独立数据库、证书和模拟投递接口验收；连续 10 轮拒绝证书与 HTTP 错误访问后，无重启、启动时间不变、无 panic，仍可登录、加载真实前端、查询首页检查结果及投递旧文件事件。
- v2.0.22 与 latest 标签公开发布，核对两种标签的摘要和匿名下载镜像身份。不可变发布记录保存于 `dist/v2.0.22/release.json`。

## 应用方式

同步主服务器三文件部署包，仅更新文件，不切换生产服务。由管理员执行：

```bash
cd /root/webscan-deploy
bash deploy-webscan.sh --upgrade --central-only
```

子服务器无需升级。升级后仍使用自建 CA；浏览器需信任 CA 或由管理员设置可信域名 HTTPS 反向代理。服务侧不再因客户端拒绝证书而崩溃。

验收记录及隔离日志位于 `.cache/website-v2.0.22/`，包含私有部署快照，不应上传或公开。
