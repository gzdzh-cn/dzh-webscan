## 问题与修复

用户提供的 v2.0.40 日志中，29 节点已通过文件、扫描、投递及健康验收，最终维护状态同步失败触发旧流程回退。复查又发现镜像加速站的 `latest` 指向旧 Agent，工具包版本校验因此中止。

- 指标配置应用原先使用延迟事务，读后写可能与在线采集写入冲突；隔离回归稳定复现 `SQLITE_BUSY`。改用读取前获取写锁的短事务。
- 指标配置临时失败返回 503，允许维护状态同步限时重试；参数拒绝仍为 400，认证拒绝仍为 401。
- 已验收健康的节点在收尾失败时保留运行和检查点，支持继续原任务。
- 默认 Agent `latest` 解析为部署工具的明确版本，再锁定镜像摘要，保留显式版本和摘要。
- 缺少可信配置应用基线的旧节点显示“待核对”，成功应用后建立基线；不把采集正常误当成配置已应用。
