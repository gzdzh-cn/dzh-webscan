# v3 网站领域与数据库备份

当前仍处于本地重构，不能替换线上服务。已发布版本保持 v2.0.46；本页命令只用于独立测试数据库，不读取生产 YAML，不升级生产节点。

## 本轮已接通

网站配置、故障历史、检测状态和检测任务持久化到 PostgreSQL。检测复用原有的公网地址限制、DNS 固定连接、重定向检查、证书校验和关键词检测。SQLite 与 PostgreSQL 使用同一状态机，保留连续三次失败、连续两次成功恢复、证书提醒和慢响应规则。

多个网站工作器通过短事务领取任务，检测期间不持有数据库事务。租约有递增代次、90 秒期限及配置版本检查；暂停、编辑、删除、工作器中断或租约过期后，旧结果不能回写。`website_monitor.max_concurrent` 限制集群全部网站工作器的总并发，缺省 128；单个工作器另外限制本机并发。

故障、恢复状态及待通知出箱在同一事务写入；出箱写入失败不会留下只更新状态的半成品。通知角色按 15 秒窗口合并，同一网站的故障与恢复保持顺序；窗口内同组超过五条时汇总显示前五条。飞书与邮箱入队及出箱完成同事务提交，发送失败由各通道独立重试。

写接口要求登录、权限、CSRF、明确配置版本及幂等键。批量软删除只处理明确提交的 1～200 个网站版本，任一版本冲突则整批拒绝。软删除保留历史和排队通知，不触发恢复提醒。故障历史接口提供保护原因；共享清理工作器未完成前，不开放删除。

## PostgreSQL 版本与一致性备份

业务 schema 现为 10。初始化只允许空的应用 schema；已有 schema 1～9 不能用 `init-db` 直接升级，必须指定私有备份目录：

```bash
.cache/webscan-v3 control-v3 --config /绝对路径/隔离配置.yaml \
  --action migrate-db --output /绝对路径/隔离备份目录
```

迁移在事务中执行，先以一致性快照导出 Webscan 业务表，再检查 SHA256。目录必须属于运行账号且权限为 `0700`，文件为 `0600`；拒绝符号链接。文件同步、校验或数据库操作失败时，不提交 schema 变更。

独立备份与恢复入口：

```bash
.cache/webscan-v3 control-v3 --config /绝对路径/隔离源配置.yaml \
  --action backup-db --output /绝对路径/隔离备份目录

.cache/webscan-v3 control-v3 --config /绝对路径/隔离空库配置.yaml \
  --action restore-db --snapshot /绝对路径/备份.jsonl
```

恢复只允许空的应用 schema，禁止覆盖正在使用的库。恢复前校验全文件，恢复过程中再次校验，事务提交前核对版本和完整性；保留业务 ID 并推进自增序列。schema 1 的备份恢复后仍为 schema 1，需另行备份升级。

这些备份包含业务凭据和密码摘要，必须独立保护。它们不包含 PostgreSQL 角色／权限、数据库服务配置、VictoriaMetrics、外部私钥、PKI 或文件备份。灾备恢复后如何协调 Agent 已记录的租约代次仍未完成，因此空库恢复通过不代表可以直接接管生产节点。

## 网站与账号的归档映射

先按重构指南使用 `archive-v2` 创建一致性 SQLite 快照并完成无损归档。记录归档报告的 `source` SHA256，然后执行：

```bash
.cache/webscan-v3 control-v3 --config /绝对路径/隔离配置.yaml \
  --action map-websites-v2 --source <已完成归档的SHA256>
```

映射覆盖 `website_admin`、`website_sessions`、`websites`、`website_incidents` 和可选的 `website_outbox`。包含网站出箱时，要求同一快照的 `tasks` 已完整归档。首次映射要求目标网站及账号为空，拒绝混入另一部署来源；每批最多 500 条且归档载荷不超过 8 MiB，检查归档摘要并持久化检查点。中断后使用同一 source 继续，已提交的批次不重复写入。失败报告包含已完成部分。

网站 ID、配置版本、关键词、关联节点、暂停／删除标记、检测状态及未结束故障均保留。管理员沿用原密码摘要及账号版本；只导入仍有效且账号版本一致的会话，不延长到期时间，过期或撤销记录继续留在原始归档中。

网站导入使用持久迁移保护；导入网站带 `migration_pending: true`，不会检测、编辑或删除。迁移期间新建网站、修改账号／密码及新建登录会话返回服务暂不可用，不能混入新数据；已有有效会话可继续只读查询。原始归档不会因映射而清除。当前报告的 `ready_for_cutover` 保持 `false`：旧通知队列已可按原收件人及进度冻结映射，见 [历史迁移](V3-HISTORY-MIGRATION.md)；合并出箱已接入，但其他领域、浏览器会话衔接、最终增量与保留新数据的回退仍未接通。

## 网站待通知出箱

`websites` 角色负责检测和事务写入出箱，`notifier` 角色负责合并入队及双通道投递；`all` 包含两者。合并工作器使用 `website-flush` 持久租约和递增代次，每轮最多处理 500 条、8 MiB；数据库入队或提交失败不会标记出箱完成，换实例继续也不会复制通知。

出箱暂停、全部通知通道关闭时保留待发送记录；网站软删除不撤回原通知。仅因时钟回拨而产生较早创建时间的恢复，不会越过同网站旧故障，也不会卡住其他网站。网站总览接口增加 `notification_outbox` 数量／最老等待时间和 `notification_worker` 心跳，无运行证据时健康状态为 `null`。

旧出箱保留原 ID、网站、节点、类别、消息和创建时间；已入队的旧通道任务继续由通知映射保留原收件人和进度。v2 的出箱删除与通知入队处于同一 SQLite 事务，因此同一快照中若出箱与其原任务重叠，停止映射并要求核对快照，不猜测或重新发送。

映射期间不执行通知策略，也不开放领取。只有测试专用的解除保护用例会验证历史入队：原出箱沿用 `website:<原出箱首ID>:<序号>`；新观测使用独立的 `website-v3:` 身份，避免与已清理的旧历史编号冲突。完整切换门禁尚未开放，不提供生产解除保护命令。

schema 7→8 仍要求一致性备份；此前本地版本已导入的网站检查点会建立持久保护。备份／恢复包含待通知记录、检查点、原身份和保护状态；恢复后不会自动激活。原始 SQLite 文本含 NUL 或无效 UTF-8 时停止归档，保留一致性快照并给出脱敏错误，不宣称归档已完成。
