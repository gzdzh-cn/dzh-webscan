# v3 文件与安全事件迁移

本页只用于本地隔离验证。完整 v3 尚未交付，已发布版本仍为 v2.0.46；映射成功不代表可以切换生产。

## 保留哪些数据

| 来源 | v3 保留方式 |
|---|---|
| v2 原生 SQLite 事件 | 保留节点、原事件 ID、原接收时间、载荷、扫描命中分类和原摘要，恢复原生确认回执 |
| 从 Loki 导入的旧日志 | 保留日志 ID、节点、原时间和载荷，只作为历史展示，不凭日志生成 Agent 确认 |
| 已移除节点 | 只增加历史身份，不创建活动节点或采集地址 |
| 与原生事件重复的旧日志 | 无损归档保留原文，历史列表不重复展示 |

迁移不重新计算通知策略，不创建新通知。飞书和邮件的原任务、收件人、重试及完成状态通过同一中心快照的通知映射保留，详见 [告警和通知迁移](V3-HISTORY-MIGRATION.md)。

## 隔离环境命令

先对旧中心 `events-v1.sqlite3` 执行 `archive-v2`，创建一致性快照并完成暂存。记录报告中的 SHA256，只对独立测试数据库执行：

```bash
.cache/webscan-v3 control-v3 --config /绝对路径/隔离配置.yaml \
  --action map-events-v2 --source <中心快照SHA256>

.cache/webscan-v3 control-v3 --config /绝对路径/隔离配置.yaml \
  --action map-notifications-v2 --source <同一中心快照SHA256>
```

两个映射可按任意顺序执行，事件映射要求配套通知表已完整归档。首次绑定要求对应目标领域为空；同一领域不能混入另一个快照。每批最多 500 条且归档载荷不超过 8 MiB，业务写入和检查点同事务提交。失败保留已提交批次，重复命令从检查点继续。

单条旧事件载荷上限 2 MiB；缺少原节点、事件类型、原生身份／时间、摘要不一致、归档损坏或不支持的载荷均停止映射，原始快照和暂存保留。错误不包含 PostgreSQL 可能引用私密载荷的 DETAIL。

## 回执与数值兼容

原生摘要沿用 v2 的规范：去掉中心补充的 `server_ip`、`server_name`、`received_time`，按相同的 canonical 格式计算 SHA256。新的 v3 接收也使用该规范，避免已接收事件重发时被误判为冲突。JSON 大整数采用 `json.Number`，文件大小及 inode 不经过 float64 舍入；迁移保留原接收时间的小数部分。

早期本地 v3 数据库曾使用 JSON／float64 摘要。升级后单独标记该格式；只有原摘要和保留载荷的精确 JSONB 值都相符才确认。大整数被舍入、载荷已不存在或身份冲突时不伪造确认。该兼容仅用于本地旧 v3 数据，不修改已发布 v2 协议。

仅有 Loki 历史时，主控仍须先事务保存实际 Agent 事件和回执，再确认。若旧展示载荷与重读事件规范摘要一致，不为这次历史重读生成新通知；有差异的实际新载荷继续正常处理。包含 NUL 文本、超出 PostgreSQL 数值范围或无法规范化的实时事件单独永久拒绝，不阻断同批正常事件。

## 查询与清理边界

`/api/v3/events` 同时查询原生和迁移历史，默认排除探针；显式查询 `operation=probe` 必须开启 `include_probes`。返回固定时间范围和包含来源的分页游标，时间／节点／ID 相同的不同来源记录也不会遗漏。旧游标仍兼容。

记录增加 `source`、稳定 `record_key`、`can_delete` 和保护原因。原生回执独立于历史展示：删除展示记录后，旧迁移副本不会重新出现。自动期限清理已接入，旧日志删除身份不能当作 Agent 回执，详见 [历史保留](V3-RETENTION.md)。**手动清理仍未接入，当前接口不会宣称历史可选择删除。** 现有 v2 网页及删除行为不受影响。

文件事件在 schema 7 引入，当前业务 schema 为 **9**。已有 schema 1～8 必须使用 `migrate-db --output <私有目录>` 先完成校验过的一致性备份。备份恢复包含原生摘要格式、迁移历史、精简删除身份、检查点及持久迁移保护；只允许空应用库恢复。

迁移完成的 `ready_for_cutover` 仍为 `false`。保护不会因重启或恢复备份解除；映射阶段不领取业务通知、不确认新事件。最终增量、冻结交接、部署、网页和保留新增数据的回退尚需完成，没有公开激活命令。

## 验证范围

使用实际 v2 接收器、真实 SQLite 一致性快照及独立 PostgreSQL 验证：原生与旧日志去重、超出 float64 精度的整数、原接收时间、扫描分类、已移除节点、双来源同键分页、探针默认隐藏、重复确认及冲突隔离、503 条续作、8 MiB 边界中断、大载荷、坏摘要／身份／格式、运行目标拒绝、备份恢复及 schema 6→7 备份门禁。

自动验证不连接业务通知渠道，不触及线上配置或服务。完整结果及尚未完成项目见 [验证记录](V3-VALIDATION.md)。
