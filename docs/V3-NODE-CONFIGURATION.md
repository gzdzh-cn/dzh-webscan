# v3 子控运行配置包

2026-10-30：宿主准备工作器现已服务于公开网页部署流程，API 不持有 CA 私钥或宿主执行权限。当前入口见 [网页部署与凭据](V3-WEB-DEPLOYMENT.md)，真实验收见 [发布记录](V3-FORMAL-RELEASE-READINESS.md)；下文保留早期阶段边界。

v3 数据目录中的 `.scanner-readiness/` 为扫描自检专用私有目录，配置验证拒绝将其自身或子路径指定为监控根、关键文件或探针。上层目录仍可监控，运行时会单独排除这个内部目录，防止自检快照被当作业务文件。此排除不写入用户监控规则，不改变旧版 Agent 配置。目录权限、扫描自检和中心验收的说明见 [部署验收](V3-DEPLOYMENT-STATE.md)。

本模块将 PostgreSQL 中的节点配置、独立证书和规则编成私有配置文件，并由 SSH 传输及子控 `stage` 阶段校验。显式执行器已连接 native／Docker 阶段处理器，本地管理员可准备并提交任务；真实服务完整安装验收及公开部署预览／提交仍未完成。配置包准备或任务入队不会推进 `applied_version`，公开部署写接口继续关闭。

## 配置来源和任务绑定

主控内部调用 `PrepareNodeConfiguration`，明确传入节点 ID、预期版本、已经核实的发布清单、节点证书及私钥、签名吊销列表、采集器身份、YARA 规则和私有输出目录。方法先重新读取 PostgreSQL 节点，核对启用状态和版本，拒绝过期请求。

只从节点源配置提取监控、扫描、资源、队列及日志容量、探针、保留天数和指标来源设置。没有提供的字段采用明确默认值；已提供分组中的未知字段和非法参数拒绝，不把主控内部状态、SSH 凭据、业务通知凭据复制到子控。运行目录和执行程序路径由程序生成，配置不能提交任意执行命令。

配置包绑定：

- 节点 ID、配置版本及完整源配置 SHA256。
- native／Docker 方式、目标程序版本和已验签的工具包 SHA256。
- 指标端口、TLS 名称、监控目录及是否启用 ClamAV。
- 独立节点证书、私钥、CA、签名吊销列表、允许的采集器身份及规则。

私有包最大 2 MiB，采用严格规范 JSON。重复键、未知字段、多个文档、版本／用途／SAN 错误、私钥不匹配均拒绝。普通安装准备拒绝过期或被吊销的证书；已续期节点的公开配置包及旧任务继续采用下述专用校验，不能把历史种子当作当前身份。监控探针必须位于监控范围且未被排除；请求 auditd 外部能力时明确拒绝，不宣称单 Agent 已覆盖该功能。

文件按 SHA256 保存，目录 0700、文件 0600。已有同摘要内容可复用；错误文件、符号链接或不安全权限拒绝。返回的元数据只有大小及摘要，本地路径不进入 JSON，包和私钥不得作为 API 响应、日志或审计字段。

创建部署任务时把 `runtime_artifact`（SHA256、字节数）写入不可变任务计划；不存包内容。此字段目前只用于内部运行器，不是已经开放的网页部署接口。

## 本地管理员准备与提交

仅在隔离环境使用 `control-v3` 的显式操作。这些操作不会自动启动执行器、SSH 或切换服务；只有另行启动且显式启用的执行器才能消费排队任务。本地文件输入不提供给 HTTP 调用者。已补入[账号绑定十分钟预览与确认](V3-DEPLOYMENT-PREVIEWS.md)，公开网页流程尚未接入。

1. `store-ssh-credential`：私有 JSON 提供 `node`、`expected_version`、`credential`。凭据字段为 `host`、`port`、已核实的 `fingerprint`，以及二选一的 `password`／`private_key`。加密保存后仅返回凭据 ID；重试使用同一 `--request-key`。
2. `prepare-deployment`：私有 JSON 提供 `node`、`expected_version`、`kind`（`install` 或 `upgrade`）、`credential`（上一步 ID）、`collectors`、`rules_file`。身份选择 `identity_directory` 或 `identity_id`，不能同时提供；前者目录包含离线工具生成的 `ca.crt`、`identity.crt`、`identity.key`，后者从加密发行登记读取。两者均不提供时，显式启用 `node_pki` 并提供稳定 `--request-key` 可自动签发。使用当前采集器配置中的吊销列表，不采用身份目录里可能过时的副本。
3. `queue-deployment`：输入上一步输出的部署请求。再次核对包内容、节点设置、启用状态、配置版本、凭据、发布签名及当前采集器信任，再事务创建任务。节点行加锁期间重新核对账号及源配置，复用部署互斥、迁移冻结、幂等和审计。

这些操作要求已登记的管理员账号，源码中不会自动创建管理员。文件是当前运行账号所有、仅所有者可读写、无链接的规范绝对路径；输入上限 128 KiB，拒绝未知字段、重复 JSON 键和过深嵌套。身份目录和配置包目录为 `0700`，读取逐层检查父目录。输入可能包含真实 SSH 凭据，必须在私有目录生成，不能加入仓库或终端历史。

```bash
# 以下路径均指隔离主控上的私有测试目录；先准备好输入和受信任发布资料。
umask 077
webscan control-v3 --config /私有目录/control.yaml \
  --action store-ssh-credential --username admin \
  --source /私有目录/credential.json --request-key credential-node-a-1

webscan control-v3 --config /私有目录/control.yaml \
  --action prepare-deployment --username admin \
  --source /私有目录/prepare.json > /私有目录/request.json

webscan control-v3 --config /私有目录/control.yaml \
  --action queue-deployment --username admin \
  --source /私有目录/request.json --request-key install-node-a-1
```

准备阶段核对节点 CA 与当前采集器 CA 一致，验证节点身份和 SAN，校验采集器证书与私钥、当前吊销列表及允许的采集器身份；配置了持久吊销下限时，同样拒绝版本回退。提交时全部重查，吊销列表更新后须重新准备。无法确认信任关系时，不生成私有包、不创建部署任务，不依赖“文件自身验签通过”推断中心一定能连接。

`queue-deployment` 要求 `executor.enabled: true`，但不会启动执行器。输出只证明任务排队；准备元数据、任务计划和审计均不包含证书私钥、SSH 密码或本地输入路径。已提供本地账号绑定预览与确认；尚无公开凭据管理、完整自动签发分发和正式安装菜单，不应把这些本地入口直接接入生产网页。

## SSH 与子控准备

SSH 使用当前任务租约、固定主机指纹和受限程序传输，目的位置固定为：

```text
/var/lib/webscan-deploy/v3/configs/<SHA256>/node.json
```

远端重新核对 root 所有权、0600／0700、大小和 SHA256；拒绝截断、不同内容和链接。配置内容不放入 shell 命令文本，也不经标准输出回显。

子控 `stage` 将包与当前任务的节点、配置版本、源摘要、程序包摘要、方式、端口、证书名称、监控目录和 ClamAV 设置逐项比对。然后在私有临时目录生成：

```text
runtime.json
rules.yar
ca.crt
ca.crl
identity.crt
identity.key
clamd.conf
# 按运行方式二选一
webscan-agent-native.service
compose.json
```

YARA 使用目标程序包中的真实工具编译新规则，通过后才原子发布为：

```text
/var/lib/webscan-deploy/v3/configurations/<SHA256>/
```

`runtime.json` 继续使用既有 Agent 的数据和日志目录 `/var/lib/webscan-v1`、`/var/log/webscan-v1`，只启用主控主动拉取，不写入旧推送令牌或主控通知参数。native 读取本机 `/proc`、`/sys`；Docker 读取挂载的宿主机 `/host/proc`、`/host/sys` 和 `/rootfs`。

服务定义同样由已验证参数生成：systemd 设置 CPU、内存、Go 内存与并行数、文件句柄限制和停止超时；Docker 固定 Linux amd64、不可变镜像、相同资源限制、宿主网络、只读系统与监控挂载，仅数据、日志、探针及启用时的 clamd 目录可写。不存在的挂载来源不会自动创建。离线镜像按签名归档对应的配置 ID 运行，关闭隐式拉取，并核对配置 ID 与仓库摘要的绑定。私钥内容不进入服务定义。

systemd 与 Compose 分别处理路径中的 `%`、`$`、空格和引号，不经过 shell。Docker 合并重复／嵌套监控挂载，拒绝覆盖数据、配置、系统挂载或探针控制区域的目录；当前 Docker 直接监控 `/` 或其他冲突路径仍明确拒绝，不能据此宣称所有目录组合已完成兼容。实际安装、启动和生效资源验收仍由后续安装器负责，定义生成不能代替服务验收。

新配置把吊销版本状态放在 `/var/lib/webscan-v1/pki-trust`，独立于可替换的程序和配置目录。配置恢复不降低已接受的签名吊销列表版本；该目录随子控数据保留和备份，详见 [证书说明](V3-PKI.md)。

已有准备结果或完成凭据必须重新核对全部文件、证书和规则。私有临时准备中断可重试；已发布目录的私钥、运行配置等遭修改时拒绝，不静默覆盖。这个阶段不停止现有 Agent、修改当前运行配置、改变中心登记或创建服务。

## 生效版本回执

Agent `Capabilities` 在原 RPC v1 上增加两个兼容字段：

| 字段 | 含义 |
|---|---|
| `configuration_version` | 此次进程启动时加载的配置版本 |
| `configuration_sha256` | 此次进程加载的源配置摘要 |

使用原文件解码器保留 JSON 整数精度；大于 2^53 的有效 int64 版本不会舍入。错误类型、分数、超限及无效摘要拒绝。旧 Agent／未设置版本的验证配置返回 `0` 和空字符串，不能据此伪报已生效。

回执固定在此运行实例中，主控保存新的期望配置不会改变它。它证明监听进程加载了什么配置，不能单独证明目录覆盖、扫描、投递和资源限制健康；后续部署验收仍须同时核对这些能力，完成后才更新 PostgreSQL 的 `applied_version`。

## 验证边界

自动测试使用隔离证书、私有目录、PostgreSQL 和本机 SSH 服务，覆盖参数拒绝、源版本冲突、主控秘密不外传、摘要绑定、传输、文件权限、篡改、规则错误、重放及整数精度。Linux 容器使用真实 YARA 验证新规则和错误规则，实际启动当前代码的 Agent，核对 mTLS、配置回执、就绪与目录覆盖、文件事件，以及重启后原 ID 的未确认事件仍可读取和确认。Compose 解析与一个不启动的隔离容器验证路径不展开，systemd 252 解析生成的单元。没有操作业务通知或生产节点。

仍需完成自动证书分发轮换和正式安装向导、实际 systemd／原生 Docker 完整服务切换验收、公开升级预览、旧三容器接管及迁移回退验收。程序包、配置包准备及排队不能代替完整部署验收。

## 活动节点身份（私有包 format 2）

新准备包使用 `format: 2`，不可变安装种子与活动身份分开。Agent 首次启动将同节点、同 CA 的签名种子原子初始化到 `/var/lib/webscan-v1/pki-identity/active.pem`，随后只读当前活动文件；不会用升级、配置回退或重启重新激活旧种子。既有 `format: 1` 继续使用原 cert／key 路径，运行配置字节保持兼容。两种模式仍使用原有数据目录，Docker 只读安装挂载不变。初始化、权限、私有历史和备份边界见 [证书生命周期](V3-PKI.md#子控活动身份与安装种子)。此处不代表远端定时续签／分发或 CA 换根已经完成。


## 已续期子控的升级与旧任务继续

首次安装仍生成 format 2，初始化子控数据目录内的活动身份。主控已有本节点公开续期签发回执时，升级准备改为 format 3：只包含公开 CA、CRL、采集器名单、规则和运行参数，不包含叶证书或私钥，也不设置种子导入目录。活动身份继续使用 `/var/lib/webscan-v1/pki-identity/active.pem`，native、Docker 及方式切换复用同一数据目录。

主控按当前公开信任和共享吊销下限核对签发回执、节点归属、有效期与 TLS 名称；没有续期回执的节点沿用原安装路径。已签发但激活确认响应丢失时也可选择公开配置包；子控实际私钥是否有效仍须在远端检查，不能仅凭回执宣告部署成功。预览和任务提交再次核对证据，format 3 不能作为新装任务提交。命令行自动准备不会为这种升级重复签发初始密钥。

保存的部署绑定可继续引用旧证书登记 ID。原始证书只用于核对同节点、同 CA、历史签名及绑定摘要，不解密旧私钥；其过期或被明确吊销不会使有效的本机续期身份失效。未签名、错误节点、换根、绑定摘要变化及当前继任证书吊销仍停止。

子控在准备、备份停止服务之前、切换及任务继续时检查活动身份、固定 CA、目录权限、私钥匹配、用途、节点 ID、TLS 名称、有效期及当前 CRL。续期可在准备与任务提交之间完成，不固定某一瞬时叶证书摘要。失败不写入活动身份、不降低本地吊销下限、不停止旧服务；失效活动证书仍需要专用 SSH 恢复。

旧 format 2 不可变任务可能同时含过期的初始证书和 CRL。节点本机恢复读取器保留原包和所有文件字节，要求已有有效活动私钥及可信的最新持久 CRL，绝不重新初始化丢失的目录。主控仅对既有租约任务采用相同的历史资料读取，并在 SSH 前核对任务版本、原包摘要、当前公开继任证书、Collector 及 SQL 吊销下限。普通准备、在线认证及 format 1 仍严格拒绝过期身份；恢复读取器不能独立授权连接。更新后的持久 CRL 优先用于检查，不用配置回退覆盖它。

本节已通过本地与容器分层验证；完整真实宿主管理、公开部署和跨架构恢复仍按 [验收记录](V3-VALIDATION.md) 的剩余门禁执行。


活动身份已过期时仍不能直接升级或回退到旧种子。新增的主控持久恢复记录与固定路径 SSH 工具仅对当前管理员独立授权和当前 CRL 生效；节点就地保留新私钥、旧私钥历史和事件库，不通过重新准备安装包覆盖身份。已接入固定的、精确核对服务归属的启动步骤；公开恢复操作和完整编排尚未开放，详见 [证书恢复任务](V3-PKI.md#过期身份的主控恢复任务与-ssh-工具schema-32)。

## Docker 29 的离线镜像身份

经典镜像存储使用 config ID，Docker 29 的 containerd 存储可能使用 manifest ID，不能将两者混用。准备阶段先校验整个已签名归档及 OCI manifest 到 config 的绑定，再探测可用的不可变本地 ID，将选择写入私有回执；Compose 生成、激活、容器归属和恢复共同核对该身份。错误、缺失或篡改的回执会阻止启动。镜像准备先于配置生成，避免相同任务在导入前后生成不同的服务定义；保持关闭隐式拉取。
