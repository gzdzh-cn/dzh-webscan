# v3 部署配置备份：存档接口与接入边界

当前已完成内部备份文档、一致性快照、数据库加密存档，以及管理员专用的创建、分页、仅存档导入、脱敏／age 导出接口和网页。恢复已补齐内部规划、预览、待验证恢复意图、恢复前自动备份、取消及本机资料只读诊断，**已增加独立加密候选版本和恢复到真实保存态的内部原子提交；公开恢复到保存配置已接入；运行应用及其余自动备份接入尚未完成，不能据此迁移或恢复生产。** `/backups?tab=deployment` 已接通可用的存档操作，已增加单条／当前页批量删除及本账号任务进度，已增加恢复预览、持久记录及明确的保存态提交。

## 备份范围

v3 配置不再全部保存在 YAML 中。内部 `format_version: 3` 文档包含：

| 内容 | 来源及行为 |
|---|---|
| 启动配置 | 无草稿时使用已校验启动快照，有草稿时捕获本成员已保存的启动配置引用及代次；不自动读取磁盘 YAML 或凭据文件 |
| 运行设置 | PostgreSQL 已保存草稿（无草稿时使用运行设置）、独立代次和运行版本 |
| 节点期望配置 | 稳定节点 ID、名称、采集地址、TLS 名称、开关、运行方式及期望版本 |
| 节点规则 | 去重的 profile，保留已知及未知 JSON 字段；不是证书或可执行部署包 |

运行设置与节点通过同一个 PostgreSQL repeatable-read 事务捕获，避免设置来自修改前、节点来自修改后的混合快照。独立捕获是只读操作；手动存档则把捕获、加密记录、幂等回执和无凭据审计放在同一事务。回执重放不重新捕获，重复点击不能创建第二份备份。捕获不会修改运行设置、创建部署任务、发送通知、连接子控或修改应用版本。数据库内的启动配置草稿参与捕获；不会自动捕获后来编辑的磁盘 YAML。

文档不包含账号、当前管理员密码、会话、事件、故障历史、通知队列、指标、部署任务检查点或远端 SQLite。也不读取 SSH 凭据库、外部私钥、数据库 DSN 文件、独立凭据密钥、PKI、规则文件或部署工具文件。配置中已有文件路径或不透明引用，不等于已经备份这些外部资料。

运行设置中的邮件／飞书凭据仍沿用现有受限 PostgreSQL 载荷；本模块没有将这些设置改成独立密钥加密存储。完整灾备仍须一致性数据库备份、独立密钥和配套文件。

## 数据库存档与保护

未发布的 v3 业务 schema 现为 **24**，其中节点运行登记分离见 [说明](V3-NODE-RUNTIME.md)。已有旧版本库必须先完成并校验 PostgreSQL 一致性备份，失败停止升级；空库可初始化。旧 schema 13／14／15／16／17 的备份仍可在空目标恢复，再按同样门禁升级。

- 配置备份正文使用独立 Vault 密钥和 AES-GCM 加密后入库；身份、版本及关键元数据受认证保护。密钥不进入数据库或其备份，读取需要原密钥或保留的上一版密钥。
- 密文按最多 1 MiB 分块存放，避免最大配置文档经 PostgreSQL `bytea` 十六进制转换后超过既有 64 MiB JSONL 行限制。元数据和全部分块同事务提交，失败不会留下半份备份或成功回执。
- 列表仅有时间、来源、配置版本、节点数、需补全及删除保护信息。创建／导入回执不表示实时可删除，需刷新列表；不返回正文、密钥身份或敏感配置摘要。存档管理、导入及导出均在存储层重查管理员权限，回执重放也不能绕过降权。
- 导入只新增存档；脱敏文档标记需补全。它不修改当前配置、节点、账号、应用版本或部署队列。脱敏导入可再次脱敏导出，重复脱敏不累加或覆盖省略字段。
- 导出准备前持久化五分钟引用，HTTP 响应写入返回前继续持有；结束、失败或取消均尝试解除，进程退出后的过期引用由既有维护工作器分批清除。引用表预留恢复、部署及回退保护，存在这些引用时同样阻止底层删除；对应任务的自动建立／释放仍需后续接入。独立备份不受普通历史 24 小时限制。
- 底层删除在迁移共享门禁及父记录锁下重新检查保护，元数据、密文分块和过期引用同事务删除。公开删除通过固定范围预览、确认及持久化任务运行，不在 HTTP 请求中直接调用底层删除。
- 可在同一事务重新加密到新密钥，保留备份 ID 和业务内容；旧密钥必须保留至所有存档、数据库灾备及其他引用都完成处理。它不会自动改写独立灾备文件。

一致性数据库备份覆盖这些密文表，空库恢复按既有归档校验恢复分块；实际读取时再检查分块连续性、长度、AEAD 和文档元数据。恢复保留持久回退引用，但不复活已中断的导出引用。导出审计只标记“已准备”，不把准备成功说成 HTTP 下载完成。外部权限、受信 HTTPS、解密并发与持久化频率限制已接入下述 API；仍不声称客户端已完成下载。

## 格式、隐私与上限

- 节点按唯一 ID 存放，不按列表位置匹配。公共 profile 编号为文档内的 `p1`、`p2`，不会公开敏感配置的 SHA256 作为标识。
- 默认脱敏采用字段白名单：移除节点名称、地址、TLS 名称、来源 IP、启动地址／文件路径、完整通知通道及未知字段，并明确记录省略路径。稳定节点 ID、中心实例 ID、监控目录等仍保留，不能把脱敏文件当作适合任意公开发布的资料。
- 未知节点配置在私有文档中完整保留，在脱敏文档中显式省略。相同脱敏规则可共用 profile；恢复缺失值时逐节点展开，只使用同一 ID 的当前配置。
- 缺失值合并只处理显式省略项，不覆盖已提交值，也不写库或应用。新增节点缺少地址等信息时保留缺失清单，不能假装已经补全。加密包“保留当前凭据／明确替换”的选项及最终生效流程尚未接入。
- 只接受单份严格 YAML，拒绝重复键、未知顶层／节点字段、别名、锚点、合并键、自定义类型、过深嵌套、非法 profile 引用及凭据遮罩。错误不包含输入片段。支持的已知节点参数、保留期限和完整启动配置复用现有校验；不完整文档仍需要后续完整恢复校验，格式通过不表示可以直接应用。
- JSON 数字保留原始十进制文本，避免未知配置中的大整数／小数在浮点转换中失真。扩展字段只被保存，不因此获得执行权限。
- 启动配置、运行设置和每份节点配置各自仍限制 2 MiB。为容纳两万节点元数据，原生 v3 合并文档单独限制 **32 MiB**、节点最多 **20,000**，二进制 age 包限制 **34 MiB**；超过限制明确失败，不截断。原 v2 YAML 2 MiB／加密包 4 MiB 规则没有改动。

两万节点合成配置的编码测试用于验证去重、体积和隐私。它不等于采集容量、事件吞吐、真实部署、HA 或 72 小时稳定性验收。

## 加密边界

使用官方 Go `filippo.io/age` 库及标准密码加密格式；密码为 12～1024 字节且二次确认，不进入文档、状态或错误。错误密码、截断、内容损坏和过大包均拒绝；解密限制 scrypt 工作因子，读取明文时仍受大小上限限制。私有文档拒绝 JSON 状态序列化，普通诊断输出仅显示固定占位文字。

本地开发 API 已接入以下边界；当前没有向生产部署或发布：

- 所有配置备份接口只允许管理员；列表和存储事务重新校验当前角色。写操作要求已有登录及 CSRF，创建与导入要求幂等键。
- 导入（包括 YAML）和加密导出要求原生 TLS，或来自 `central.trusted_proxies` 显式配置的直连代理且单一 `X-Forwarded-Proto: https`。默认不信任代理，回环地址也不自动信任；公网域名、`Forwarded`、`X-Forwarded-For` 或客户端伪造头不建立信任。
- `trusted_proxies` 最多 32 个代理 IP／CIDR，禁止 `/0`。反代须覆盖而非追加 `X-Forwarded-Proto`，并隔离代理到主控的明文链路；只配置真实代理地址，不使用宽泛网段代替来源控制。示例为 `central.trusted_proxies: [127.0.0.1, "::1"]`，仅适用于反代确实从这些地址连接的环境。
- 标准 age 导入和导出共用持久化计数：账号每五分钟 10 次、全库每五分钟 60 次。失败和忙碌尝试也计数，不因重启清空；过期记录沿用维护工作器清理。密码和包内容不进入计数键、审计或错误。
- PostgreSQL 事务 advisory lock 限制跨 API 实例最多两个 scrypt 操作。单实例连接池只有两个连接时最多一个，保留业务读写连接；失败或返回后释放事务锁，数据库断连同样解除；请求取消不提前释放尚在计算的工作位。工作位事务与请求取消分离，并有两分钟孤儿上限，不把会话锁泄漏回连接池。忙碌返回 429／3 秒重试建议，频率超限返回 429／300 秒；数据库失败拒绝操作。
- 加密导入以受限 multipart 在内存中读取，不调用会落临时文件的 `ParseMultipartForm`。只接受一个 `file` 和一个 `password`，不使用上传文件名或客户端路径。整个请求除 34 MiB 包外仅预留 8 KiB，密码最多 1024 字节。
- 下载使用固定生成文件名、`no-store` 和明确的 Content-Length；浏览器核对类型及长度。审计仍仅表示准备完成，不把 HTTP Write 成功当作客户已保存。

## 存档 API 与网页

接口文档见 `api/control/v3/openapi.yaml`：

| 方法与地址 | 行为 |
|---|---|
| `GET /api/v3/configuration-backups` | 安全元数据，游标分页，最多 200 条；恢复不可用、持久化删除可用 |
| `POST /api/v3/configuration-backups` | 手动存档，JSON `{}`，幂等键必填 |
| `POST /api/v3/configuration-backups/delete-preview` | 明确选择 1～200 个稳定标识，固定预览十分钟 |
| `POST /api/v3/configuration-backups/delete` | 确认及幂等键创建任务；仅回执，不代表已删除 |
| `GET /api/v3/configuration-backups/delete-jobs` | 本账号任务游标分页 |
| `GET /api/v3/configuration-backups/delete-jobs/:id` | 本账号进度、实际数量及逐项原因 |
| `POST /api/v3/configuration-backups/import` | 原始 v3 YAML，不重新序列化以保留重复键供校验；仅存档 |
| `POST /api/v3/configuration-backups/import-age` | multipart `file`、`password`；解密校验后仅存档 |
| `GET /api/v3/configuration-backups/:id/export` | 默认脱敏 YAML |
| `POST /api/v3/configuration-backups/:id/export-age` | JSON `password`、`confirm`；生成标准 age 配置包 |

手动备份的 bootstrap 优先使用本成员已认证的数据库草稿，无草稿时为启动时已校验快照；成员身份与运行时租约标识分开，不把进程随机 ID 写入备份。设置和节点为同一数据库快照中的已保存配置，**不自动捕获后来编辑的磁盘 YAML，也不表示已应用**。完整保存／应用模型仍须后续接入，不能把这个阶段误称为当前磁盘 YAML 灾备。

网页支持独立配置存档游标、创建、文件选择／YAML 粘贴导入、脱敏和加密下载。未成功确认的写入重试沿用幂等键；配置导入不触发恢复。私有内容和密码只在当前弹窗内使用，关闭、切换页签或离开页面清除；旧文件读取及请求迟到结果不会覆盖新页面。纯 HTTP 页面禁用导入和加密下载；服务端仍独立判断传输安全。非管理员不会请求配置存档或显示管理按钮。没有系统设置删除按钮，恢复仍没有开放操作按钮。

## 持久化删除

仅管理员操作。单条及批量均先选择当前页明确的稳定 `record_key`，不接受表名、路径或筛选全量删除。服务端限制 1～200 个不重复标识，预览绑定账号、设置版本和固定范围，有效十分钟。预览时已保护或不存在的记录，后续不会因保护解除而悄悄加入可删除范围；执行时新增的保护仍可阻止删除。

- 导出、恢复、部署和回退引用，以及其他待处理删除任务会显示保护原因。无引用的配置备份不受历史 24 小时规则限制。
- 确认后只创建任务，同账号同幂等键重试返回原回执。每账号最多一百份有效未用预览和一百个未结束任务；超额返回 429 及可操作中文说明。
- 与历史／自动清理共用 `retention` 持久租约和代次门禁，每轮总预算两秒，配置备份工作器最多占五百毫秒。一份备份一个事务，主记录、密文分块、逐项结果、检查点和审计一起提交；审计失败则全部回滚。永久单条错误保留原记录，继续处理其他选中项；基础设施错误保留检查点并重试，不阻塞独立历史清理。
- 页面显示实际删除、跳过和失败数量；排队不能当成成功。详情每三秒读取，不重叠、后台暂停、返回恢复；关闭页面不取消后台任务，可从本账号任务列表继续查看。不同账号不能读取任务。
- 普通进程重启按已提交检查点继续；一致性灾备恢复取消未完成删除，并保留已经完成的计数与结果，防止意外恢复破坏性操作。权限或设置版本变化同样停止剩余删除。
- 任务终态及逐项信息保留 365 天，维护按最多 500 行分批回收；运行任务及其预览受保护。幂等回执继续保留，旧请求不会因历史回收而重新创建删除任务。审计保留 365 天，普通删除不能修改。
- 不改运行配置或服务器，不撤销已导出的文件，也不承诺 PostgreSQL 文件立即缩小；空闲页可复用，不执行在线 VACUUM。

## 内部恢复规划及持久化预览

这部分是恢复工作流的内部规划层；公开 API 和网页的保存态流程见下文，CLI 恢复命令尚未接入。它不会读取本地私钥或证书，不连接子控，不修改实时设置／节点、创建部署或发送通知。仍不能从备份直接应用。

- 文档规划按稳定节点 ID 解析省略项；默认保留现有凭据。邮件和飞书作为完整通道保留，避免把现有 SMTP 密码拼接到备份中的其他主机或收件人。未知设置／节点规则分支保守地作为私有整体处理；含私有身份的数组不按位置匹配。独立 Vault、部署信任、PKI、证书、吊销资料与 DSN 文件引用默认保留。
- 明确选择使用备份凭据时，私有分支使用备份值；脱敏省略仍只从同 ID 的当前记录补全。无法补全会保留省略清单；遮罩、伪造默认值不当作有效凭据。节点／设置版本不回退到备份版本，新增节点从版本 1 开始。
- 公开摘要只含固定字段、节点 ID、增改删数量、凭据保留／替换／缺失计数和固定阻止原因，不含值、路径、地址、未知字段名或敏感配置摘要。私有计划禁止作为 JSON 响应或普通诊断内容输出。
- 拓扑／分片／HA 改变、节点部署方式改变和移除节点分别要求专用迁移／卸载，不能借恢复隐式完成。即使路径文本完全相同，仍标记 `requires_local_validation: true`。`can_prepare` 只表示文档层面没有上述阻止项，**不表示环境检查通过或可以应用**。
- 相同源／当前规则组合只合并一次，输出 profile 去重；节点元数据和缺失项仍分别归属原 ID。扩展 profile 的累计正文达到 32 MiB 时提前拒绝，避免大量节点展开造成无界内存分配；实际 YAML 导出继续执行原字节上限。

schema 16 的内部预览有效十分钟，绑定管理员及账号修订号、备份 ID 和逻辑文档、恢复选项、当前完整已保存配置及最新部署证据。启动快照的配置值参与绑定，重新捕获的时间不参与当前状态比较；不能用设置版本不变掩盖节点或配置正文变化。当前有排队／运行或仍需恢复的部署时拒绝预览。预览重查时重新构造私有计划，不信任数据库中的展示摘要。

私有内容仅在内存中比较；数据库保存有独立域的 HMAC 证明及安全摘要，不保存明文配置、原始预览令牌或可离线猜测密码的普通摘要。证明允许读取保留的旧密钥；仅重新加密同一备份不会使逻辑内容变化。删除证明所需的旧密钥会使旧预览失效。

预览、十分钟源备份引用及审计同事务提交；审计失败全部回滚。预览期间源备份受删除保护，早先生成的删除预览也须在执行时尊重新增引用。已排队删除的备份不再接受恢复预览。账号最多一百份有效预览，并发通过数据库行门禁限制；到期预览与引用由维护任务每批最多五百条回收。

普通进程重启可重新验证未到期预览；账号／配置／备份／选项／部署变化或过期则拒绝。灾备恢复清除全部旧恢复预览及它们自己的临时引用，同时保留真实部署／回退的持久引用。

**单独重新验证预览不是配置写入互斥。** 内部恢复意图提交已接入下面的事务表锁；保存待应用配置已复用此门禁；后续实际应用时也必须复用此门禁、检查本地路径／凭据并做最终版本校验。当前没有实施实际生效步骤，不把预览或待验证意图称为恢复完成。

## 待验证恢复意图与恢复前自动备份

schema 17 增加内部持久恢复意图，状态为 `pending_validation`，明确表示“待本地验证，运行配置未修改”。公开创建／取消及网页记录现已接入，CLI 恢复操作尚未接入；意图本身不是实时设置或可直接部署配置。

- 提交在 **READ COMMITTED** 事务中对 `v3_settings`、`v3_nodes`、`v3_deployment_jobs` 获取 `SHARE ROW EXCLUSIVE` 表锁，再重新验证预览。PostgreSQL 会阻止所有配置与部署表的 INSERT／UPDATE／DELETE，包括不同保存入口、旧导入、直接 SQL 和未来遗漏的普通 DML；不会只依赖各入口自愿遵守某个 advisory lock。
- 表锁会短暂等待正在提交的配置写入；获得锁后读取最新状态，不沿用等待前的 repeatable-read 旧快照。门禁主动拒绝 repeatable-read／serializable 用法，创建意图总预算三十秒，取消或失败由事务释放锁。普通共享查询和事件入库继续运行；若已有未结束部署，则拒绝恢复意图，避免在表锁中等待远端工作。
- 重新验证账号、选项、原备份、当前配置及部署状态，拒绝补全不足、运行方式／拓扑迁移及节点卸载阻止项。随后捕获当前配置，自动写入加密的 `before_restore` 存档。此存档与恢复意图、源／恢复前备份的持久保护引用、预览消耗、幂等回执和审计**同事务提交**，任何一步失败全部回滚，旧预览可在有效期内重试。
- 全库同时最多一份未完成恢复意图，重复请求复用原回执，不重复备份或新建恢复。预览消耗后不再可创建其他意图；状态查询必须读取实际记录，不能把历史回执当作当前运行状态。
- 待验证意图不保存明文候选配置或 SSH 凭据，只保存安全元数据、选项、HMAC 证明及摘要。继续前在同一事务门禁内重新读取并校验源存档、恢复前存档、两份持久引用、原账号版本和当前配置；从认证正文重新规划，不能执行数据库中的展示摘要。
- 普通重启保留待验证状态。原账号改密、降权、配置变化、凭据证明变化、引用丢失或存档损坏会使继续验证失败；另一位当前管理员可查看并取消失去原负责人的意图，但不能借其旧身份继续应用。
- 取消只解除这份意图自己的保护引用，不删除任何存档、配置或业务历史。取消、回执和审计同事务提交；审计失败保留原待验证状态及保护。终态意图保留 365 天后按最多五百行分批回收，幂等回执继续保留；待验证意图不被普通回收删除。
- 灾备恢复将旧待验证意图改为取消，只移除它们自己的引用；保留源／恢复前存档、其他真实回退引用及幂等回执。旧请求重放不复活恢复操作。

这一阶段完成了安全的持久恢复待办及恢复前配置存档，后续已补入下节的本机资料只读诊断和独立待应用版本保存；**统一生效版本模型、节点配置下发和中心重启编排仍未完成**。`pending_validation` 不能作为“已恢复”“已应用”或“可部署”的证据。

## 本机资料只读诊断

内部 `inspectConfigurationRestoreLocal` 重新校验意图所有者、账号版本、认证存档、引用、当前配置及部署证据，在同一读已提交关系锁门禁中检查候选配置引用的本机资料。操作有三十秒上下文预算，但不是公开接口，也不会改变意图状态、写入待应用配置或创建任务。

| 检查 | 当前范围 |
|---|---|
| 数据库凭据 | 私有普通 DSN 文件存在、受限大小且非空；不解析隐式环境／service 配置，不连接数据库，不验证账号权限 |
| 后台 TLS | 证书／未加密私钥匹配、叶证书有效期、公开域名及服务端用途；不验证公网入口或浏览器信任链 |
| 采集 TLS | 私钥匹配、采集器身份、CA 信任、有效期及已配置 CRL；无吊销配置单独显示未配置 |
| 持久吊销状态 | 已存在的私有目录、固定根、已接受历史 CRL 与候选 CRL 单调一致；拒绝回退及撤销已吊销记录，不推进磁盘状态 |
| 部署信任 | 发布清单与签名、helper／native 包及已配置镜像归档的签名摘要、独立 Vault 当前／旧密钥；不执行或解包工具 |
| 密钥延续 | 候选密钥环必须保留当前配置的全部解密密钥；防止换配置后丢失旧凭据或存档读取能力，不代表逐条检查所有密文 |
| 节点签发 | 启用时校验受管理 CA／私钥、当前 CRL 与采集器信任一致；不签发、不修改 CA 或 CRL 历史 |
| 本地目录 | 导出、已配置的 spool／执行器目录必须已存在、私有且安全，检查访问权限、可用 inode 和超过 64 MiB 余量；不创建目录或写入探针，不代表实际写入、完整容量或跨 HA 机器共享性已验收 |
| HA 本机私钥 | 只读检查配置中全部 SSH 私钥可解析且不需口令；不连接成员或检查 HA 入口 |

所有文件通过固定目录描述符和 `O_NOFOLLOW` 读取，拒绝不安全祖先目录、符号链接、硬链接、特殊文件和超限文件。缺失资料或单项失败保留其他检查结果，报告仅包含固定组件名、状态及原因，不回显路径、DSN、证书身份、密钥 ID 或底层错误。未启用的可选能力明确标记 `not_configured`，不冒充通过。

`local_checks_passed` **仅指本次已配置的本机检查通过**；`requires_apply_checks` 始终为 true。报告不是持久凭据或应用许可；同一路径中的文件被替换后必须重新读取，不能复用旧报告。真正提交还需最终本机复核、数据库权限及密文引用检查、网络／角色可达性和统一保存／生效事务。普通诊断不连接 SSH、时序库、DSN 或通知服务，不创建目录／锁文件，不初始化或推进吊销持久状态。

## 独立加密待应用版本（schema 18）

内部 `saveConfigurationRestorePending` 重新认证恢复意图和全部基准，并重新检查本机资料，不接受之前的成功报告作为输入。通过后将完整候选配置加密分块保存到独立版本表，恢复意图转为 `pending_application`。**这是真实持久保存，不是实际应用。** 当前采集、通知及清理工作器直接读取运行表，因此该操作不改 `v3_settings`、`v3_nodes` 或它们的版本，不创建任务、不改本地文件，也不提前执行新策略。

- 版本使用独立递增 `generation`，接口元数据以十进制字符串表达，避免浏览器丢失大整数精度；它不是运行设置或节点的版本。回滚旧配置时仍须产生新的运行版本，不能退回旧计数。
- 候选正文使用 Vault 和 AES-GCM；AAD 绑定版本、意图、账号、基准版本、文档元数据和证明。分域候选 HMAC 同时绑定恢复选项和独立代次。复核时不仅认证密文，还从认证源存档与当前配置重新构造目标并比较；替换为另一份可解密正文、甚至另一个有效候选证明，也不能改变恢复目标。
- 加密头、最多 1 MiB 的连续分块、意图状态、幂等回执和审计同事务提交。任一步失败全部回滚，仍保留待验证意图及原运行配置；本机资料检查失败可修复后重试。同一意图用其他请求键确认也不生成第二个版本。
- 保存仍有三十秒总预算，复用读已提交关系锁门禁；事务完成后普通编辑可继续。保存期间没有长期冻结全库，后续编辑造成基准变化时，继续恢复必须拒绝，不能覆盖新配置。原始 JSON 大整数及小数文本保持精度。
- 状态查询读取当前记录。历史幂等回执只证明当时保存成功，取消、灾备或历史回收后不能凭旧回执认定仍待应用或重新创建恢复。
- 取消同时取消意图与独立版本、释放本意图的源／恢复前引用，失败一起回滚。源存档、恢复前备份、加密版本历史和回执仍保留；终态正文先分批回收，之后再清理元数据和意图，均保留 365 天，待应用记录不被历史清理删除。
- 普通重启保留待应用状态；一致性灾备恢复取消所有未完成恢复及其待应用版本，只解除它们自己的引用，保留其他真实回退保护。数据库备份包括独立版本及分块，恢复后代次继续递增；schema 17 升级仍要求备份成功，旧归档可先恢复后升级。

这一层只覆盖恢复候选，**尚未将普通编辑统一到保存／下发／生效生命周期，公开保存态恢复现已接通，实际应用尚未完成（下文公开流程为准）**。数据库权限、外部凭据引用、网络和最终提交必须在真正应用前再次复核。

## 编辑前自动备份：服务器登记及保留期限

schema 20 起，存在设置草稿时捕获已保存草稿及其独立代次，并核验草稿／运行基准证明；运行版本字段继续表示实际运行设置版本。下述旧阶段中“运行设置”的捕获描述以此为准。内部普通设置保存及显式应用也接入编辑前存档，公开运行设置已接通，恢复后的完整运行应用仍待接通，见 [设置生命周期](V3-SETTINGS-LIFECYCLE.md)。

公开 `POST /api/v3/servers` 和 `PUT /api/v3/retention/policy` 在第一次成功执行写入前创建 `before_edit` 加密存档；配置备份页显示为“编辑前”。新增节点也先备份原配置，存档不包含尚未创建的节点。保留期限仍沿用当前保存即生效行为，尚未改造成统一待应用模型。

- 使用主控启动时通过校验的原始配置快照，以及事务中当前设置、全部节点及私有参数；不读取后来编辑的磁盘 YAML，也不把运行时租约身份写入存档。
- 先通过迁移门禁，再获得恢复流程共用的关系锁，然后重新检查当前管理员权限。锁等待结束后读取实际已提交状态，先前并发配置写入不能造成设置与节点混合的快照。事件及指标共享读取继续运行，配置写入有请求超时预算。
- 存档头、加密分块、原配置变更、幂等回执和两份安全审计在同一事务提交。密钥不可用、现有配置不能完整存档、数据库／磁盘／审计失败时停止保存；后续写入失败时，刚创建的存档也一起回滚。
- 同账号同幂等键重试返回原保存回执，不新增备份；不同正文仍拒绝。管理员权限在事务内重新检查，降权后不能通过旧回执绕过检查。冲突、未完成节点部署及取消的等待不留下部分备份。
- 保存依赖有效的独立 Vault 密钥和原始启动快照；缺失时返回脱敏的 `before_edit_backup_failed`，保留表单，不允许绕过备份。生产安装向导的密钥初始化仍待完成，不能把开发配置直接接管生产。

低层 `SaveNode`／`SaveRetentionPolicy` 仍供内部设置、测试或迁移组合使用，不自动捕获启动配置；公开 HTTP 入口统一走带备份上下文的事务版本。完整设置和其他内部写入仍须在各自真实提交流程接入；可信本地部署提交的存档及引用保护见下节。这一编辑前备份层不自动恢复／应用，不改变删除逻辑或部署子控。

## 部署前自动备份与任务引用

可信本地 `queue-deployment` 和 `confirm-deployment` 已接入 `before_deploy` 全配置加密存档，包含原始启动快照、运行设置、全部节点和去重规则。正文使用现有 Vault；SSH 凭据正文、外部私钥和 PKI 文件仍须独立备份。存档 ID 进入不可变计划摘要，不通过公开任务 JSON 返回。

存档、分块、精确任务引用、任务及日志、防重回执、审计和预览消费在同一 REPEATABLE READ 事务提交。失败全部回滚，同键重放不重复备份；仅对数据库序列化冲突／死锁做最多五次短暂退避重试，事务内没有远端操作。执行器先取得相容的表写模式，再加节点／任务行锁，避免与编辑／恢复快照门禁形成锁升级倒置，不将普通执行器全局串行化。

引用固定为本任务的 `job:<ID>`：排队和准备期使用 `deployment`；进入可能停服的备份阶段前，与恢复保护原子换成 `rollback`。未进入恢复保护的准备失败释放本任务引用；进入后失败、中断、继续及租约接管保留回退引用。成功或已回退只释放本任务引用，存档历史及其他任务引用不删除。缺失、错误类型或冒用其他任务引用均拒绝领取、继续或进入恢复保护。

执行器还必须实际认证并解密存档，核对目标节点元数据、版本和 PostgreSQL 规范化配置摘要；不能仅凭密文和引用存在就连接子服务器。首次领取／接管后的远端调用前，以及备份／恢复服务前重新检查。密钥丢失、损坏或备份与计划不匹配记 `backup-failed`；切换前失败不建立恢复责任，已有恢复责任继续保护。密钥轮换保留旧密钥可读取原存档，重新加密不改变任务绑定。大整数与小数不经 float64 转换。

复用 schema 18 的存档与引用表，不增加迁移。已有无存档绑定的低层／旧任务保持兼容，不伪造历史备份；这不代表旧部署已经接入完整 v3。HTTP 部署写接口和网页部署操作仍未开放，不会触发真实安装、通知或生产切换。

## 恢复到保存配置（schema 21）

内部提交将已认证的候选真正写入待部署节点、设置草稿及本成员启动参数草稿。它与独立候选保存分开，**保存成功仍不是运行应用成功**；公开 API 和网页已接入保存态提交；运行应用仍需独立协调。

- 提交重新验证账号修订号、恢复代次、源存档、恢复前存档、完整当前保存态、部署证据和本机配套资料。在同一事务持有配置关系门禁，防止并发编辑造成混合快照。
- 已有节点只推进保存版本及不可变配置快照，保留原运行登记、采集代次和已生效版本；新增节点不自动登记或采集。节点按最多 100 条、约 2 MiB 一批写入，全部批次仍在同一事务。
- 通知、告警、检测和清理工作器继续读取原运行设置。恢复的设置写入独立草稿；启动参数写入 `v3_bootstrap_drafts`，不写磁盘 YAML、不重启中心、不创建部署或通知。
- 启动草稿按稳定成员 ID 保存，证明绑定原运行参数摘要和代次。不同 HA 成员不共用一个启动草稿；配置值中包含的地址及文件引用仍按私有资料保护，不附文件正文。
- 节点、设置、启动草稿、安全回执、审计、状态和两份回退保护原子提交；任何一步失败全部回滚。终态使用 `saved`，回执显示 `saved_pending_application`，不冒称 applied。
- 保存证明绑定候选、账号、选项、版本、提交结果、部署证据和精确的两份存档 ID。当前适用性还必须重新认证原存档、恢复前基准及两条无限期回退引用。正文、引用或部署状态改变时停止，不信任展示摘要。
- JSONB 数字规范化和 profile 编号不影响逻辑校验，大整数及小数不转为浮点数。同键重试不重复更新；后来普通编辑不会丢失历史回执，但旧证明不能授权新状态应用。
- schema 20 升级同样要求先校验一致性备份。灾备保留已提交的保存态、代次、证明及回退引用，不自动应用；尚未提交的恢复意图继续按原规则取消。旧 YAML 初始化不能覆盖已有保存态。

回退引用仍需后续明确结束恢复责任的流程解除，不通过清理程序隐式移除。最终应用还需实际数据库、网络、独立密钥及外部配套资料复核，以及节点下发、中心启动参数切换和重启协调；内部本机只读检查不能代替这些步骤。

## 后续接入

公开预览、待验证意图及真实保存态提交已接入；还需接入其余自动备份来源，以及完整下发／生效版本模型。实际提交继续要求最终本机资料复核、独立凭据／数据库及任务冲突检查与最终版本校验，通过后才能走统一应用流程。旧 YAML 备份映射、完整业务灾备与增量回退也未完成。

这些步骤完成前保持现有发布版本，不更新 `latest`，只提供已完成的保存态恢复，不提供尚未完成的运行应用按钮。


## 公开保存态恢复流程

此功能属于本地开发 v3，未发布，**不是生产迁移或运行应用**。`/backups?tab=deployment` 每份备份提供“恢复预览”，下方列出全库恢复记录；重开页面或主控进程重启后可找回原记录，不依赖浏览器临时弹窗。

| 接口 | 作用 |
|---|---|
| `POST /api/v3/configuration-backups/:id/restore-preview` | 十分钟安全差异，`use_backup_credentials` 必须明确传布尔值 |
| `GET /api/v3/configuration-restores` | 管理员查看所有账号的恢复记录，游标分页 |
| `POST /api/v3/configuration-restores` | 使用 `preview` 和 `confirm: true` 创建持久意图及恢复前备份 |
| `GET /api/v3/configuration-restores/:id` | 同一快照的状态、安全差异、独立候选及继续／取消能力 |
| `POST /api/v3/configuration-restores/:id/check` | 只读本机资料诊断，请求 `{}` |
| `POST /api/v3/configuration-restores/:id/prepare` | 重查资料，准备独立加密候选，请求 `{}` |
| `POST /api/v3/configuration-restores/:id/commit` | `generation` 字符串和 `confirm: true`；写入保存配置，待应用 |
| `POST /api/v3/configuration-restores/:id/cancel` | 明确 `confirm: true`，取消未完成意图 |

所有接口要求当前管理员；写入要求 CSRF、可信 HTTPS，创建／检查／准备／提交／取消要求有效幂等键。请求最大 4096 字节，严格拒绝重复字段、大小写别名、未知参数、null、数值型代次和非规范代次字符串。恢复预览只接受固定选项，不能提交任意路径、配置正文或执行命令。每次操作上限 30 秒，不把内部事务缩短为存档下载的 20 秒预算。

- 默认保留当前完整邮箱／飞书通道及凭据，避免把当前密码发送到备份中的另一个地址；选择使用备份凭据后必须重新预览。差异只显示固定分区、字段标签和计数，无路径、私有配置值或证明。
- 创建、准备和提交均重新核验。准备成功只表示候选已准备；提交成功才表示已恢复到保存配置，仍未运行应用。代次始终用字符串传输，避免浏览器整数精度丢失。
- 原操作账号及账号修订号一致时才可继续；其他当前管理员可查看并取消遗留意图，不能以原账号权限继续。`can_continue` 不是新授权凭据，执行仍须重查配置和本机资料。
- 只读本机检查不连接数据库、SSH、HTTP 或通知渠道，不创建目录、不写配置、不推进吊销下限。失败报告只返回固定代码；本机资料失效时仍可取消意图，取消不要求解密密钥或启动快照可用。
- 两万节点差异仍保留完整确认范围，网页只渲染前 100 条节点变化并明确提示总数，避免创建两万行 DOM。
- 页面错误保留，结果不确定时沿用原幂等键明确重试，不自动重放。切换页签、关闭弹窗和离开页面忽略迟到请求；配置冲突要求重新预览。详情重读使用同一数据库快照，不混合提交前后的意图和候选。
- 列表保留 `restore_available: false` 表示运行应用未开放，新增 `saved_restore_available: true` 表示保存态恢复能力；能力列表新增 `configuration-saved-restore`，不把部分能力表示为完整恢复。

最终运行切换仍需专用应用协调、数据库及网络检查、节点下发、启动参数落地和中心重启。这一流程不会创建部署任务、发送测试通知或改变节点采集身份。

## 保存后应用前环境诊断

本地管理员可通过 `control-v3 --action check-configuration-apply --config <隔离启动配置> --username <原恢复账号> --source <私有请求文件>` 检查一份已提交的保存态恢复。请求文件为 `0600` 普通文件，只接受 `{"stage":"<64 位恢复记录 ID>"}`，不能提供探测目标、路径或命令。此入口未加入网页，不改变原有 `/check` 只读本机检查的边界。

- 先认证原账号、保存代次、候选、两份回退存档及完整当前配置，再检查本机配套资料；缺失时不发起网络请求。
- 使用候选配置引用的 DSN 独立连接 PostgreSQL。通过临时事务咨询锁核对当前业务库身份，同时核对默认 schema、业务表 OID、当前 schema 版本、非只读状态、逐项表／序列权限及 RLS；不迁移、不写业务表、不绑定新集群。更换数据库属于专用数据迁移，不能靠恢复配置跳过。
- 在目标时序接口查询当前时刻的 `vector(1)`；向导入接口发送空请求，不写入指标样本。验证 TLS、响应类型、大小及时间，不跟随重定向。支持单机和集群路径前缀。
- 网络检查在配置门禁事务外执行，不阻塞并发配置修改。完成后重新认证保存态、账号、部署证据、本机资料及 DSN 正文；检查期间发生变化则拒绝沿用结果。整体上限 30 秒，网络阶段 10 秒、单个 HTTP 请求 5 秒。
- 报告只包含固定组件、状态及原因代码；不回显地址、DSN、路径、密钥或原始错误。代次使用十进制字符串。检查失败返回非零退出码；依赖检查失败仍可输出安全诊断。

`preflight_passed: true` 仅表示本次诊断通过，**不是可复用的应用凭据**。`requires_runtime_receipts` 始终为 `true`：空导入不能证明磁盘持久化、完整采集链路或节点运行状态。正式应用协调器仍必须重新检查、获取实际运行回执，并协调节点下发、启动配置、重启和无损回退；本入口不会应用配置、创建部署任务、发送通知或发布版本。

## 持久化应用任务基础（schema 22）

内部应用日志已与保存态恢复分开：从已提交的恢复记录创建任务，绑定原账号修订号、稳定中心成员、保存代次及原提交签名；进度检查点另行签名，包含控制账号、阶段、方向、回退责任和执行代次。客户端不能提交检查点，也没有公开排队、执行或恢复应用接口。本阶段尚未安装到 `Serve`，不会因数据库中存在任务自动开始应用。

前向阶段为环境检查、节点下发、中心启动配置、运行设置、实际运行验收和完成；回退按设置、中心启动配置、节点及回退验收推进。回退不得覆盖事件数据库。任务、固定代码日志、幂等回执和用户操作审计持久化；当前页展示模型不包含私有配置、地址、配置摘要、签名或原始远端错误。

- 同一集群只允许一个排队、运行或仍承担回退责任的应用。受管理的设置／节点编辑及恢复提交会报告配置应用冲突；任务操作使用同一关系锁顺序，网络阶段不持有该锁。
- 执行租约 45 秒，每 10 秒续租；接管递增代次，旧拥有者不能续租、失败覆盖或推进阶段。每个完成阶段重新排队，下一工作器从持久检查点领取，不能依赖进程内循环状态。
- 正在执行且租约有效时不能直接继续、取消或更换方向。无切换副作用的失败可取消；已经开始切换的任务保留回退责任，不能通过取消丢弃。原账号及修订号有效才可继续前向应用；当前其他管理员可以明确接管回退，不继承原账号的应用权限。
- 开始任何切换前，适配器必须声明实际支持全部剩余前向阶段及全部回退阶段。当前真实适配器只支持环境检查，因此之后明确失败且不进入回退状态；没有把空方法、重启请求已发送或合成回执当作真实完成。
- schema 21→22 仍须先做并验证一致性备份。灾备保留原签名、阶段和回退责任，额外设置执行冻结；旧租约不能复活。管理员显式继续或请求回退后才推进新代次，并必须先核对实际运行证据。

测试中的完整前向／回退适配器仅验证日志状态机、租约和控制权限，不执行实际切换，也不构成运行验收。尚需实现真实节点部署协调、中心启动配置及重启交接、设置原子提交、运行回执、回退资料认证及保护引用释放，再开放统一应用入口。

## 运行设置应用回执（schema 23）

继上述协调基础之后，内部运行设置适配器已支持真实策略事务应用和回退，见 [运行设置生命周期](V3-SETTINGS-LIFECYCLE.md#配置恢复应用中的运行设置schema-23)。加密前后回执与实际设置、应用标记和审计原子提交；中断后检查实际状态，不能将“没有回执”或“已发出请求”当作完成。回退恢复原运行策略并保留目标保存草稿，不覆盖事件数据库。

应用领取、阶段提交及设置适配器会核对原候选、提交证明、存档及两份回退引用。回退可由当前新管理员明确控制，原账号失效不妨碍验证历史签名，但不能绕过损坏／缺失的资料。迁移前仍须一致性备份；灾备恢复保留加密回执并冻结执行，显式重新授权后才可接管。

中心启动参数与重启交接、节点应用协调、完整运行验收及保护引用释放尚未完成。没有开放统一应用接口或自动运行任务；不能用本阶段设置回执代表完整配置已生效，不能据此发布完整 v3。


## 中心启动交接与灾备（schema 24）

已增加内部启动交接适配器及实际进程初始化证明，详见 [设置生命周期](V3-SETTINGS-LIFECYCLE.md#中心启动交接schema-24)。备份包含加密前向／回退交接及确认；恢复时清除运行进程记录，未结束应用继续保持恢复冻结。未确认交接不能自动激活，已确认配置也不能凭归档心跳冒充新的采集或部署验收。

外部 Vault、DSN、证书、原始启动文件和工具仍不包含在数据库或配置包内，须独立保留。实际安装器、完整节点应用及最终验证尚未接通；内部启动交接不等于配置恢复已完整交付，不开放生产恢复。
