# v3 节点保存、运行登记与生效

此模块为尚未发布的本地 v3 实现，不代表完整安装或生产切换已经交付。

## 三个版本

| 字段 | 含义 |
|---|---|
| `version` | PostgreSQL 中已保存、待部署的节点配置版本 |
| `configuration.registered_version` | 当前采集器使用的运行登记版本；零表示没有登记 |
| `configuration.delivered_version` | 部署激活确认的下发版本；零表示缺少可靠证据 |
| `applied_version` | 完成采集、目录覆盖、扫描能力及事件链路验收的版本 |

`configuration.runtime_enabled` 为 `null` 时尚未登记，为布尔值时表示当前运行登记的监控开关。`runtime_endpoint` 和 `runtime_mode` 是登记值，表单地址和部署方式则是已保存值。公开响应不包含私有配置、凭据或内部快照标识。

仅保存会产生不可变节点快照，保留编辑前存档与审计，不向运行登记发布。已有节点继续使用原地址和规则采集，保存停用不会取消运行中的告警或通知；新节点没有登记，不会因保存成功而开始连接。

## 部署与回退

任务私有计划绑定原登记和目标快照的摘要、版本及运行代次，不复制配置内容。准备、工具校验和一致性备份阶段保持原登记。远端 `activate` 确认后，发布目标快照与推进任务检查点使用同一事务。发布失败不会留下半个检查点。

发布后清除当前状态缓存、短期健康样本和旧就绪证据，新的采集请求重新建立观测；历史指标、事件及指标游标保留。不能用旧地址的最近指标为新目标证明健康。verify 和 finalize 持续复查真实采集证据，最后才更新生效版本。

回退恢复原登记快照，递增运行代次，保留已保存的待应用修改。首次安装没有旧登记时，回退撤销登记；重新安装仍使用更高代次。版本即使相同，旧代次的请求也不能写指标、事件或就绪证据。

每次远端操作前及提交检查点前复核原、目标快照的摘要和登记状态。变更或损坏时停止，不先操作远端再报告冲突。旧任务缺少原登记证明时不伪造历史快照，完整旧部署迁移仍需单独验收。

## 并发与查询

采集事务先锁定分片租约，再按节点、运行登记顺序加锁；发布遵循节点在前的顺序。已持有合法采集锁的事务完成后，发布才能切换；之后的旧请求被运行代次隔离。调度器按运行登记分页读取，代次改变会重启该节点采集任务。

告警、组件适用节点及资源排名读取当前登记。总服务器数包含仅保存节点，未登记且启用的节点计为未知；它们不进入资源排名，也不被计成正常采集。总览分区仍由摘要工作器生成，不在页面请求中逐台探测。

## schema 19 与灾备边界

schema 19 增加配置快照、运行登记、持久递增计数及只读活动节点视图。已有库必须先完成并核验一致性备份；失败不升级。schema 18 的最后登记会原样承接，历史 `applied_version` 只作为已有证据，不将未知下发补成成功。

PostgreSQL 备份恢复保留快照标识、登记和递增计数；短期就绪证据不作为灾备后的健康依据。数据库快照恢复不能解决备份之后远端已增加的操作代次，灾备后的主控／子控代次协调、证书与外部资料恢复仍是完整切换的待验收项。

验证使用隔离 PostgreSQL 和合成节点，覆盖仅保存、激活、首次安装回退、再次安装、损坏快照、事务失败、采集与发布竞争、旧请求隔离、schema 18 升级及空库灾备恢复。测试未连接生产或业务通知渠道。
