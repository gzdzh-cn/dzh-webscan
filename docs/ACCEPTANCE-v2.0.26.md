# v2.0.26 首次安装内存检查修复

## 原因与调整

首次安装原有检查在组件预算、新建 Grafana、新建 Loki 和网站后台预算之外，固定增加 128 MiB 预留。组件预算 320 MiB、网站后台额外预算 128 MiB 时，要求可用内存达到 1024 MiB，因此可用 1008 MiB 的主机被停止安装。失败发生在环境检查，尚未初始化部署任务或启动监控容器。

新增 `central.install_memory_reserve_mib`，默认仍为 128，允许 64～4096 MiB。实际主服务器配置设为 64，其安装门槛为 960 MiB。组件预算、容器限额和 Go 内存目标不变。可用内存仍按物理内存 `MemAvailable` 检查，不计 Swap，低于门槛时停止。

日志列出完整预算明细，失败时提示差额、对应配置字段和处理方法。预检阶段失败后重新执行脚本即可，无需 `--resume`；部署阶段中断继续沿用已有恢复机制。

## 验证

- 前端类型检查、6 项测试、Vite 构建及 Go 全量测试通过；配置、部署包竞态检查和 `go vet ./...` 通过。
- 内存回归覆盖旧配置默认 128、允许范围及非法值、1024 MiB 原始门槛、960 MiB 新门槛、按 KiB 的边界，以及复用组件和关闭网站后台的预算。
- Linux amd64 隔离容器执行内存测试，确认调整预留不改变接收容器内存限额。
- 实际 SH 包在禁网 Linux 环境完成四项离线配置验收：缺省值、64、128、非法 63；非法值显示字段和范围。实际主服务器 YAML 离线校验通过，保留 HTTP 和原组件预算，仅新增预留 64。

## 发布与同步

central、agent 发布 v2.0.26 与 latest。版本标签和 latest 对应摘要一致；匿名下载全部镜像层，核对压缩及解压摘要并重新加载，镜像身份与本地构建一致。摘要记录于本地 `dist/v2.0.26/release.json`。

同步主服务器三文件部署包前保存受保护备份，并检查配置、部署状态和引导/部署锁。同步后执行离线预览，验证版本、预留及网站后台设置；部署状态和全部容器 ID 保持不变。本次不安装生产监控容器，不停止业务服务、不修改防火墙或 Nginx。管理员运行新版脚本选择安装，安装时会重新检查可用内存。

私有日志、配置及快照保存在 `.cache/memory-v2.0.26/`，不可公开上传。此版未改动检测、告警、事件、扫描或传输逻辑，未执行生产功能验收。
