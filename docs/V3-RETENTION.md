# v3 PostgreSQL 历史保留、导出与清理

本模块处于本地重构验证阶段，**完整 v3 尚未完成，不能用于生产切换**。现有 v2 页面、SQLite 清理和删除行为保持原样。

## 独立保留期限

期限存在 PostgreSQL `v3_settings`，通过配置版本和幂等键编辑，不写回启动 YAML。不返回其他配置或通知凭据。

| 类别 | 兼容配置键 | 缺省 |
|---|---|---|
| 普通文件及运行事件 | `sqlite_events_days` | 30 天 |
| 安全扫描命中 | `security_events_days` | 原普通事件期限 |
| 网站故障 | `website_incidents_days` | 30 天 |
| 服务器告警 | `server_alerts_days` | 原 `monitoring.history_days`，缺省 15 天 |
| 飞书与邮件完成历史 | `delivery_records_days` | 30 天 |

均限定为 1～3650 天整数，不接受字符串、布尔、空值或小数。保留期限沿用旧键名；旧 YAML 的运行参数可通过[参数迁移](V3-SETTINGS-MIGRATION.md)冻结导入，完整部署配置和最终切换尚未接通，不能把兼容默认值解释为已经迁入生产期限。显式错误配置会阻止清理。

保存只修改这五个字段，保留其他设置。仅管理员可以修改，要求有效会话、CSRF、配置版本及幂等键；并发版本冲突返回 409。缩短期限不可逆，调大不能恢复已删历史。系统设置不增加删除操作。

## 自动清理与恢复

API／all 角色启动时检查一次，随后每个小时只建立一个持久任务。多个实例通过递增代次租约协调。同一小时已完成或已取消的任务不重复扫描；未完成任务每五秒尝试继续。

每轮预算两秒，每批最多扫描 500 条主记录。关联投递尝试、重复展示副本也按最多 500 条分批处理，处理完依赖后才删除父记录。游标、删除、依赖处理、实际数量和审计在同一短事务提交；超时或失败不推进该批游标，之前已提交的部分保留。任务重启后继续原游标，过期工作器不能更新任务。设置版本变化后停止旧范围，下一小时按新期限重新检查。

事件按接收时间、通知按完成时间、网站按故障结束时间、服务器告警按事件时间计算。期限最短一天，因此自动清理不会选中最近 24 小时的历史。探针和普通运行事件采用普通事件期限，页面隐藏不会触发删除。

以下记录继续保留，并在删除前重新核对：

- 已标记未完成的扫描事件、未完成或待切换通知、有效投递租约。
- 当前 pending／firing 异常期间的记录及未结束网站故障。
- 待入队网站出箱、服务器告警出箱和未完成批次。
- 尚有未完成收件人、近期完成收件人或顺序依赖的通知。

旧网站通知缺少精确网站关联时采用保守保护：有未完成网站通知即保留相关阶段的网站历史。宁可下一轮再清理，不能猜测依赖已结束。

通知删除分批移除其尝试记录后删除父记录，不删除原始事件、不撤回已发送消息。已完成网站出箱和服务器告警批次按各自历史期限清理；仍被引用的批次保留。

## 事件重传与重复展示

原生事件清理后保留规范摘要回执，并在同一事务移除对应迁移展示副本。重复重传仍按原事件 ID 确认，不重新展示或通知。

旧日志历史可能只有展示记录，不能凭日志生成 Agent 确认。清理这类记录时保存精简身份及摘要，**不创建原生确认**。以后实际 Agent 重传到达，先校验实际内容并事务保存规范回执，再遵守已删除历史的状态，不重新展示或入队。清理和接收按节点串行协调，避免两者并发造成历史重现。

回执和精简删除身份是去重资料，不能随普通历史一起删除。迁移暂存、原始一致性快照及备份也不由本工作器删除，最终切换和归档策略仍待完成。

## 当前接口

| 接口 | 内容 |
|---|---|
| `GET /api/v3/retention/policy` | 期限、配置版本、更新时间 |
| `PUT /api/v3/retention/policy` | 管理员保存五类期限 |
| `GET /api/v3/retention/status` | 期限、最近任务、应用表及索引大小、工作器心跳 |
| `GET /api/v3/retention/jobs` | 按时间及 ID 游标分页的自动清理任务 |

没有心跳证据时显示未知。备用实例的心跳不能掩盖实际执行实例失效。状态读取失败返回 503，不返回空任务或伪造成功，不误报登录失效。

任务统计分别记录扫描次数、删除主记录数、保护跳过次数和联动删除数。大依赖图可能分多批访问同一父记录，因此扫描及跳过次数不等于去重后的记录总量；删除计数只记录实际已提交部分。数据库大小包括可复用空间，记录删除不代表立即归还磁盘空间，不执行在线 VACUUM。

手动预览、导出与清理接口和列表删除保护已补入，见下文。任务删除、旧审计和完整扫描任务依赖迁移、指标及备份策略仍需接入完整 v3。现有网页尚未切换至本 API。

## 数据库与验证

schema 9 增加清理任务、删除身份及排序索引。已有 schema 1～8 必须先完成校验过的一致性备份，失败不升级。备份／空库恢复保留清理游标、计数、去重身份及迁移保护；清理工作器心跳失效，等待新实例提供证据，恢复不会解除业务迁移冻结。

本地测试使用隔离 PostgreSQL，不连接真实飞书或邮箱。覆盖期限兼容、并发保存、配置冲突、500 条边界、故障事务回滚、重启续作、租约接管、受保护记录、收件人及尝试联动、清理与实际重传竞争、API 权限、调度及心跳过期。完整日志与后续缺口见 [验证记录](V3-VALIDATION.md)。

## 手动预览、导出及选择清理（本地实现）

新增接口均要求登录；写入要求 CSRF，提交任务另需幂等键。viewer 只能查看，operator 和 admin 可提交历史操作。系统设置仍不增加单条或批量删除按钮。

| 接口 | 内容 |
|---|---|
| `POST /api/v3/retention/preview` | 固定范围，返回可操作及受保护数量、10 分钟预览凭据 |
| `POST /api/v3/retention/export` | 只导出，不删除 |
| `POST /api/v3/retention/cleanup` | 先导出再清理，或明确确认不导出后清理 |
| `GET /api/v3/retention/jobs?kind=manual` | 仅当前账号的手动任务，游标分页 |
| `GET /api/v3/retention/jobs/:id` | 当前账号任务、固定范围及实际完成部分；兼容自动任务详情 |
| `GET /api/v3/retention/jobs/:id/download` | 仅当前账号下载已完成且未过期的 JSONL |
| `GET /api/v3/notifications` | 飞书／邮件历史元数据、稳定字符串 ID 和删除保护原因 |

范围类别为 `events`、`security-events`、`website-incidents`、`server-alerts`、`feishu`、`email`，可限定服务器和截止时间。传入 `records` 时只接受明确的 1～200 个 `record_key`，不会扩大为全部筛选结果。未传记录列表时按类别范围固定预览。范围默认 30 天前，明确选中记录默认 24 小时前；均禁止清理最近 24 小时。默认不包含探针，需通过 `include_probes: true` 明确加入。

预览使用同一数据库快照，绑定账号、配置版本和截止时间；提交后不可扩展，晚到的匹配记录不加入。每账号最多 100 个未使用的有效预览、5 个未结束任务。任务创建不表示清理完成。预览凭据只在创建响应返回，其原文不进入数据库、审计、请求收据或 URL。新配置使未提交预览失效，已运行任务保留已完成部分并停止后续处理。

清理与导出共用自动清理的 `retention` 持久化租约及业务保护规则，逐批重新核对异常、通知顺序、扫描状态和有效租约。排队、运行的手动任务固定记录会暂时保护免于自动删除。原生事件删除同步分批移除重复迁移展示记录；通知删除分批处理投递尝试，不删除原始事件。列表的 `can_delete` 和 `delete_reason` 使用同一保护判断，执行仍需重新预览和校验。

每批最多 500 条主记录。导出批次及先导出再清理的批次最多 20 条，单个文件分片最多 8 MiB；依赖图每批最多 500 条。工作器单轮总预算仍为 2 秒，手动部分最多 750 毫秒，给自动保留策略预留执行时间；预算到期正常让出，重启继续已提交进度。非超时失败保留实际数量并标明失败，不能显示全部成功。

### 导出文件与恢复保护

`central.exports_directory` 默认 `/var/lib/webscan-v3/exports`，要求绝对路径。目录 0700、文件 0600，属于运行账号，拒绝符号链接和不安全权限。部署生产时应由 root 管理；HA 中所有处理、下载实例必须使用同一受控共享目录，不能把某台机器的局部文件误认为其他实例可用。客户端不能指定服务器路径。

JSONL 只包含列表可查看的历史字段，通知载荷和提供商响应不导出。文件名由服务端随机生成，先持久化文件意图，再原子写入并同步数据，最后提交摘要和进度。文件写入或数据库提交中断会留下可追踪的意图，重试使用新文件名，过期工作器不能覆盖后继文件。

选择“先导出再清理”时，导出完成前不删除；清理前核对相应分片的权限、大小和 SHA256，缺失、损坏或过期即停止。未导出需明确 `confirm_without_export: true`。下载固定 `Content-Length` 并逐片验证；后续分片丢失时客户端拒绝不完整下载，不将其当作有效备份。下载不静默重试，单次上限两分钟，并记录开始及实际结果。

文件完成后保留 24 小时，工作器通过文件意图分批清除，不遍历整个文件系统。操作元数据和审计保留 365 天；任务结束 24 小时后分批回收其固定选择明细。普通清理不删除审计。删除记录不等于立即释放文件系统空间，不执行在线 VACUUM。

schema 11 增加手动任务、预览、明细及文件意图。已有 schema 1～10 必须先创建并核对一致性备份，失败停止升级。普通重启继续任务；数据库灾备恢复则取消未完成的手动任务、使所有预览失效并撤销外部导出证据，要求重新预览，不能凭旧备份自动恢复破坏性授权。文件意图仍供过期清理使用；数据库备份不包含 JSONL 文件本身。

TypeScript 传输模型和 OpenAPI 已同步；现有 Vue 页面尚未切换到这些 v3 接口。完整部署配置、旧审计与任务依赖迁移、指标及备份策略和最终切换仍需继续。

## 网页入口

schema 20 起，历史期限接口仍只更新五项期限并生效；有其他待应用设置时，将相同天数合并到草稿，不顺带应用通知或告警修改。未知字段及大整数保持精度，缺少草稿证明密钥时停止保存。详见 [设置生命周期](V3-SETTINGS-LIFECYCLE.md)。

独立 v3 `/settings` 已接入五项保留期限、范围预览、仅导出、导出先行清理、持久任务及只读审计；系统设置没有新增单条／批量删除按钮。工作器状态与应用 schema 大小使用真实接口证据，尚不填造类别总数或最早时间。详见 [网页接入与边界](V3-CONSOLE.md)。
